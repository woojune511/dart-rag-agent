# Sol 잔여 4문항: 필수 원문·단위 보충 진단

> 실행 당시의 판정과 조건을 보존한 기록입니다. 후속 재채점과 전체 비교는 [최신 종합 보고서](rag_quality_progress_2026-10-21.md)를 참고하세요. `benchmarks/results/` 경로는 공개 파일이 아닌 로컬 증거 위치입니다.

2026-10-20, [Sol top-12 전체 평가](full77_sol_top12_result_2026-10-20.md)에서 완전 정답이 아니었던 4문항에 필요한 원문 표 5개를 보충하고 각각 한 번씩 생성했다. **완전 정답은 0/4 → 4/4**, **인용 근거 충실성 PASS는 3/4 → 4/4**였다. 추가한 표 5개를 새 답변이 모두 실제로 인용했다.

이는 사람이 필요한 원문을 골라 준 **oracle evidence 진단**이다. 검색 알고리즘이나 제품 성능을 개선한 결과가 아니며, 기존 전체 평가의 **42/46은 그대로 유지**한다. 모델·프롬프트·질문을 바꾸지 않고 근거를 보충했을 때 이 네 실패를 해결할 수 있었음을 보여준다.

네 문항 모두 기존 문서의 원문·문맥·순서를 그대로 보존했다. 모형에는 정답, 수정 지시, 계산식 예시, rubric을 추가하지 않았다. 평가 자료에 저장한 기준값은 생성 요청에 포함되지 않는다.

SK하이닉스는 기존 top-12에서도 byte 제한 때문에 실제 문서 9개가 전달됐으며, 이번에는 그 9개와 자산표 1개가 들어갔다. 이전에 생략되던 금융자산 표 3개는 동일하게 생략됐다. 입력 상한을 늘리거나 기존 근거를 제거하지 않았다.

## 문항별 결과

| 문항 | 보충한 원문 | 새 답변의 핵심 결과 | 판정 |
|---|---|---|---|

| SK하이닉스 차입금 / 유·무형자산 | `20240319000684:123:0` 연결 재무상태표 | 유형·무형자산 합계 **56,539,420백만원**, 유동성 대체분 포함 차입금 **29,468,632백만원**, 비중 **52.12%** | 모두 PASS |

POSCO는 원래 제공된 이자비용 `692:331`에 추가 영업이익을 연결했다. 원문은 연결실체와 2023년 문맥, 제56기 금액, 백만원 단위를 함께 담고 있다.

SK하이닉스는 자산표와 기존 차입금 표 `277:148`을 함께 인용했다. 단기차입금·유동성장기차입금·장기차입금·유동성사채·사채의 다섯 항목을 명시적으로 합산했다. 사용권자산은 유형·무형자산 합계에서 제외했다고 설명했으며 실제 계산도 일치한다.

**하이닉스의 52.12%는 기존 허용 기준에 따른 답이다.** 참고답안의 42.02%는 유동성 대체분을 제외한 세 개 명명 계정 23,757,090백만원을 사용한다. 기존 평가 계약은 유동성 대체분 포함 여부를 명시하면 29,468,632백만원 기준도 허용한다. 이번 결과를 본 뒤 허용 범위를 넓히지 않았다.

Motional은 연결 주석의 공동기업 범위로 답했고, 별도·타법인출자 표의 25.81%·1,294,367백만원을 섞지 않았다. 네 손익 항목을 모두 답하고, 모셔널 자체 요약 재무정보와 현대차 지분율을 적용한 지분법손익을 구분했다.

SK이노베이션은 이전에도 비율 계산 자체는 맞았다. 이번에는 단위가 있는 `882:499`를 실제로 인용했으므로 백만원·억원 표기가 근거로 뒷받침된다. 배터리 **부문**의 581,816과 SK온 **법인**의 581,824를 혼합하지 않았다.

## 무엇이 확인됐나

| 이전 실패 | 이번 관측 |
|---|---|
| POSCO: 영업이익 분자 부재 | 분자를 주자 기존 이자비용과 결합해 계산 |
| 하이닉스: 유형·무형자산 분모 부재 | 분모를 주자 차입금 범위를 명시하고 계산 |
| Motional: 대상 행과 손익 표 부재 | 두 원문 표를 주자 같은 연결 범위의 필수 항목을 모두 추출 |
| SK이노베이션: 금액의 통화 단위 연결 부족 | 단위가 함께 있는 표를 주자 그 표를 인용하여 금액·환산·비율을 설명 |

이 네 사례에서는 필요한 원문·범위·단위가 전달되면 Sol이 현재 프롬프트로 답할 수 있었다. 문서 이해나 산술 능력이 항상 충분하다는 일반 결론은 아니다. 이번에는 원문 보충과 생성 표본이 함께 달라졌고, 반복이나 새 대조군을 만들지 않았다.

추가한 표의 기존 후보 위치를 확인하면 검색 개선의 경계도 구분된다.

| 원문 | 기존 검색 후보에서의 위치 |
|---|---|
| POSCO `1186:24` | BM25 18위, RRF 28위 |
| 하이닉스 `123:0` | 기존 Dense/BM25 후보에 없음 |
| Motional 지분·장부금액 `275:133` | Dense 15위, RRF 27위 |
| Motional 요약 손익 `285:143` | 기존 Dense/BM25 후보에 없음 |
| SK이노베이션 `882:499` | BM25 9위, RRF 15위 |

따라서 **하이닉스와 모셔널 손익까지 해결하려면 후보 수집 단계도 다뤄야 한다.** 현재 후보를 그대로 둔 채 최종 top-k만 늘려서는 이번 보충 근거를 모두 전달할 수 없다. POSCO·Motional 지분·SK이노베이션 단위 표는 후보 선택 범위 밖에 있었다.

## 비용과 검증

답변 4회가 모두 완료됐으며 HTTP 오류·재시도는 없었다. 생성은 **47.89초**, usage 기반 추정 비용은 **$0.168999(약 $0.17)**다. 준비·사후 검토 시간은 생성 시간에 포함하지 않는다.

| 실제 사용량 | tokens |
|---|---:|
| 전체 입력 | 62,966 |
| 일반 입력 / cache read / cache write | 12 / 0 / 62,954 |
| 전체 출력 | 1,159 |
| reasoning / reasoning 외 출력 | 144 / 1,015 |

비용 구성은 일반 입력 $0.000024, cache write $0.157385, reasoning 출력 $0.00144, 그 외 출력 $0.01015다. 같은 날 앞선 실행에서 확인한 [공식 Sol 모델 문서](https://developers.openai.com/api/docs/models/gpt-6.1-sol)의 단가 snapshot을 그대로 사용했다. 청구서 확정액은 아니다. 검색·임베딩·ingest·judge API 호출은 0회다.

- 모의 실행 4회와 호출·비용·모델·요청 변경 등 부정 검증 13개를 통과했다.
- 실제 native request 4개가 동결 요청과 일치했고, 고유 응답 ID·제품 투영·출처 ID 검사를 통과했다.
- raw 응답을 봉인한 후 같은 assistant가 답변의 실제 인용 원문을 검토했다.
- 16개 원문 발췌와 19개 답변 발췌를 원본 해시·구절 위치에 연결했다.
- 단위 정보는 저장 원문의 단위 행 또는 같은 표에 연결된 앞선 원문 단위 표에서 확인했다. 임의로 금액의 단위를 채우지 않았다.
- 기존 결과·점수·rubric·소스·설정·저장소 등 6,221개 보호 파일과 HEAD·stage를 보존했다.

문항당 1회, 실패 사례를 보고 선택한 원문, 개발 노출 평가셋, 동일 검토자라는 한계가 있다. 금액 표와 단위 문맥을 함께 추가했으므로 단위 정보만의 효과를 독립적으로 측정한 것도 아니다. **실험의 4/4를 기존 전체 평가의 46/46으로 바꾸지 않는다.** 제품 기본값과 검색 구현도 변경하지 않았다.
