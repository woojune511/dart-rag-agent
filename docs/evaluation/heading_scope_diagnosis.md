# 소제목 범위 잔존: provider-free 파서 진단

2026-09-29. **COMPLETE_OFFLINE_DIAGNOSIS**. 현재 `ec714bd0`의 변경하지 않은
파서에서 KB금융 G02의 제목 범위 충돌을 재현했고, 삼성전자 회사 개요에서도
같은 종류의 잔존을 확인했다. **파서의 범위 문제는 확인했지만, 이를 수정하면
LLM 답변이 개선되는지는 실행하지 않았다.**

## 범위와 재현

- 분류: parser structure / evidence schema의 버그 진단. 제품 수정 아님.
- 기존 full77 준비 산출물에 등록된 11개 보고서의 원본과 table corpus를 읽었다.
  원본 XML을 읽은 후 `1. 회사의 개요` 절만 현재 `FinancialParser`로 수집·청킹했다.
  전체 ingest, store 생성·갱신, 검색, 임베딩, 답변 호출은 없다.
- 이 11개 절은 현재 모두 plain 모드다. 기존 실험의 regex adapter를 설치하지
  않았으며 구조화 모드로 강제 전환하지 않았다. 정규 런타임에서 사용하는
  파서와 기본 청크 설정(2500/320)을 사용했다.
- 현재 121개 청크 모두 기존 corpus의 청크 하나와 **본문·local_heading이 일치**했다.
  기존 검색용 prefix를 제외한 본문 suffix와 제목을 대조한 결과이며,
  전체 ingest metadata·embedding·검색 순위의 동일성을 주장하지 않는다.

## 원문 검토 결과

**KB금융:** `사. 주요 사업의 내용` 아래에 그룹·자회사 설명이 있고 마지막
자회사 표제는 `[KB라이프생명]`이다. 뒤이어 동급 항목인 `아. 신용평가에 관한 사항`과
`자. 회사의 주권상장...`이 시작하지만 `local_heading`은 이전 자회사로 남는다.
아래 artifact에는 각 문단의 정확한 XML·XPath를 보존했다.

G02의 `20240326000894:12:12`는 현재 청크 12와 본문·제목이 일치한다.
하나의 청크에 KB라이프생명 사업 설명, 새 `아.` 항목, 해외 등급 표가 함께
들어 있으며 `local_heading=[KB라이프생명]`이다. `table_context`는 해당 등급
항목을 가리키므로 모든 metadata가 잘못된 것은 아니다.

**삼성전자:** `라. 주요 사업의 내용`의 `[DX 부문]`은 단독 문단이라 제목으로
잡히지만 `[DS 부문]`, `[SDC]`, `[Harman]`은 설명과 같은 문단에 있어 plain
모드에서 제목으로 분리되지 않는다. 이후 `마. 연결대상 종속회사 현황`,
`바. 중소기업 해당 여부`, `사. 신용평가에 관한 사항`, `아. 주권상장...`에도
`[DX 부문]`이 잔존한다. 원문 신용평가 설명은 회사인 ‘당사’를 명시한다.
이는 부문 범위와 회사 범위의 충돌이다. 삼성전자 답변을 새로 생성하지는 않았다.

## 실패가 생기는 경계

1. [financial_parser.py](../../src/processing/financial_parser.py)의
   `_extract_paragraph_heading_parts` plain 경로는 문단 전체가 대괄호 제목일 때만
   제목을 만든다. `아. ...` 또는 제목과 본문이 합쳐진 문단은 일반 본문으로 남는다.
2. [block_collection.py](../../src/processing/block_collection.py)는 새로운 제목으로
   인식되지 않은 본문에도 기존 heading stack을 붙인다.
3. [chunking.py](../../src/processing/chunking.py)는 인식된 제목·scope가 바뀔 때
   pending 청크를 나눈다. 앞 단계가 경계를 놓치면 이전 회사 설명과 다음 항목이
   함께 청크로 묶일 수 있다. 따라서 chunker만의 문제로 분류하지 않는다.
4. 회사명이 없는 최소 fixture에서도 같은 동작을 재현했다. 강제 structured 모드에서도
   `[Birch] > 아. Next topic`이 남았다. 현재 정적 heading level에서 대괄호는 2,
   한글 번호는 3이므로 대괄호 아래의 새 항목처럼 쌓인다. 단순 whitelist 확장만으로는
   범위 종료를 해결하지 못한다. 이 모의 확인은 전체 보고서의 structured 재실행이 아니다.

## 다음 변경의 조건

이번 승인 범위인 provider-free 진단은 완료했다. 제품 변경과 답변 비교는 미실행이다.
수정 후보는 **원문 번호 체계의 동급 항목 전환에서 이전 하위 제목 범위를 종료하는
구조 복원**이다. 회사명·질문·신용평가라는 주제에 의존한 분기를 만들지 않는다.

구현 전에는 동급 전환과 대괄호 아래의 정상 하위 항목, 인라인 제목, 표 caption을
구분하는 계약을 먼저 고정해야 한다. 현재 static level을 전역 변경하거나 모든
대괄호 제목을 삭제하는 방식도 근거 없이 채택하지 않는다.
수정이 검증되면 기존 산출물을 유지한 별도 출력에서 metadata만 달리한 읽기 비교와
청크 경계 변경 비교를 분리한다. 재임베딩·전체 벤치마크·유료 답변 비교는 자동 실행하지 않는다.
