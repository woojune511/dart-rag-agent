# v9 저장 문맥 8개와 12개의 답변 비교 실행 준비

상태: **PREPARED_NOT_RUN**. 이번 준비의 모델·임베딩·검색·reranker·judge 호출은 **0회, USD 0**이다. 공식 요금 문서만 조회했으며, 실제 답변 생성과 품질 평가는 아직 하지 않았다.

**새 18문항 × 문맥 2조건 × 각 2회 = 새 답변 72개**를 비교하도록 고정했다. 예상 비용은 **약 $1.48~$1.79**, 제안하는 실행 상한은 **72회·$12.37·2시간 30분**이다. 양쪽 모두 새로 생성하며, 과거 답변으로 대조군을 대체하지 않는다. 이번 요청은 준비까지이고 이전 실행의 승인·소진 예산을 재사용하지 않는다.

[직전 v9 무호출 비교](new18_v9_rrf_context_window_comparison.md)에서 필수 근거 노출은 27/33→28/33, 기존 충분 근거 회귀는 0개였다. HD 원인은 9위라 12개에 들어오지만 U16 현금 요약과 미래 리스는 19·30위라 두 조건 모두 빠진다. 이번 비교는 **HD의 실제 답변 개선, U03의 표 해석, U16의 불충분한 근거 처리와 오독, 전체 답변 회귀**를 검증한다. 근거 노출 점수를 답변 점수로 사용하지 않는다.

## 예상 비용과 호출 상한

이번 준비에서 다시 읽은 [공식 Standard API 요금](https://developers.openai.com/api/docs/pricing)의 Terra short-context 요율은 1M tokens당 **입력 $2.00·캐시 읽기 $0.20·캐시 쓰기 $2.50·출력 $12.00**이다. [캐시 쓰기 계산](https://developers.openai.com/api/docs/guides/prompt-caching)에 따라 입력을 일반·읽기·쓰기로 나누고, 쓰기 비용을 일반 입력 비용에 중복 가산하지 않는다. reasoning은 출력 사용량에 포함된다. 세금·환율은 제외한다.

기존 v9 36답변의 실제 입력은 **244,698 tokens**, 출력은 **10,662 tokens**(reasoning 1,110 포함), 평균 출력은 약 296.17 tokens다. 새 top8의 입력 예상에는 이 실측값을 사용하고, top12는 문항별 **실측 top8 입력 × 최종 요청 UTF-8 byte 비율**을 올림해 추정했다. 72회의 예상 입력은 **612,874 tokens**, 기존 출력 길이 가정은 **21,324 tokens**다.

로컬 토크나이저 캐시가 없어 자동 다운로드를 네트워크 guard가 DNS 전에 차단했다. 토크나이저 의존성을 제거하고 저장된 사용량 기반 추정으로 준비를 완료했다. **새 top12 토큰 수는 측정값이 아니다.** 추가 자료의 토큰 밀도·출력 길이·캐시 동작이 달라질 수 있다. 최대 예약액은 이 추정에 의존하지 않는다.

## HD 실제 답변 개선

U04의 목표는 **2025 실적 변화에 중동·미주 매출 증가와 수익성 개선을 연결하는 설명**이다. 12개 조건의 9위 `20260316000940:1128:1`에 해당 원문이 있다. 실제 답변에서 의미가 정확히 전달되는지와 제공·인용한 출처가 지지하는지를 각각 기록한다. 특정 문자열 일치만으로 통과시키지 않는다.

조건별 0/2·1/2·2/2 사용과 두 matched 반복의 변화를 보고한다. 두 번 모두 8개 non-P→12개 P이면 반복된 목표 개선, 한 번만이면 부분 관측이다. 양쪽이 이미 P면 개선이 아니라 유지다. 목표 설명이 좋아져도 추가 수치·인과·기간 오류가 있으면 전체 성공으로 합치지 않는다.

기존 8개 문맥의 다른 경영진 설명으로 넓은 질문에 답한 경우에는 기존의 U 판정 원칙을 유지한다. 지정 원인 누락을 별도로 기록하고 이를 자동 F로 강화하거나 목표 P로 승격하지 않는다. 2026 매출계획을 2025 실적 원인으로 읽는지도 확인한다.

## 전체 18문항의 회귀 판정

조건·회차별 **정확도, 필수 항목 충족/누락, 출처 충실도, 실제 인용 지원, 경계 처리, 엄격 성공**을 P/F/U/NA/NOT_RUN으로 기록한다. 실행·schema·출처 ID 통과는 의미·산술 정확도와 구별한다. 모든 핵심 축·필수 그룹이 P이고 중대한 추가 문제가 없어야 엄격 P다.

문항·회차를 맞춰 **P→F와 P→U**, F→P와 U→P를 따로 집계한다. 총점으로 개별 회귀를 상쇄하지 않는다. 18문항의 네 답변 판정, 조건별 2/2·1/2·0/2 성공, 회사별 결과, 필수 항목 66관측/조건을 함께 보고한다. 추가 관계·계산·보고서 전체의 부재 주장도 검사한다. 오류·잘림·미실행은 예정 분모에 남긴다.

U14의 문제 서술은 이번 v9에서 14위라 양쪽 문맥에 없다. 과거 v6의 ‘12개에서 상충 서술 추가’를 재사용하지 않는다. U13·U15에는 기존 원문 충돌이 양쪽에 이미 있고, 출처에 충실한 논쟁 진술은 정확도 U·충실도 P가 가능하다. U17의 과거 비누적 설명 충돌도 이번 문맥에 없으므로 새 회귀로 세지 않는다.

원문 수치 검산은 표시 정밀도·허용 반올림·측정 기준을 유지한 사후 평가다. 제품 runtime이 계산을 검증했다고 주장하지 않는다. 새 gold 문제가 발견되면 원본을 유지하고 양쪽에 대칭적인 유보·재판정 기록을 남긴다. 질문 삭제·평가기준 조정·prompt 수정·추가 반복으로 점수를 맞추지 않는다. **2회 반복은 일반 정확도나 통계적 우월성의 근거가 아니다.**

## 중단 규칙과 무호출 검증

전송 직전에 실제 outgoing wire의 body·packet·slot 해시, 허용 endpoint, 시도 수, 누적 실제 비용·미확정 예약액·다음 최대 예약액, 남은 시간을 검사한다. 시도 기록은 전송 전에 남기며 실패한 요청도 호출 수에 포함한다. 미확정 timeout은 예약액을 반환한 것으로 계산하지 않는다. 다음 요청 90초를 남은 시간에 수용할 수 없으면 전송하지 않는다.

HTTP/transport 오류, timeout, incomplete/refusal, model·effort·tier 불일치, schema·출처 ID 오류, usage 누락/범위 이상, 입력 변경, 비용·호출·시간 한도 도달 시 중단한다. 나머지는 NOT_RUN으로 보존하고 재시도·fallback·추가 근거·자동 재개로 채우지 않는다. 답변 품질이 낮다는 이유로 추가 호출하지 않는다. 실행 결과의 기본값 자동 채택도 없다.

**준비 검증:** 기존 요청 일치 18/18, 12개에서 출처 4개만 추가 18/18, 고정 요청 36개·슬롯 72개·균형 순서·반복 해시·예약 산술을 확인했다. **모의 실행 72건과 거절 검사 26개**를 통과했다. 기존 답변은 schema·출처 ID·usage fixture일 뿐 새 답변이나 새 품질 판정이 아니다. 이번 검증은 같은 assistant가 수행했으며 독립 평가라고 표현하지 않는다.

준비 묶음에는 live API client가 없다. 실제 실행 단계에서는 전용 adapter가 **동일 검사를 실제 전송 경계에서 적용하는지 먼저 확인**해야 한다. 기존 95회 store 구축 실행기나 과거 v6 문맥 실행기를 그대로 실행하지 않는다. 현재 모든 새 답변·품질 판정은 NOT_RUN이다.
