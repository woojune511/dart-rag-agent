# 동일 근거에서 선택 기록을 출력하는 실험 — 재시도 후 완료 결과

상태: **COMPLETE_SOURCE_REVIEWED_WITH_ONE_AUTHORIZED_RETRY**.

HTTP 520으로 중단됐던 요청을 사용자 요청에 따라 같은 입력으로 한 번 재시도했고 성공했다. 이후 추가 오류 없이 원래 계획한 **6문항 × 2조건 × 3회 = 36개 답변**을 모두 확보했다.

완전 정답은 **기존 P0 7/18, 선택 기록 S1 4/18**이었다. 인용 근거 지지 PASS도 **9/18 → 6/18**이었다. 이 개발 노출 실패 문항 패널에서는 개선을 확인하지 못했다. 기본 프롬프트와 제품 동작은 유지한다.

이 문서는 [중단 시점의 부분 결과](reader_selection_records_result_2026-10-20.md)를 이어 완료한 결과다. 당시의 6개 응답과 판정은 그대로 보존했다.

## 오류와 재개

실패 응답은 Cloudflare의 `unknown_origin_error`이며 HTTP 상태는 520이었다. 원문 서버에서 비어 있거나 예상 밖의 응답을 받아 처리하지 못하는 경우에 해당한다. [Cloudflare 공식 문서](https://developers.cloudflare.com/support/troubleshooting/http-status-codes/cloudflare-5xx-errors/error-520/)

실제 오류 본문에는 `retryable: true`, `retry_after: 60`이 있었다. 권고된 지연보다 오래 지난 뒤, 사용자의 “그냥 바로 재시도 해봐도 되나?” 요청을 받아 실패 요청 한 건을 재시도했다.

- 기존 완료 응답 6개와 오류 응답을 수정하거나 삭제하지 않았다.
- 실패 요청의 모델·프롬프트·스키마·질문·근거와 재시도 요청이 동일함을 확인했다.
- 성공 후 원래 미실행이던 29개 요청을 이어 실행했다. 성공한 답변을 다시 생성하거나 좋은 답변만 선택하지 않았다.
- 최종 HTTP 시도는 37회, 정상 답변 36개, 520 실패 1개다. 수동 재시도 1회 외 SDK 자동 재시도는 0회다.
- 실패 요청의 사용량은 알 수 없으므로 예약액 $0.273304를 남겨 두고, 이전 완료분을 포함한 원래 2달러 상한 안에서 재개했다.

동일 요청이 재시도에 성공한 관측은 이번 실패를 일시적인 서버 응답 문제로 보는 해석을 뒷받침한다. 정확한 서버 내부 원인은 확인되지 않았다.

## 비교 조건과 판정

P0는 기존 지시와 `RagAnswer` 출력이다. S1은 원래 지시에 일반적인 기록 지시를 추가하고, 최종 답변 전에 `evidence_selections`를 출력한다. 각 기록에는 요청 항목, 사실 또는 수량, 주체, 기간, 범위, 원문 값·단위, 출처 ID와 원문 인용을 넣는다.

모델은 양쪽 모두 `gpt-5.6-terra`, reasoning `low`, 출력 한도 8,192토큰이다. 질문과 근거는 이전 실험의 고정 패킷을 그대로 사용했다. 5문항은 top-12, NAV_T3_032는 top-8 패킷이다. 새 검색·임베딩·judge 호출은 없으며, 각 답변은 모델 한 번 호출로 생성했다. 생성 요청에 평가 정답이나 문항별 실패 원인을 넣지 않았다.

완전 정답은 기존 정확성·요청 충족·인용 근거 지지가 모두 PASS인 경우다. 중단 전 6개 판정을 유지하고, 재개 후 30개는 선택 기록과 조건 이름을 가린 최종 답변부터 검토했다. 판정과 해석상 경계 사례를 저장한 뒤 조건을 공개했다. 이후 선택 기록의 물리적 대응과 의미를 별도로 확인했다. 기록의 결함을 최종 답변의 주 지표에 소급해 추가하지 않았다.

독립 평가자는 없었다. 같은 에이전트가 검토했으며, 출력 스타일로 조건을 추측할 수 있다.

## 기록으로 구분한 실패 단계

### 1. 값 선택 단계에서 같은 오류를 반복했다

**차량 영업이익:** S1 세 번 모두 차량 `12,969,227백만원`을 선택했다. 출처에 있는 조정 전 값이다. 전체 `15,126,901백만원`은 조정 후 값이며, 원래 평가 기준인 조정 포함 차량 `12,677,300`과 비중 `83.8%`도 같은 패킷에 있었다. `scope: 연결 영업부문`이라는 기록만으로 두 조정 기준을 구분하지 못했다.

조정 전 값을 전체와 비교한 `85.74%` 자체는 그 피연산자 기준으로 맞다. 따라서 원문 숫자의 날조와 기준 선택을 구분했다. S1 1회차는 그 분수도 `85.81% ≈ 85.8%`로 잘못 계산했다. S1 나머지 두 번과 일부 P0는 전체에 조정이 포함됐다고 밝혔지만, 원래 조정 포함 차량 기준의 답을 주지는 않았다.

**상각비:** S1 세 번 모두 `fact_or_quantity`에 “무형자산상각비 기능별 항목 합계”라고 적고 `182,286,838천원`을 선택했다. 이어 이 전액을 영업비용으로 가정해 `8.38%p`를 계산했다.

동일 근거의 매출원가와 판관비 합계는 `182,049,824천원`이다. 나머지 `237,014천원`은 개발비·건설중인자산 배분이다. 손익 비용 기준의 영향은 `182,049,824 ÷ 2,176,431,531 × 100 = 8.364601…%p`, 즉 `8.36%p`다. 정확한 항목명을 기록한 뒤에도 필요한 비용 범위를 고르지 못했다.

### 2. 인용문은 정확해도 기록의 기간 연결이 틀렸다

제네시스 S1 2·3회차는 2023년 미국 현대차 판매 실적에 2022년 제네시스 판매 호조 설명을 결합했다.

- 2회차: 2023년 현대차 판매 문장을 인용하고 `fact_or_quantity`를 제네시스의 미국 판매 성장 기여로 기록했다. 해당 문장은 그 기여를 말하지 않는다.
- 3회차: 2023년 판매 문장과 2022년 제네시스 기여 문장을 같은 기록에 붙이고 `period: 2023년`으로 지정했다.

파이프라인 S1 1·2회차도 “작성기준일 이후 신청”이라는 주석을 그대로 인용하면서 기록의 기간을 “작성기준일 현재”로 고정했다. 최종 답변에서도 사후 신청 시점이 빠졌다.

### 3. 기록이 맞아도 최종 답변에서 미지원 설명이 추가됐다

미국 성장률 S1의 세 답변 모두 `87.0만 대/2023년`, `78.1만 대/2022년`을 올바르게 기록했다. 그러나 1·2회차 최종 답변은 계산값 `11.4%`와 원문 `11.5%`의 차이를 반올림 때문이라고 확정했다. 제공 근거는 그 원인을 설명하지 않는다. 3회차는 두 값을 분리해 정답이었다.

파이프라인 S1 3회차는 기록에 없는 CT-P53·CT-P55의 참조 브랜드명을 최종 답변에 추가하고, 그 대응이 있는 `1056:11`을 인용하지 않았다. 사실 자체는 다른 제공 청크에 있지만 최종 인용 집합으로 지지되지 않는다.

### 4. 기록은 산술 실행·검증을 대신하지 못했다

CAPEX S1 1회차는 원문 값을 기록한 뒤 `756.2−692.3`을 `64.0십억원`이라고 계산했다. 올바른 감소액은 `63.9십억원`이다. 나머지 두 번은 정답이었지만, 과거 틀린 감소율을 생략한 응답이므로 그 비율의 계산 능력이 개선됐다는 근거는 아니다.

제품 경로에서 계산 도구를 실행하거나 의미 검증을 추가한 것은 아니다. 위 재계산은 생성이 끝난 뒤의 평가다.

## 인용 기록의 물리적 대응

S1 응답 18개에서 기록 64개와 인용 구간 69개를 얻었다.

- 인용 출처 ID 69개 모두 제공된 근거에 존재하며 최종 인용 목록에도 포함됐다.
- 67개 인용은 제공 청크의 연속 문자열과 정확히 일치했다.
- 2개는 원문에서 떨어진 행들을 이어 붙였다. NAV 1회차의 표 머리글·취득 행, 2회차의 회사채 시설자금 두 행이다. 없는 숫자를 만든 사례는 아니지만, “정확한 연속 인용” 조건을 위반했다.
- 모든 응답에서 기록 필드가 답변 필드 앞에 출력됐다. 이는 내부 추론 순서의 증명이 아니다.

물리적 일치는 의미·기간·기준 선택의 정확성을 보장하지 않았다. 반대로 원문 값 여러 개를 `/` 등으로 합친 문자열이 인용문 전체와 다르다는 이유만으로 숫자 오류라고 세지도 않았다.
