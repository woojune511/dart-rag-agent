# U03와 U16 답변 회귀의 원문 및 청킹 진단

2026-10-16. 추가 외부 API 호출 **0회**, 비용 **USD 0**. 저장된 8개·12개 문맥과 실제 답변을 원문 XML까지 역추적했다. 기존 평가 점수·요청·답변·store·`.env`와 런타임 코드는 변경하지 않았다.

**U03의 지역별 금액 오연결은 열 손실로 설명되지 않는다. 올바른 열·값 대응이 실제 전송 입력까지 보존됐고 모델 답변에서 달라졌다. U16은 전기말을 당기말로 읽은 답변 오류와, 다음 표의 소개문을 앞 표 뒤에 합치는 청킹 경계 문제가 함께 확인됐다.** 다만 청킹 혼합이 모델 오답을 유발한 인과 효과는 추가 생성 실험 없이 확정할 수 없다.

## 검증 범위와 재현

동결된 [직전 답변 비교](new18_rrf_window_answer_result.md)의 U03·U16 각 4개 답변과 실제 HTTP 요청 8개를 읽었다. 원본 XML은 새 문항 작성 묶음 (`../../benchmarks/results/new_report_user_eval_2026-10-15/`, local artifact not included)에 저장된 HD현대일렉트릭 `20260316000940`, 호텔신라 `20260311004398`이다.

네트워크 연결을 차단한 프로세스에서 현재 v6 파서와 원래 `2500/320` 청킹·검색 입력 포맷을 재실행했다. HD 1,305개와 호텔신라 1,248개, **총 2,553개 청크의 본문·전체 메타데이터·검색 입력이 저장본과 모두 일치**했다. 두 원문의 section fallback은 없었다. 따라서 이번 재현은 저장 실험과 다른 청킹 조건을 사용한 결과가 아니다. store를 열거나 임베딩을 생성하지 않았다.

실제 전송 요청 8개는 동결 요청과 같았고, 각 요청의 user 메시지는 저장 packet과 일치했다. 각 조건의 두 반복은 **전송 본문 바이트까지 동일**했다. 12개 문맥의 앞 8개도 8개 조건과 동일하며, 문서 텍스트와 공개 context는 저장 청크와 같았다. 실제 전송이나 평가 파일을 만들 때 열을 이동시킨 흔적은 없다.

단계별 추적 (`../../benchmarks/results/new18_u03_u16_regression_audit_2026-10-16/stage_trace.json`, local artifact not included)은 원문 셀·byte witness, 파서 블록, 청크, 순위, 실제 답변을 연결한다. 진단 검사 (`../../benchmarks/results/new18_u03_u16_regression_audit_2026-10-16/diagnostic_checks.json`, local artifact not included)의 42개 항목은 XML 구간 해시, 열 대응, 실제 packet, 기간과 청킹 경계를 검사한다. 이 검사는 제품의 의미 검증 기능이나 새로운 답변 평가를 뜻하지 않는다.

## U03 지역 열은 유지됐고 답변에서 연결이 바뀜

원문 `original:1124`(XML 23265행)의 지역 표는 다음과 같다. 단위는 **백만원**이다.

| 원문 열 | 원문·구조화 셀·실제 문맥 값 | 12개 1회차 답변에서 붙인 지역 |
|---|---:|---|
| 본사 소재지 국가 | 932,160 | 국내 |
| 북미 | 1,611,950 | **아시아** |
| 아시아 | 1,098,132 | **유럽** |
| 유럽 | 413,598 | **북미** |
| 기타 국가 | 23,658 | 언급하지 않음 |
| 지역 합계 | 4,079,498 | 총매출 |

원문은 첫 헤더 셀이 비어 있는 7열 표다. 대상 표에는 rowspan/colspan 병합이 없고, 파서 grid·`rows[].cells[].column_headers`·`values[].column_headers`가 모두 올바르게 대응한다. 출력 본문에서도 첫 빈 셀이 선행 `|`로 남아 있다. 공백 정규화(`지역  합계`→`지역 합계`) 외에 헤더·숫자 내용은 달라지지 않았다. [표 grid 복원](../../src/processing/table_structure.py)이나 청킹에서 한 칸 밀린 사례가 아니다.

값 청크 `363:255`는 Dense 6위, RRF 9위로 12개 조건에 새로 들어왔다. 틀리게 연결한 세 금액은 저장된 U03 후보 37개 중 이 청크에만 등장하며, 여기에는 **북미→아시아→유럽** 순서가 정확히 보인다. 답변의 오류는 값의 단위 변환이나 자리수 변화가 아니라 지역명과 금액의 연결 변경이다. 단순한 한 칸 밀림으로도 세 변경을 모두 설명하지 못한다.

12개 1회차는 위 세 지역을 틀렸지만 **같은 전송 본문**의 2회차는 세 지역과 값을 모두 올바르게 답했다. 8개 두 답변은 해당 상세 지역 금액을 주장하지 않았다. 이번 비교에서 추가된 정보에 대한 생성 오류가 관측됐다는 뜻이며, 원문 파싱이 매번 잘못된 지역 대응을 공급했다는 설명과는 맞지 않는다.

다만 기간 전달에는 실제 약점이 있다. 원문 바로 앞 `original:1123`에는 “고객과의 계약에서 생기는 수익의 구분에 대한 공시_지역별 / 당기 / (단위 : 백만원)”이 있다. 이것은 별도 `362:254` 청크의 `period_focus=current`와 값 표의 `table_object_json.source_contexts`에 남았지만, 값 청크 `363:255`는 `period_focus=unknown`이다. `362:254`는 37개 후보 합집합에도 없어 두 입력에서 빠졌다. [원문 context 공개 필드](../../src/config/simple_rag.py)는 전체 `source_contexts`를 보내지 않으므로 내부 연결의 보존이 모델 입력의 보존과 같지는 않다.

이 차이는 [혼합 표제의 단위만 넘기는 파서 경로](../../src/processing/financial_parser.py)의 현재 동작과 일치한다. 값 청크의 검색용 `table_value_labels`도 지역 열을 빼고 같은 행 이름과 숫자만 반복한다. 그러나 본문과 별도 헤더에는 열이 있으므로 **지역 정보 전체가 소실됐다고 할 수 없다**. 빈 첫 셀, 반복된 행 중심 요약, 추가 문맥 길이 등이 독해를 어렵게 했을 가능성은 추정이며, 각각의 효과는 분리해 측정하지 않았다.

## U16 전기말은 남아 있지만 다음 당기말 표제가 섞임

원문 순서와 재현된 출력은 다음과 같다. 금액은 천원이다.

| 단계 | 당기 현금 표 | 전기 현금 표 | 다음 금융부채 표 |
|---|---|---|---|
| 원문 | 당기말 소개문 → 현금 **338,290,694** | `② 전기말` → 현금 **370,379,065** | 금융부채 상환계획 소개문·`① 당기말` → 원금 등 표 |
| 파서 블록 | 당기 표와 뒤의 전기말 문단이 별개 | 전기 표와 뒤의 당기말 소개문이 별개 | 별도의 금융부채 표 |
| 청크 본문 | `57:3`: 당기 표 + **다음 `② 전기말`** | `58:4`: 전기 표 + **다음 금융부채 소개문·`① 당기말`** | `59:5`: 당기 부채 표 + 다음 `② 전기말` |
| 청크 metadata | `table_context`는 당기말 소개문 | `table_context`는 **`② 전기말`** | `table_context`는 당기말 부채 소개문 |

대상은 원문 `original:190~195`이며, 전기 현금 표 자체는 `original:192`(XML 3743행)다. 원문에서는 다음 `① 당기말`이 금융부채 상환계획을 소개한다. 앞의 전기말 현금 표를 당기말로 바꾸는 문장이 아니다.

**혼합이 생기는 위치는 [chunk_blocks](../../src/processing/chunking.py)의 짧은 표 병합이다.** 전기 표는 431자로 독립 표 기준 1,250자보다 짧다. 뒤의 75자 소개문은 같은 heading scope에 속해 pending 목록에 붙고, 다음 표가 도착할 때 flush된다. 결과 본문은 정확히 `전기 표 431자 + 빈 줄 2자 + 다음 소개문 75자 = 508자`다. 이때 `table_context`는 첫 표에 맞는 전기말을 유지한다.

인접한 파서 블록 7개만으로 이 출력을 재현했다. 진단용 메모리 입력에서 다음 소개문 하나만 제외하자 전기 표의 모든 값·열과 `table_context=② 전기말`은 그대로이고, 당기말 꼬리 문장만 사라졌다. 이는 **청킹이 꼬리 문장을 합치는 원인**을 확인한 대조이며, 모델 답변을 다시 생성해 개선을 확인한 실험은 아니다. 런타임이나 저장 청크는 바꾸지 않았다.

기간의 구조화는 불완전하다. 파서의 table bundle에는 `period_labels=[]`, `period_focus=unknown`이 저장되고, 청킹에서 앞 문단을 `table_context`에 붙여도 이 필드는 다시 계산되지 않는다. 그렇다고 `current`로 잘못 저장된 것은 아니다. 실제 전송에는 `[table_context: ② 전기말]`이 text에 있고 JSON context에도 같은 값이 있다. 따라서 **기간 단서가 완전히 사라진 오답**으로 분류할 수 없다.

12개 2회차는 이를 “연결 기준 **2025년 말** 현금및현금성자산은 **370,379,065천원**”으로 답했다. 원문의 2024년 말 연결 현금 **370,379,064,991원**을 천원으로 반올림하면 이 값과 일치한다. 실제 2025년 말 현금은 **338,290,693,972원**, 천원 반올림값은 **338,290,694**다. 보고서의 `year=2025`는 표별 당기·전기를 대체하지 않는다.

같은 12개 전송 본문의 1회차는 2025년 말 현금 근거가 없다고 답하고 이 전기값을 사용하지 않았다. 따라서 모델이 보존된 전기말 단서를 따르지 않은 사실은 확인된다. 다음 당기말 문장, 보고서 연도, `period_focus=unknown` 중 무엇이 얼마나 영향을 주었는지는 확인되지 않았다. **청킹을 고치면 이 오류가 반드시 사라진다는 결론도 아직 없다.**

## 현재값 누락과 잘못된 답변을 분리

U16의 전기 현금 청크 `58:4`는 Dense 5위, RRF **11위**라 8개에는 없고 12개에는 들어간다. 당기 현금 **338,290,694천원**을 포함한 다른 표 `1028:2`는 RRF **17위**, 순부채 표에서 같은 현금값을 담은 `493:409`는 **33위**다. 경영진단 요약의 `1026:0`은 **24위**이며 현금을 3,383억원으로 제시한다. 당기 현금 표는 저장된 후보에 있지만 8개·12개·16개 모두에서 제외된 것이다.

기존 정답의 1년 리스 금액 82,251,054천원 및 유동 리스 장부액 81,011,496천원은 저장된 후보 합집합에 해당 숫자가 없다. 숫자 검색 자체를 의미 평가로 대신하지는 않으며, 기존 필수 근거 누락 판정을 유지한다. 문맥에 있는 리스부채 총잔액이나 과거 지급액으로 미래 1년 상환액을 대체할 수 없다.

이것은 U16의 지속적인 불완전 답변을 설명하는 **근거 선택 문제**다. 반면 12개 2회차가 전기 현금을 현재 현금으로 단정한 것은 그 불완전함 위에 추가된 **생성 오류**다. 현재값이 없는 상황에서도 1회차처럼 근거 부족을 설명할 수 있었다. 저장된 RRF는 원문을 수정하지 않았고, 이번 추적으로 점수 산식 버그를 발견한 것도 아니다.

## 다음 변경의 우선순위

1. **먼저 표 경계를 바로잡는 최소 변경을 검증한다.** 물리적으로 다음 표를 소개하는 문단·기간 표제를 앞 표의 본문 뒤에 합치지 않고 소유한 표와 함께 보존하는 일반 규칙이 대상이다. 기간 표제를 단순 삭제하면 다른 질문의 근거가 줄어들므로 안 된다. 회사명이나 U16 전용 분기를 넣을 이유가 없다.
2. **표제·기간의 원문 연결을 값 표 입력까지 전달하는 별도 검증을 한다.** U03의 당기 표제 분리와 U16의 `period_focus=unknown`을 함께 고려하되, 임의의 이웃 문단을 해당 표의 의미로 승격해서는 안 된다. 원문 연결 검증과 모델의 기간 해석 정확도는 따로 평가한다.
3. **U03의 열 오독은 별도의 표현 실험으로 다룬다.** 원문에서 검증된 `행·열·값` 대응을 모델에 명시하는 표현을 후보로 둘 수 있다. 이미 올바른 구조화 셀이 있으므로 원문 숫자를 다시 파싱하거나 회사별 규칙을 추가할 필요는 없다. 입력 표현만 바꿨을 때의 답변 개선은 아직 미측정이다.

이번 결과는 후보나 문맥을 일괄 늘릴 근거가 아니다. 먼저 위 경계 수정의 provider-free 재현과 기존 근거 보존을 확인할 수 있다. 이후 생성 비교는 별도 조건·상한을 고정해야 한다. 기본 RRF·문맥 8개는 유지한다.

## 보존과 한계

진단 자료는 별도 새 묶음 (`../../benchmarks/results/new18_u03_u16_regression_audit_2026-10-16/`, local artifact not included)에 기록했다. 원문·과거 동결 평가·기존 소스 및 문서·`.env`·store를 포함한 보호 대상은 2,507개다. 최종 보존 검사 (`../../benchmarks/results/new18_u03_u16_regression_audit_2026-10-16/closeout.json`, local artifact not included)에 전후 해시, 새 산출물 해시, 0회 호출 및 store 미개방을 기록한다.
