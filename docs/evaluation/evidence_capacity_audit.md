# 요청 항목별 근거와 입력 용량 진단

2026-09-30. **COMPLETE_OFFLINE_REVIEW**. 모델·임베딩·답변 호출0, 비용USD0. 제품 변경 없음.

**다음 개선 후보를 최종 근거 선택 단계로 좁힐 수 있다.** 검토한27문항 중7개에서는 필요한 원문이 이미 후보에 있으며, 이를1–2개 청크·최대7,963바이트로 전달할 수 있었다. 현재 top8에는 그 묶음이 없다. 따라서 이7개에 대해서는 후보 생성이나 입력 한도를 바꾸기 전에 최종 선택을 검증할 근거가 있다. 실제 selector가 그 묶음을 고를 수 있다는 결과나 제품 도입 승인은 아니다.

## 방법과 판정 경계

- [절 선택 실험](section_hybrid_result.md)의 동일한27개 노출 문항을 재사용했다. 저장된 **A: 보고서 전체 exact Dense16/BM25≤24 후보 합집합**과 기존 packet을 사용했다. B 절 선택 결과를 A 후보에 합치지 않았다. 새 검색, 질문 임베딩, 재수집, store 열기/쓰기 없이 저장 JSON과 원문을 읽었다.
- 질문을 기간·대상·범위·수치·서술 요구로 나누고, 기존 정답 예시는 원문을 찾는 단서로 사용했다. 예시의 모든 부가사항을 질문의 필수 항목으로 승격하지 않았다. 각 검토 항목에 원문 ID와 정확한 인용 구간을 남겼다.
- 같은 청크가 여러 항목을 충족할 수 있고, 서로 대체 가능한 묶음도 기록했다. 숫자와 설명의 연결/별도 범위를 섞지 않았다. 타법인출자 현황처럼 질문이 허용하는 대체 출처는 그 기준을 명시하는 조건으로 인정했다.
- 개방형 요약은 질문에 답할 수 있는 **최소한의 직접 근거**를 확인했다. 모든 가능한 주요 요인의 누락 없는 포괄성을 보장하지 않는다. 과거 예시에만 있는 세부사항은 별도 보조 기록으로 남겼다. 이 판단은 결과를 본 동일 assistant의 검토이며 독립 gold, 사전 등록 평가, 새 holdout이 아니다.
- 검토한 대체 묶음의 모든 조합을 만들고 원문 청크·출처 ID·기존 context를 그대로 직렬화했다. 표 헤더의 반복분도 비용에 포함했다.8개·65,536 UTF-8 JSON바이트 제한 아래 가능한 최소 바이트 묶음을 계산했다. 줄이기·행 추출·본문 수정·새 문맥 추가는 하지 않았다.
- 이것은 **검토된 매핑 안에서의 최소 크기와 실현 가능한 입력 예시**다. 모든 의미적 대체근거를 망라한 전역 oracle 상한이 아니다. 완전한 묶음을 찾지 못한 경우도 보고서나 후보 전체에 대체근거가 없다고 단정하지 않는다.
- 원문의 숫자·헤더·일부 당기/단위는 저장된 XML의12개 표와 추가 대조했다. 모든 문맥 메타데이터를 독립적으로 재검증한 파서 감사는 아니다. 원문과 충돌한 gold를 조용히 바꾸지 않고 별도 보류로 남겼다.

## 검증 및 다음 단계

- 저장된27개 baseline packet을 원문·context로 재구성하여 동일함을 확인했다.
- 가능한20개 묶음은 실제 `SimpleRagAgent.run`에 고정 검색 결과를 넣어 생성 직전 입력을 가로챘다. 모델 호출은 없다. 독립 구성 결과와20/20 동일했다.
