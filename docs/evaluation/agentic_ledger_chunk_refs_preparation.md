# 청크 참조 원장: 첫 문항 확인 후 6문항 실행

2026-09-28. 사용자는 출처 ID와 해석으로 참조를 단순화하고 무호출 검증,
첫 문항 실제 실행, 정상 완료 시 나머지5문항을 이어가는 제안에 “진행해줘”라고 답했다.

새 실험은 모델의 `piece_start`/`piece_end`와 코드 복사 인용문을 제거한다.
모델은 `source_id`와 짧은 `note`만 선택한다. 입력은 조각 번호 없이 기존 청크 원문과
context를 제시한다. 코드가 원장의 evidence/qualifications 참조를 중복 제거해 다음
검색에서 보존하고 답변에 전체 원문을 전달한다. 원장에는 코드가 생성한 출처 hash와
chunk 단위 참조라는 표시를 붙인다.

검증 보장은 정확한 구간 연결에서 **청크 단위 연결**로 바뀐다. note의 의미 지원이나
특정 문장이 있다는 보장은 하지 않는다. 미노출·미등록·다른 보고서·청크 ID 불일치,
빈 원문, 출처8개 초과, 보존 원문/답변 용량 초과는 여전히 거절한다. 이전 좌표형 출력은
새 형식으로 자동 변환하지 않는다. 기존 실패와 점수는 보존한다.

## 고정 실행 범위

- 기존6문항과 순서, corpus/store/vector, 검색 방식, 평가 rubric 유지. 기본 앱 변경 없음.
- 모델 `gpt-5.6-terra`, low reasoning, default tier, 출력8,192토큰, store=false 유지.
- 문항당 추가 검색 최대2회, 선택 청크 최대8개. 초기 진단 답변과 추가 검색 후 답변을 기록하며 검색이 없으면 답변을 공유한다.
- 생성 최대30회·질의 임베딩 최대12회·보수적 USD15 상한, 전체 예약 상한USD14.0106. 재시도·resume·출력 수정 없음.
- 첫 문항의 결정·검색·답변 계약이 정상 완료되면 `pilot_gate.json`을 기록하고 같은 배치에서 나머지5문항으로 진행한다. 이는 **실행 계약 통과 기준**이며 정답 판정으로 다음 문항을 선별하지 않는다.
- 오류가 발생하면 배치 중단, 미실행 문항은 NOT_RUN.20초 heartbeat를 기록한다.

실제 평가 기준은 이전 계획을 그대로 사용한다. 실행 완료와 답변 품질을 구분하고
근거 보존·추가 검색의 회수·성급한 충분성 판단·인용 지원·완전성·비용을 보고한다.
카카오의 대안 답변 민감도는 원래 strict rubric과 별도로 유지한다. 개발에 노출된
6문항의 역사적 비교이므로 독립 gold, holdout, 인과 효과를 주장하지 않는다.

22개 청크 계약 테스트와 최대 경로42회 모의 호출,15개 중단 통제를 검증한다.
기존 모델·검색·예산 정책의 동일성과 panel/rubric hash를 확인한 뒤 새 manifest에
연결한 일회성 승인으로 실행한다. 이전 승인은 재사용하지 않는다.
