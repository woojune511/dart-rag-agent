# 동일 후보에서 RRF 합계와 최댓값 비교

2026-09-30. **COMPLETE_OFFLINE_SUM_VS_MAX; NO_NET_GAIN; NOT_ADOPTED**.

77개 고정 입력에서 합산 방식만 바꿨다. 검토된 대표근거의 실제 입력 전달은
**8→8개**로 같았다. 최댓값은 수수료·판매보증 근거를 복구했지만, 모셔널·총자본
근거를 밀어냈다. 답변은 생성하지 않았으며 정답률이나 문항 전체의 충분성을 평가하지 않았다.
사전에 정한 순이득 없음 종료 조건에 따라 가중치·상수·동점 순서를 추가 조정하지 않는다.

## 고정 조건과 범위

[Dense16→32 실험](full77_v5_dense32.md)의 B 후보를 그대로 재사용했다.
현재 앱 기본 Dense16을 바꾸는 배포 실험이 아니며, 실제 ANN32 실행도 아니다.

| 항목 | A: 기존 합계 | B: 최댓값 |
| --- | --- | --- |
| 후보 | 저장된 정확 Dense32와 BM25 최대24개 | ID·순서·원문·metadata 동일 |
| 점수 | 존재하는 목록의 1/(60+순위)를 합산 | 같은 기여값 중 최댓값 |
| 동점 | Dense 최초 삽입 순서, 이어서 새 BM25 ID | 기존 방식 유지 |
| 중복 원문 | BM25 객체가 덮어씀 | 동일 |
| 최종 선택 | 상위8개 | 동일 |
| 입력 | 65,536바이트, 원문 전체 단위로 제외 | 동일 |
| 질문·보고서 범위·프롬프트·스키마 | 고정 | 동일 |
| LLM·임베딩 호출 | 0 | 0 |

새로운 검색, 저장소 열기·변경, 재수집, 생성 답변, 오류 재시도는 없었다.
실제 SimpleRagAgent 입력 생성 경로에서 모델 호출 직전에 중단하여 154개 packet을 확인했다.
모델 출력이나 원시 응답은 없으며 저장 산출물은 후보 순위와 모델에 전달될 입력이다.

27개 기존 대응을 고정했다. 이 중 26개는 위치 추적 대상이고, 1개는 주석 요청 적합성
유보 상태를 유지했다. 새 정답 근거나 질문별 성공 기준을 결과에 맞춰 추가하지 않았다.

## 관측된 원인과 입력 변화

최댓값 점수는 두 목록 중 더 높은 순위만 사용한다. BM25 1위인 두 복구 근거는
중복 등장 보너스를 받은 다른 청크에 밀리지 않게 됐다. 반대로 두 목록에서 함께
발견된 모셔널(17·12위), 총자본(9·7위) 근거는 합산 이점을 잃었다.
이는 검색 순위 조합의 상충 관계이며, 어느 근거가 의미적으로 더 적합한지를
순위만으로 판정할 수 있다는 증거는 아니다.

8·9위가 같은 점수인 입력은 **14→20개**였다. 기존 Dense 우선 삽입 순서를 그대로
유지했다. 예를 들어 MIX_T3_048의 대표근거는 B 9위이고 8위와 동점이지만 제외됐다.
결과를 보고 동점 규칙을 바꾸지 않았다. 위에서 바뀐 대표근거4개는 B 경계 동점에 없다.

| packet 점검 | 합계 | 최댓값 |
| --- | ---: | ---: |
| 전체 입력 바이트 합계 | 2,050,179 | 2,046,957 |
| 가장 큰 입력 바이트 | 62,234 | 63,175 |
| top8 중 용량 때문에 빠진 청크 합계 | 3 | 7 |

77개 중2개 입력만 완전히 같고75개가 바뀌었다. 긍정55/55, 근거 부족17/19,
진단3/3 입력이 바뀌었다. 순서만 달라져도 변경으로 집계한다.
전체 바이트는0.157% 줄었지만 이를 토큰 비용 절감으로 주장하지 않는다.
65,536바이트를 넘는 입력은 없고, 제외된 청크를 자르거나9위 이후로 보충하지 않았다.
근거 부족 문항도 답변을 생성하지 않았으므로 기권 안전성·confusion matrix는 평가하지 않았다.

기존에 별도로 검토한 배출권 별도 회계정책 대체근거는4→2위로 계속 전달됐다.
고정 연결 대표문단은11→25위로 양쪽 모두 제외됐다. 대체근거를 주 집계에 섞지 않았다.
