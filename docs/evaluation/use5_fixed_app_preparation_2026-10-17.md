# 기존 보고서 2개 실사용 질문 5개 — 실행 전 준비

상태: **PREPARED / NOT_RUN**. 2026-10-17. 질문별 **1회**, 총 5개 답변을 확인한다.
이번 준비에서 모델·임베딩 호출, 검색 실행, 앱 재시작은 하지 않았다.

목적은 현재 앱이 보고서를 읽는 데 얼마나 도움이 되는지 작은 사례로 확인하는 것이다.
실제 사용자 로그가 아니라 실사용 상황을 가정해 새로 작성한 질문이다. 익숙한 보고서이며
P03·P04는 일부 근거를 공유한다. 독립 holdout이나 일반 정확도, 기존 평가 대비 회귀 검증으로
해석하지 않는다. 결과를 본 뒤 질문·검색·프롬프트를 조정하는 후속 실험은 포함하지 않는다.

## 질문과 사전 판정 기준

**P01 — 삼성전자 선택**

> 삼성전자는 2023년에 전년보다 얼마나 부진했나요? 연결 매출액과 영업이익을 2022년과 비교해 금액과 증감률로 보여주세요.

필수 6개: 2023/2022 연결 매출액 **258,935,494 / 302,231,360백만원**,
2023/2022 연결 영업이익 **6,566,976 / 43,376,630백만원**,
매출 **약 14.3% 감소**, 영업이익 **약 84.9% 감소**.
증감률은 `(2023 / 2022 - 1) × 100`으로 평가자가 확인한다.
근거: `III. 재무에 관한 사항 > 1. 요약재무정보 > 가. 요약연결재무정보`, v12 청크 `20240312000736:117:0`.
연결/별도, 연도 열, 단위, 증감 방향 오류는 중대 오류다. 앱이 산술을 코드로 검증했다고 주장하면 안 된다.

**P02 — 삼성전자 선택**

> 삼성전자는 2023년 설비투자에 총 얼마를 썼고, 어느 사업에 가장 많이 투자했나요? 가장 큰 부문의 투자액과 투자 목적도 알려주세요.

필수 4개: 총 **531,139억원(약 53.1조원)**, 가장 큰 부문 **DS**,
DS 투자 **483,723억원(약 48.4조원)**, **첨단공정 증설·전환과 인프라 투자 중심**이라는 설명.
원문은 DS·SDC 등에 관한 투자 설명이며 사업별로 없는 목적을 배분하지 않는다.
근거: `II. 사업의 내용 > 3. 원재료 및 생산설비 > 시설투자 현황`,
청크 `20240312000736:61:18`, `20240312000736:62:19`.
유형자산 장부가액이나 연구개발비로 대체하거나 2024년 계획을 2023년 집행으로 읽으면 중대 오류다.

**P03 — SK하이닉스 선택**

> SK하이닉스는 2023년에 왜 영업적자로 돌아섰나요? 적자 규모와 주요 원인, 하반기에 업황이 나아진 배경을 설명해주세요.

필수 6개: 영업손실 **7,730,313백만원(약 7.7조원)**, 전년 흑자에서 적자 전환,
**판가 하락**, **재고평가손실**, 하반기 **AI향 메모리 수요 급성장**, **공급 업체들의 감산**.
전년 영업이익은 6,809,417백만원이며 그 정확한 수치까지 답하는 것은 필수로 두지 않는다.
근거: `IV. 이사의 경영진단 및 분석의견 > 영업이익`과 `II. 사업의 내용 > 7. 기타 참고사항 > 영업개황`,
청크 `20240319000684:724:3`, `20240319000684:98:10`.
순손실을 영업손실로 바꾸거나 영업외 평가·파생상품손실을 영업적자 원인으로 치환하면 중대 오류다.
업황 개선을 연간 흑자나 근거 없는 분기 흑자로 확대하지 않는다.

**P04 — SK하이닉스 선택**

> SK하이닉스가 2023년 AI 메모리 수요에 어떻게 대응했는지 궁금합니다. 어떤 제품을 내세웠고, 관련 매출은 전년보다 얼마나 늘었나요?

근거: `II. 사업의 내용 > 7. 기타 참고사항 > 영업개황`, 청크 `20240319000684:98:10`.
배수를 뒤바꾸거나 이를 임의로 400%/500% 성장으로 바꾸지 않는다.
근거에 없는 고객사, 정확한 원화 매출, 수익성 개선을 덧붙이면 출처 충실도 실패로 기록한다.

**P05 — 두 보고서 모두 선택**

> 2023년 삼성전자와 SK하이닉스의 연구개발비 총액과 매출 대비 비중을 비교해주세요. 지출 규모가 큰 회사와 매출 대비 비중이 큰 회사가 같은가요?

필수 6개: 삼성전자 **28,352,769백만원 / 10.9%**, SK하이닉스 **4,188,404백만원 / 12.8%**,

근거: 두 보고서의 `II. 사업의 내용 > 6. 주요계약 및 연구개발활동`,

비중만으로 기술력·효율·수익성의 우열을 단정하지 않는다.

## 공통 판정과 종료 기준

26개 필수 항목을 각각 `정확하고 근거 있음 / 누락 / 오류 / 불명확`으로 기록한다.
원문 → 저장 청크 → 실제 최종 문맥 → 인용 근거를 구분한다. 알려진 청크 ID가 달라도
동일한 원문 사실을 올바르게 뒷받침하면 인정한다. 문자열 일치나 출처 ID 통과만으로 의미를 통과시키지 않는다.
표는 값뿐 아니라 주체·기간·연결 범위·행열·단위를 함께 확인한다.
명시한 단위의 올바른 변환과 표시 자릿수에 맞는 정상 반올림은 허용한다.

| 판정 | 기준 |
|---|---|
| 유용함 | 필수 항목 모두 정확하고, 중요한 추가 주장도 실제 인용 문맥으로 뒷받침되어 바로 쓸 수 있음 |
| 일부 도움 | 올바르고 유용한 부분은 있으나 항목 누락 또는 설명 문제가 있음. 중요한 허위·무근거 단정은 없어야 함 |
| 사용 불가 | 중요한 수치·기간·대상·관계 오류, 근거 없는 핵심 단정 또는 유용한 답변이 없음 |

안전한 답변 유보는 출처 충실도에는 문제가 없어도 이 업무에는 `사용 불가`일 수 있다.
정확도·필수 누락·출처 충실도·실행 오류를 별도 열로 남긴다. 추가 주장도 검사한다.
앱이 하지 않는 산술·의미·요청 누락 검증을 수행했다고 표시하지 않는다.

화면 확인은 보고서 선택, 답변별 당시 검색 범위, 출처를 찾아갈 수 있는지,
기록된 근거 생략·검색 저하 경고와 화면 표시가 일치하는지를 별도 기록한다.
자연적으로 발생하지 않은 경고 상황은 `NOT_EXERCISED`다. UI 확인 때문에 답변을 다시 생성하지 않는다.
저장 답변 화면 확인과 실시간 질문 제출도 구분한다. 실제 사용자 관찰이 없으면 사용자 만족·절약 시간은 `NOT_RUN`으로 둔다.

5개 결과와 실패 층을 한 번 정리하면 종료한다. 재질문·재실행·A/B·자동 수정·옛 평가 전체 실행을 하지 않는다.
특정 문항용 규칙을 추가하는 다음 작업으로 자동 연결하지 않는다.

## 예상 비용과 호출 상한

[공식 요금표](https://developers.openai.com/api/docs/pricing)를 2026-10-17 확인했다.
Standard, 272K 이하 입력 기준, 백만 토큰당 Terra 입력 **$2.00**, cache read **$0.20**,
cache write **$2.50**, 출력 **$12.00**, embedding 입력 **$0.13**이다.
cache write 부분에 일반 입력 요금을 중복 더하지 않는다.
[출력 토큰 한도](https://developers.openai.com/api/docs/guides/token-counting#understand-output-token-counts)는 reasoning 등 비가시 토큰도 포함한다.

- **예상 비용: 약 $0.11–$0.28.** 답변당 입력 8,000–15,000, 전체 출력 500–1,500토큰을 가정했다.
  실제 검색·생성 전의 계획 추정이며 측정치가 아니다. cache 할인은 기대하지 않는다. 세금·환율 제외.
- **정상 호출: 10회** — 질문 임베딩 5회 + 답변 생성 5회. 각 문항 1회이며 반복 비교가 아니다.
- **재시도 포함 HTTP 시도 상한: 20회** — embedding 최대 15회 + 생성 최대 5회.
  현재 `OpenAIEmbeddings`의 기본 재시도 2회를 바꾸지 않았다. 생성 재시도는 현재대로 0회다.
  논리적 `embedding_api_calls` 관측만으로 SDK 재시도를 셀 수 없으므로 실제 요청 경계에서 따로 센다.
- **비용 상한 제안: $1.40.** 답변당 입력 70,000토큰 예약, 출력 8,192토큰 최대,
  embedding 시도당 1,024토큰 예약을 적용하면 `0.875 + 0.49152 + 0.0019968 = $1.3685168`이다.
  질문은 각각 160–194 UTF-8 bytes이며 예약량보다 작다. 입력 비용에는 가장 높은 cache-write 단가를 썼다.
- 재수집·재임베딩·별도 모델 판정·가용성 확인·토큰 계수 API는 **0회**다.

실행 전 별도 평가 프로세스에 요청 계수·비용 예약을 적용한다. 이 문서는 그 실행 계약이며
유료 실행용 가드를 이번 준비에서 실행 검증한 것은 아니다. 실제 전송 요청의 schema 포함 직렬화 UTF-8 bytes에
1,024 여유분을 더한 보수적 입력 예약이 70,000을 넘으면 입력을 고치지 않고 중단한다.
이는 정확한 토크나이저나 공급자 청구액 보증이 아니다. 실제 응답 usage와 모델·tier를 함께 기록한다.
매 요청 직전에 비용과 호출 슬롯을 예약하고, timeout 등 비용 불명확 시 예약을 유지한다.
다음 예약이 상한을 넘거나 설정·해시·범위·응답 계약이 어긋나면 중단하고 나머지는 `NOT_RUN`으로 남긴다.
SDK 재시도 소진 뒤 별도 재시도·자동 재개는 없다. 실행 시점 요금이 인상되면 먼저 준비 조건을 다시 계산한다.
