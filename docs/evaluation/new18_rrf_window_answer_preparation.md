## HD와 U14의 사전 판정

**HD U04는 지정 원인의 실제 사용과 넓은 질문의 답변 판정을 분리한다.**12개 조건의11위 `20260316000940:1128:1`에는 중동·미주 매출 증가와 수익성 개선을2025 실적 변화에 연결하는 설명이 있다. 이를 의미상 정확하게 전달하고 실제 제공된 출처로 뒷받침했는지 조건별0/2·1/2·2/2로 기록한다. 정확한 문자열 일치를 강제하지 않는다.2026 전망을2025 원인으로 바꾸거나 추가 인과를 만들어내는지도 본다.

기존8개에 있는 `1126:0`의 다른 경영진단 설명을 답한 경우, 기존 기록처럼 지정 원인 누락과 넓은 질문에 대한U를 구별한다. 이를 새로F로 강화하거나 지정 원인P로 승격하지 않는다. 두 matched 반복 모두8개 non-P→12개P이면 **반복된 지정 원인 개선**, 한 번만 개선이면 부분 관측으로 보고한다. U04 전체 답변 성공은 정확도·누락·출처 충실도를 모두 별도로 확인해야 한다.

**U14의 필수 항목은 기존 부문 금액과 범위다.** 양쪽5위 `20260311004398:45:1`의 TR 영업손실53,107백만원과 호텔&레저 등이익60,854백만원을 정확히 연결해야 한다. 전사 손익표 `1019:1`을 이 부문 수치의 근거로 대체하지 않는다.

12개 조건의12위 `1017:0`은 두 부문 모두2025 영업이익이 개선됐다고 서술하지만, 부문 표의 호텔&레저 이익은64,522→60,854백만원으로 감소한다. 아래를 추가 진단으로 기록한다.

- 논쟁적인 개선 주장을 실제로 썼는지, 출처에 귀속했는지, 표와 불일치를 인지했는지

## 전체18문항의 회귀 확인

기존33필수 항목, 허용 대체 근거, 반올림 구간 규칙, optional 항목, 판정 보류 기록을 그대로 사용한다. 각 조건·회차의 정확도, 필수 항목 충족/누락, 출처 충실도, 인용의 실제 지원, U06·U12·U18의 한계 처리, 엄격 성공을 **P/F/U/NOT_RUN**으로 보고한다. 형식·출처 ID 통과를 의미·산술 검증으로 계산하지 않는다.

모든 문항·회차에서8→12의 **P→F와P→U를 구분**하고, F→P와U→P도 따로 기록한다. 총점 상승으로 개별 회귀를 상쇄하지 않는다. 문항별2/2·1/2·0/2 성공과 실제 두 판정, 회사별 결과, 필수 항목66관측/조건을 함께 제공한다. 오류·잘림·미실행도 예정 분모에 남긴다. 두 번의 반복은 일반화나 통계적 유의성의 근거가 아니다.

## 중단 규칙과 준비 검증

호출 직전에 최종 request·packet·slot 해시, 허용 endpoint, 호출 수, 누적 비용/미확정 예약액과 다음 최대 예약액을 확인한다. 전송 전에 attempted slot을 한 번 기록하며 실패한 요청도 호출 상한에 포함한다. 불명확한 timeout이나 usage 누락은 예약액을 돌려받은 것으로 처리하지 않는다.

HTTP/transport 오류,90초 timeout, incomplete/refusal, model·effort·tier 불일치, schema·출처ID 실패, usage 누락/불일치, source/request 변경, 비용·호출·시간 한도에 도달하면 중단한다. 나머지는 `NOT_RUN`이며 재시도·다른 모델·추가 근거·자동 재개로 채우지 않는다. 답변 품질이 낮다는 이유로 같은 조건을 추가 반복하지 않는다.

**준비 검증:** 기존8개 실제 요청18/18 일치,12개에서 원문4개만 추가18/18, 요청36개·슬롯72개·반복 해시·균형 순서·예산 산술을 확인했다. 소켓을 차단한 mock 리허설72건과25개 거절 대조를 통과했다. 기존 답변은 schema/출처ID fixture로만 사용했으며 새 생성·답변 평가 결과가 아니다. 별도 assistant가 요청과 비용을 재검증했다.

이 준비 산출물은 live runner가 아니다. 실제 실행 단계에서 전용 adapter를 연결하고, **실제 outgoing wire 경계에 같은 admission 검사를 적용한 뒤** 실행해야 한다. 임베딩 선행·문맥≤8·95회 상한을 가진 이전 실행기를 그대로 재사용하지 않는다. 현재 생성 성능·HD 개선·U14 영향·전체 회귀 결과는 모두 `NOT_RUN`이다.
