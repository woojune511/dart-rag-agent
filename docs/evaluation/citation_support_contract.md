# 날짜·단위 인용 지지 판정 기준

작성: 2026-09-30. 범위: 평가용 검토 기준 v1. 제품 실행 계약이나 자동 의미
검증기가 아니다. 이미 공개된 사례에서 정리했으므로 새 성능 증거로 사용하지
않으며, 과거 실험의 고정 채점·진입 기준을 소급 변경하지 않는다.

## 분리해서 기록할 항목

1. **사실 정확성**: 값·대상·범위·기간·단위가 원문과 맞는가.
2. **입력 근거 충분성**: 모델이 받은 자료에 요청 전체를 답할 근거가 있는가.
3. **인용 지지**: 실제 인용한 자료들의 합집합으로 해당 주장을 확인할 수 있는가.
4. **요구사항 충족**: 명시적으로 요청한 항목을 답했는가.
5. **보류 상태**: 부족한 근거를 설명하고 `abstained`도 이에 맞게 설정했는가.

정확한 답변도 인용이 부족할 수 있다. 입력에 근거가 있어도 인용하지 않았으면
인용 지지로 인정하지 않는다. 불완전한 입력에서의 적절한 보류는 숫자 선택
오류가 아니다. 일부만 답하면서 `abstained=false`인 문제도 별도로 기록한다.

## 주장과 근거를 연결하는 방법

검토자는 답변에서 실제로 한 주장의 원문 구간을 보존하고 대상·항목·범위·기간·
단위·값을 구분한다. 요청된 주장과 추가 설명의 주장을 나눈다. 답변하지 않은
항목에 의도를 추정해 넣지 않는다. 요구 항목의 누락은 `OMITTED`로 기록한다.

인용 지지는 다음 경로 중 하나로 확인한다.

| 경로 | 필요한 근거 |
|---|---|
|표 안의 명시|해당 셀/행/열과 연결되는 원문 헤더·단위·날짜 및 검토된 축 대응|
|표 밖 캡션|해당 표에 연결된 원문 캡션, 검증된 원문 위치·내용, 실제 인용 여부|
|독립 문장·표|동일한 사실의 대상·범위·값·기간·단위를 명시하는 인용 자료; 의미 대응 검토 기록|
|공통 문맥|여러 표에 적용된다고 명시된 범위 문장과 그 적용 대상의 근거; 단순 인접성으로 추정하지 않음|

표와 캡션이 별도 청크이면 수치와 날짜/단위 양쪽의 지지가 필요하다. 반드시
특정 캡션 ID만 인용해야 하는 것은 아니다. 동일 사실을 명시하는 독립 문장이
있다면 그 문장도 근거가 된다. 인용 목록의 모든 문서가 모든 주장을 각각
증명할 필요는 없지만, 전체 인용 집합이 중요한 주장들을 지지해야 한다.

다음은 그 자체로 충분한 연결 근거가 아니다.

- 같은 회사·소제목·보고서 연도, 같은 날짜 문자열, 가까운 청크 위치.
- 다른 주체를 설명하는 주석이나 이전 표에서 전파된 문맥 메타데이터.
- 평가자의 정답 지식, 인용하지 않은 입력 문서, 모델의 자신 있는 표현.
- 출처 ID가 존재한다는 검사나 표-캡션의 물리적 연결만으로 의미가 맞다는 추정.

원문 값 자체에 날짜/단위가 포함돼 있거나 `상품수`, `주식수`처럼 수량 종류가
명확한 표제에서 자연스럽게 읽히는 단위는 검토 후 인정할 수 있다. 반면 금액의
원/천원/백만원 배율, 통화, 비율의 %/%p 등은 관행이나 숫자의 크기로 채우지 않는다.
인용된 원문에서 단위가 불명확하면 판정 불가다. 환산이 요청됐다면 원문 단위와
계산 근거를 따로 기록하며, 문자열 일치로 환산의 정당성을 판정하지 않는다.

## 판정과 보수적 통과 기준

| 판정 | 의미 | 통과 처리 |
|---|---|---|
|`SUPPORTED`|인용된 근거에 검토된 주장 연결이 있음|해당 주장 인용 기준 통과|
|`UNSUPPORTED`|검토한 인용 집합에서 주장을 지지할 근거를 확보하지 못함|미통과; 사실이 거짓이라는 뜻은 아님|
|`UNDETERMINED`|후보 문맥은 있으나 적용 범위·축·단위의 의미 연결이 불명확함|미확인으로 남기며 통과 수에 포함하지 않음|
|`OMITTED`|요구한 주장 자체가 답변에 없음|요구사항 미충족; 인용 오류로 세지 않음|

원문과 명시적으로 충돌하는지는 별도 `contradiction` 항목에 기록한다.
지지 없음과 모순은 같지 않다. 올바르게 보류한 답변에 추가한 과거 수치도
그 날짜·대상과 함께 인용 지지를 검토한다. 입력 일부만 보고 문서 전체에
정보가 없다고 일반화한 주장도 별도의 범위 문제다.

엄격한 완전 답변 통과는 필수 항목의 정확성·충족과 중요한 명시 주장의 인용
지지를 함께 요구한다. 판정 불가를 틀린 값으로 집계하거나 분모에서 몰래
제외하지 않는다. 해석 민감도가 있으면 엄격 판정과 완화 해석을 나란히 보고한다.

## 검토 기록과 코드의 역할

검토 기록에는 질문/응답 ID, 원시 응답·입력 해시, 주장 원문 구간, 필수/추가
여부, 대상 표 ID, 실제 인용 ID, 근거 원문 구간, 연결 경로, 의미 대응 판단과
그 이유를 남긴다. 값과 단위가 여러 문서에 걸치면 각 근거를 따로 남긴다.

검증 코드는 파일/문자 구간/출처 ID/원문·캡션 연결/판정 조립의 일관성을
확인한다. 의미 대응 판단은 검토자의 입력이며 코드 성공이 그 판단의 독립
검증은 아니다. 인접성·동일 문자열만으로 의미 지지를 자동 승격하지 않는다.
이 기준은 새로운 LLM 판정 호출이나 답변 후 자동 인용 추가를 요구하지 않는다.

## 이번 적용의 경계

관련 검토와 합성 대조 사례를 사용한다. 기존 엄격 점수와 실험 종료 판정은
보존한다. 새 질문의 성능, 평가자 간 일치율, 자동 의미 검증 성능을 측정한
실험이 아니다. 향후 새로운 평가를 한다면 문항과 함께 이 기준도 실행 전에 고정한다.

[제품 계약](../architecture/agent_runtime_contract.md)의 기본 검증은 여전히
응답 형식·출처 ID·명시 검색 범위 검사이며, 의미 지지와 산술은 검증하지 않는다.
