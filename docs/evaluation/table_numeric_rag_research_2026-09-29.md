# 표·수치·정밀 문서 RAG 연구 조사

조사일: 2026-09-29. 논문 원문, ACL Anthology, arXiv의 현재 상태와 저자 저장소를
확인했다. 아래의 **연구 내용**과 **DART 적용 가설**은 구분한다. 연구를 재현하거나
새 평가·provider 호출·제품 변경을 수행한 문서가 아니다. 서로 다른 데이터셋의
정확도를 같은 순위표에 놓지 않는다.

## 프로젝트에서 출발하는 질문

[최근12문항 비교](semantic_selection_new_questions_result.md)는 두 경로 모두 근거가
충분했고, 고정 기준11/12 대11/12였다. 선택 경로 비용은4.17배였다. 반면
[기존 실패 중심 비교](fixed_pool_selection_result.md)에서는 근거 충분성이6/12에서
11/12로 높아졌다. 표본의 실패 구성부터 다르므로 LLM 선택 전체의 유효성에 대해
한 가지 결론으로 합치면 안 된다.

[원장 실험](agentic_ledger_chunk_refs_result.md)은 청크 참조가 정상 연결돼도
피연산자 산술 오류와 최종 설명 누락이 남는다는 점을 보여준다.
[Compiler 계약](../architecture/compiled_workflow_contract.md)에는 이미 의미 판단과
코드 실행의 분리, 원문 숫자·단위·연산 연결 검증이 있다. 따라서 프로그램 실행을
새로운 아이디어인 것처럼 재도입하거나, 논문을 이유로 전체 Compiler를 기본값으로
복구하는 것은 이 조사에서 도출되는 결론이 아니다.

## 우선 읽을 연구

### 1. FinQA / TAT-QA — 금융 수치 QA의 기본 분해

**연구 내용:** FinQA는 금융 전문가가 작성한 질문에 정답뿐 아니라 연산 프로그램을
주석으로 제공한다. TAT-QA의 TAGOP는 표의 셀과 본문의 span을 골라 기호 연산으로
답을 만든다. 둘 다 금융 표와 서술의 결합을 다루지만, 기본 과제는 관련 context가
주어진 QA에 가깝다. 대규모 corpus에서 근거를 찾는 RAG 성능과 동일시할 수 없다.
[FinQA, EMNLP2021](https://aclanthology.org/2021.emnlp-main.300/),
[TAT-QA, ACL2021](https://aclanthology.org/2021.acl-long.254/).

**DART 적용 가설:** 정답률을 피연산자 선택·연산 선택·산술 실행·최종 표현으로
나눠야 한다. 계산기만 붙여도 연도를 잘못 고른 숫자에 정확한 계산을 적용할 수
있다. 기존 Compiler에서 재사용할 부분은 검증 가능한 작은 실행기이며, 의미
정확도까지 보증한다고 주장하면 안 된다.

### 2. HiTab / MultiHiertt — 계층형 헤더와 여러 표의 결합

**연구 내용:** HiTab은 계층형 표의 질문응답과 문장 생성을 다루며, 저자 데이터는
상단·좌측 헤더를 트리로 표현한다. MultiHiertt는 여러 계층형 표와 긴 본문을
포함한 금융 문서, supporting facts, 연산 과정을 제공하며 검색한 사실 위에서
기호 추론을 수행한다.
[HiTab, ACL2022](https://aclanthology.org/2022.acl-long.78/),
[HiTab 저자 데이터 형식](https://github.com/microsoft/HiTab),
[MultiHiertt, ACL2022](https://aclanthology.org/2022.acl-long.454/).

**DART 적용 가설:** 숫자에는 전체 행·열 경로, 보고서 범위, 단위와 주석 연결이
필요하다. 예를 들어69.3이라는 값만으로는 가동률·당기·사업부문을 식별하지 못한다.
현재의 표 메타데이터를 모두 새로 만들자는 뜻이 아니다. 동일한 검색 근거에서
계층 경로가 답변 모델에 얼마나 명확히 노출되는지부터 측정할 가치가 있다.
회계기수→연도 대응은 원문 근거를 남겨야 하며, 임의 규칙으로 확정하면 안 된다.

### 3. TableRAG — 원문을 전부 읽히기 전에 표의 위치를 찾게 한다

**연구 내용:** 질문을 스키마용·셀 값용 query로 확장하고, 열 이름·자료형·예시와
고유한 열-값 쌍을 검색한다. 이후 프로그램을 사용하는 solver가 실제 표에 접근한다.
셀 검색에서 노출되지 않은 값도 올바른 열을 알면 solver가 원본 표에서 조회할 수
있다. 주요 평가에는 ArcadeQA, BirdQA와 합성 TabFact가 포함된다.
[TableRAG, 2024; 원문v3](https://arxiv.org/html/2410.04739v3).

**DART 적용 가설:** 이번 선택 비용의 큰 부분은 후보 원문을 모두 읽는 단계였다.
검색용 표 설명/헤더 인덱스와 답변용 원문을 분리하고, 선택한 위치의 실제 셀·헤더·
관련 주석을 다시 읽는 방식이 유망하다. 논문의 정형 테이블 접근을 공시의 병합
헤더·서술 주석에 그대로 적용할 수는 없다. 요약을 증거로 대체해서도 안 된다.

### 4. Chain-of-Table — Agent가 조작할 대상을 표 연산으로 제한

**연구 내용:** 모델이 행 선택, 열 선택, 열 추가, 그룹화, 정렬 등을 선택하고,
코드가 표를 변환한다. 갱신된 표를 다음 판단의 입력으로 사용한다. WikiTQ,
TabFact, FeTaQA에서 평가했으며, 금융 공시 RAG 전체를 검증한 연구는 아니다.
[Chain-of-Table, ICLR2024](https://arxiv.org/html/2401.04398v2),
[저자 코드](https://github.com/google-research/chain-of-table).

**DART 적용 가설:** Agent의 동작을 일반 검색과 자유로운 원장 작성에 한정하지 않고,
원문 표 조회·행/열 선택·제한된 계산 도구로 구성할 수 있다. 코드가 실제 조회값을
반환하고 모델은 그 결과를 해석하게 한다. 연산 목록·횟수·실행 권한을 제한하고,
단위·주석이 표 축소 과정에서 사라지지 않는지 확인해야 한다. 여러 Agent를 두는
것 자체는 이 아이디어의 필수 조건이 아니다.

### 5. FinLFQA — 정밀 답변은 인용·계산·개념을 따로 평가

**연구 내용:** 금융 장문 답변의 attribution을 supporting evidence, 중간 수치 계산,
전문 금융 지식으로 나눠 평가한다. 논문의 실험에서는 자기 피드백만 사용하는
반복 수정이 뚜렷한 개선을 주지 못했다. 실행 결과나 더 강한/도메인 특화 모델의
피드백은 일부 조건에서 도움이 됐다. 두 회사를 다루는 제한된 설정이다.
[FinLFQA, EMNLP2025 Findings](https://aclanthology.org/2025.findings-emnlp.908/),
[피드백 실험 원문 §5.3–5.4](https://arxiv.org/html/2510.06426v1).

**DART 적용 가설:** 원장의 sufficient=true나 유효한source_id를 정답 판정으로 쓰면
안 된다. 셀 연결과 단위 변환, 계산 실행 결과처럼 구체적인 검증 신호를 정의해야
한다. 외부 모델 피드백도 독립적인 진실의 보증은 아니다. 특히 설명 완전성은
질문의 명시 요구와 평가자가 추가한 기대사항을 분리해야 한다. 최근N12는 이
평가 경계가 실제 점수에 영향을 준 사례다.

### 6. T²-RAGBench — 검색과 읽기 실패를 분리하는 실제 RAG 평가

**연구 내용:** 정답 context가 주어지는 데이터셋을, 회사를 비롯한 조건을 질문에
명시하여 context를 먼저 찾아야 하는 평가로 바꾼다. EACL2026 최종판은23,088개
QA triple이다. 논문이 비교한 구성에서는 Hybrid BM25가 강했고, reranker나
요약이 항상 이득을 주지는 않았다. 요약으로 검색하되 답변에는 원문을 제공하는
SumContext도 비교한다.
[T²-RAGBench, EACL2026](https://aclanthology.org/2026.eacl-long.8/),
[최종 논문 Table3·§5.6](https://aclanthology.org/2026.eacl-long.8.pdf).

**DART 적용 가설:** 실제 검색 결과와 정답 근거를 제공한 조건을 분리하면 검색과
해석의 병목을 비교할 수 있다. 우리 새12문항은 실제 검색을 했지만 결과적으로
전부 충분했으므로 검색 개선을 검증하기에는 부족했다. 향후에는 검색 실패 가능성,
동일 지표의 여러 연도·범위, 근거 부족 사례를 사전에 층화하고 새 회사/보고서에서
평가할 필요가 있다. 정답 근거를 제공한 진단 결과는 제품 성능과 분리한다.

### 7. FinLongDocQA / FinLongDocAgent — 최신의 직접적인 금융 Agentic RAG 사례

**연구 내용:**2026년4월 preprint. 긴 연차보고서의 여러 표·본문에서 숫자를 모으는
과제와, 필요 항목 확장→검색→풀이→누락 항목 평가를 반복하는 방법을 제시한다.
보고서별 페이지 인덱스에서 최대5라운드·라운드당15개를 검색한다. GPT-4o-mini의
EM은 단회 top30에서19.07, Agent에서20.97이며, 단회 top75 비교는16.64다.
이는 저자 보고 결과이며 총 생성 호출·시간·비용까지 동일한 비교라는 뜻은 아니다.
[FinLongDocQA/Agent, arXiv2026](https://arxiv.org/html/2604.03664v1),
[저자 코드·데이터](https://github.com/AI-Application-and-Integration-Lab/FinLongDocQA).

**DART 적용 가설:** 표 간 계산에 필요한 누락 항목을 대상으로 추가 검색하는 것은
계속 검토할 만하다. 다만 필요한 근거를 이미 받은 질문까지 같은 루프를 적용할
이유는 별도로 입증해야 한다. 논문의 근거 부족 시0 출력 규칙은0이라는 실제
값과 혼동되므로 우리 경로에서는 도입하지 않는다. 정답 주석의 실행 가능한
프로그램과 운영 중 계산 실행의 보장도 구분한다. Multi-Agent 구성을 그대로
복제하기 전에 동일 도구·동일 비용에서 단일 Agent와 비교해야 한다.

## 이 프로젝트에 대한 우선순위 — 조사자의 제안

1. **데이터셋에 의미 축 주석을 추가하는 설계를 먼저 정한다.** 숫자의 source,
   행·열 경로, 기간, 연결/별도, 단위, 주석, 필요한 연산과 명시 요구사항을 구분한다.
   근거가 충분한데 틀린 경우를 연도/범위 선택과 산술/출력 누락으로 나눈다.
   정답과 질문이 불일치하는 사례도 모델 실패와 별도 집계한다.
2. **같은 검색 근거를 읽는 방식부터 한 축씩 비교한다.** 현재 청크와, 동일 원문에서
   헤더·단위·주석 연결을 보존한 표 view를 비교한다. 모델·호출 수·검색 결과를
   고정해 표현의 효과를 확인한다. 사람이 선택한 정답 셀 조건은 상한 진단으로만
   표시한다. 기존 전체 text/table ablation의 단순 반복과는 다른 질문이다.
3. **계산은 별도 실험으로 분리한다.** 동일한 피연산자와 연산을 두고 LLM 계산과
   제한된 코드 실행을 비교한다. 이후 모델이 고른 피연산자까지 연결한 end-to-end
   성능을 확인한다. 기존 실행기를 활용할 수 있지만 전체 Planner/Compiler 재도입은
   독립적인 결정이다.
4. **근거가 실제로 빠지는 복합 문항에서만 Agentic 검색을 검증한다.** 누락 피연산자,
   본문 속 예외 조건, 다른 표의 연결 항목을 평가 대상으로 삼는다. 여러 번 검색한
   비용과 단회 검색의 context를 맞춘 비교를 함께 남긴다. 근거 부족·상충과
   의미 해석의 불확실성을 분리하고, 단순 sufficient 플래그로 안전을 주장하지 않는다.

후보 도구 형태는 `find_tables` → `read_table` → `select_cells` → `calculate` 정도다.
도구가 원문의 값과 헤더·주석·stable ID를 반환하고, LLM이 선택의 의미를 판단하는
구조를 가정한다. 이는 **검증할 설계 가설**이며 새 API나 제품 변경은 아니다.
숫자를 따로 전사하는 모델 출력보다 실제 저장된 셀 참조를 실행에 연결하는 것이
실수의 관측과 재현에 유리할 것으로 본다. 참조가 맞아도 의미 선택이 틀릴 수 있다.

## 자료 선별에서 확인한 주의점

- [FinAgent-RAG, arXiv:2605.05409](https://arxiv.org/abs/2605.05409)는2026-07-05
  버전에서 실험 설계의 중대한 방법론 오류를 이유로 철회됐다. 검색 결과에 남은
  성능·비용 개선 수치를 채택 근거에서 제외했다.
- T²-RAGBench의 초기 arXiv 초록에는32,908개가 있으나 최종EACL2026 논문은
  23,088개다. 본 문서는 최종판을 기준으로 한다.
- FinTMMBench는 현재 arXiv 제목이 Towards Temporal-Aware Multi-Modal
  Retrieval Augmented Generation in Finance로 표시된다. benchmark 이름과
  초기 제목을 현 논문 제목과 구분했다.
- 공개 benchmark·기존 보고서는 모델 학습 오염이 없다고 단정할 수 없다.
  논문의 방식은 설계의 출발점이며 우리 한국어 DART 데이터에 대한 성능 증명은 아니다.

이번 작업은 문헌 조사 문서1개 작성으로 끝난다. 기존 실험 산출물, 기본 앱,
모델·프롬프트·계약과 프로젝트 완료 결정을 변경하지 않는다.
