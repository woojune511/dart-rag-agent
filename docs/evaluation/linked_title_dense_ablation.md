# 표제·기간 보존 Dense 실험: 안정성 검사에서 중단

2026-10-15 · `STOPPED_STABILITY_GATE_FAILED_REVIEWED`

**C10의 표제 편중 개선과 기존12문항의 회귀 비교는 미실행이다.** 실제 호출은 변경하지 않은 문서12개의 재임베딩1회에서 중단됐다. 같은 입력의 벡터4개에 작은 차이가 있었고, 그중3개가 실행 전에 고정한 허용 오차를 넘었다. 변경 대상723개는 호출하지 않았다. 이 결과를 Dense 표제·기간 보존의 성공이나 실패로 해석할 수 없다.

## 비교하려던 조건

기준은 [직전 `까지` 제외 대조](linked_title_until_control.md)의 B조건이다. 원본 연결이 검증된 표제·기간을 BM25에 보존하고, 문서·질문에서 정확히 `까지`인 토큰만 제외한 상태다.

- 기존723개 연결과 추가 텍스트를 그대로 Dense 문서 입력에도 사용한다. 새 연결·키워드 제거·원문 편집은 없다.
- 변경하지 않은1,517개 문서 벡터와12개 질문 벡터를 재사용한다. 모델은 같은 `text-embedding-3-large`,3072차원이다.
- BM25 입력·tokenizer·후보24개·점수·`k1=1.5,b=0.75,epsilon=0.25`,접수번호 필터,Dense16,RRF60/동일 가중치/top8을 고정한다.
- 답변 입력은 원래 canonical 출처 텍스트·metadata와65,536-byte 제한을 유지한다. Dense 입력의 `까지`를 지우지 않는다.
- 답변 생성·제품 적용·기존 앱 store 변경은 범위 밖이다.

원본2개 보고서의 파싱 결과2,240개가 기존 corpus와 정확히 일치했다. 기존 연결 규칙의 원본 XML 표제 문법과 값 레코드0 조건으로358개 표제·기간 청크의 목록을 질문과 무관하게 고정했다. 이 목록은 비중 측정용이며 검색 제외 규칙으로 사용하지 않았다. C10 기준값은 Dense16 중9개, 최종8개 중4개다.

## 사전 재현에서 확인한 인덱스 재생성 영향

같은 벡터로 새 실험용 Chroma를 만들었을 때 C11의 Dense16 후보2개가 달라졌다. 기존 후보 `125:20`,`905:9`가 빠지고 `904:8`,`895:1`이 들어왔다. 그 결과 최종8개의 출처 집합은 같지만5·6위의 순서가 바뀌었다. 나머지11문항의 실제 packet은 동일했다.

저장된 기존 Dense16은12문항 모두 전체 scoped L2 거리의 정확한 상위16과 일치했다. 따라서 유료 호출 **전** 최종 프로토콜을 다음처럼 고정했다.

1. 주 대조는 양쪽 모두 동일한 scoped squared-L2/top16을 사용한다. 기존192개 후보의 ID·순서는 정확히 재현된다.
2. 새로운 Chroma 결과는 별도 확인해 ANN 인덱스 재생성의 차이를 함께 보고한다. 인덱스 설정은 조정하지 않는다.

사전 실패 코드·입력·실험용 인덱스는 `preflight_v1/`, 차이는 `preflight_native_discrepancy.json`에 보존했다. 실제 제품의 기존 인덱스 오류를 확인한 것은 아니다. 이 대조에서 C11 필수 출처 `70:2`,`71:3`은 유지됐지만, 이는 표제 보존 Dense 실험의 회귀 결과가 아니다.

## 실제 재임베딩의 중단 원인

질문을 사용하지 않고, 보고서별 변경되지 않은 문서 목록에서 등간격6개씩12개를 선택했다. 이 문서들을 먼저 재임베딩한 뒤 기존 벡터와 비교하도록 고정했다. 조건은 cosine≥0.9999 **및** 최대 성분 절대차≤0.001이다. 실패하면723개 변경 입력에 대한 호출 전에 종료하며, 재시도·이어하기·허용 오차 완화는 없다.

| 문서 UID 끝부분 | cosine | 최대 성분 절대차 | 고정 검사 |
| --- | ---: | ---: | --- |
| 농심 `0:0` | 0.999801759 | 0.001569748 | 실패 |
| 농심 `736:200` | 0.999916082 | 0.001144409 | 실패 |
| 코웨이 `483:1` | 0.999775433 | 0.001493454 | 실패 |

전체12개 중8개는 float32 벡터가 완전히 같고,4개가 달랐다. 차이가 있는 나머지1개는 허용 오차 이내다. 이 임계값은 이번 실험의 보수적인 진행 기준이며, 임베딩 품질이나 검색 실패를 판정하는 검증된 일반 기준은 아니다.

기존 요청·압축 원응답, 새 요청·원응답, 저장된 벡터를 대조했다. **12/12개 모두 개별 문서 입력·모델·차원·출력 형식과 인덱스 매핑이 일치했다.** 저장된 이전 벡터도 이전 원응답과 정확히 같았다. 입력 변환·응답 순서·벡터 저장 버그로 설명되지 않았다. 이전 요청은64개 배치, 이번 안정성 검사는12개 배치였으므로 배치 구성은 다르다. 동일한 모델 이름에서 관측된 출력 변동이며, 모델 버전 변경이나 특정 내부 원인을 확정하지 않는다.

추가 호출 없이 새로 받은12개만 메모리에서 교체한 진단에서는12문항 모두 정확 검색 상위16의 ID·순서가 유지됐다. **관측된 작은 차이가 이 표본의 검색 순위를 망가뜨렸다는 증거는 없다.** 다만723개 변경 벡터의 변동까지 검증한 것은 아니며, 중단 기준을 사후에 낮추지 않았다.

## 다음 대조의 구체적인 형태 — 실행하지 않음

저장된 기준 벡터와 새 처리 벡터를 비교하는 대신, 변경 대상723개에 대해 **원래 입력 A와 표제·기간 입력 B를 같은 시점에 둘 다 임베딩**하는 대조가 필요하다. A/A와 B/B의 재호출 변동도 보기 위해 A/B를2회 실행하는 설계를 준비했다. BM25·RRF·나머지1,517개 문서·질문 벡터는 양쪽에서 동일하게 유지한다.
