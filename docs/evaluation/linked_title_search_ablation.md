# 원문 표제·기간의 BM25 검색 입력 보존 실험

2026-10-15 · `COMPLETE_REVIEWED_OFFLINE` · provider-free

**C10 본표의 BM25 순위는3→1위, 최종 RRF 순위는8→4위로 개선됐다. 기존12문항의 필수 근거 충분성은11/12→12/12이며, 근거 회귀는0건이다.** N03의 필요 근거가 새로 top8에 들어왔다. 답변 생성과 Dense 재임베딩은 실행하지 않았으므로 이 수치는 답변 정확도가 아니다.

이번 결과는 검색 표현을 바꿀 근거가 생겼다는 제한된 관찰이다. N03 회복은 해당 표의 문맥 보완이 아니라 전체 BM25 통계 변화에서 나왔고, C10 점수 증가에는 문맥상 다른 의미의 `까지` 토큰 일치도 크게 기여했다. 제품 기본값은 변경하지 않았다.

## 단일 변경과 고정 조건

[원본·순위 진단](header_chunk_origin_audit.md)에서 확인한 표제와 값 표의 물리적 연결을 검색 입력에 보존했다. **기준은 공통 키워드 줄을 유지한 원래 canonical 검색**이다. 회귀가 있었던 [키워드 제거 조건](keyword_prefix_bm25_ablation.md)을 겹쳐 적용하지 않았다.

변경은 다음 한 가지다.

```text
변형 BM25 입력 = 검증된 앞 표의 source_context.source_text + "\n" + 원래 색인 텍스트
```

원문 fragment를 공백·줄바꿈과 함께 한 번 복사했다. 인접 단위 표시도 원문의 일부로 보존했다. `COLSPAN`을 펼쳐 제목을 반복하거나 새로운 키워드를 합성하지 않았다. 원래 표제 청크는 그대로 남겨 두었다.

실행 전에 다음의 질문 독립 규칙을 고정해 두 보고서의2,240청크 전체에 적용했다.

- 값 레코드가 있는 유일한 `table_view=full` 청크이고, 원본 TABLE 전체와 본문이 일치해야 한다. 뒤 문단이 합쳐지거나 분할된 표는 제외한다.
- 앞 표와 값 표가 같은 `TABLE-GROUP`의 바로 이웃 TABLE이고, 사이에 유의미한 텍스트가 없어야 한다.
- 앞 표는 기존 파서의 기간 문맥 문법에 맞거나, 2행·2~3열에서 첫 행의 한 병합 셀에 제목이 있고 다음 행이 기존 기간 문법에 맞아야 한다. 제목 길이는1~120자이며 새 재무 용어 목록은 없다. 숫자 셀이 없다는 조건만으로 임의의 표를 채택하지 않는다.
- 저장된 `preceding_block` 문맥의 문서 SHA256·양쪽 XPath·부모·전체 문자 구간·텍스트가 실제 원본과 일치해야 한다. 원본 byte 구간을 별도로 추출해 양쪽 표와 공백뿐인 사이 구간까지 확인한다.

농심335개, 코웨이388개, 총**723개 값 청크**의 검색 입력만 달라졌다. 기존 기간 문법367개, 병합 제목+기간 행356개다. 추가량46,116 UTF-8 bytes. 나머지1,517개는 그대로다. 제외 사유는 전체 표 아님343, 값 없음913, 혼합 본문123, 직접 형제 관계 아님59, 표제·기간 규칙 불일치79개다. 이는 의미적 가치의 평가가 아니라 이번 표현 변형의 적용 범위다.

질문·접수번호 필터·corpus 순서·모든 청크 ID/metadata/본문·공통 키워드 접두어·저장된 Dense16·BM2524·RRF 상수60/동일 가중치·top8을 고정했다. BM25 설정은 `k1=1.5,b=0.75,epsilon=0.25` 그대로이며, 입력 변경으로 IDF와 평균 길이는 재계산된다. 평균 토큰 길이는324.0214→326.7281이다.

BM25 반환 직후 원래 canonical 문서를 복원한 뒤 실제 RRF와 `SimpleRagAgent` 입력 경로를 사용했다. 따라서 **검색에 추가한 문맥을 답변 입력에 추가하는 실험은 아니다.** 선택된 출처의 원문·metadata와65,536-byte 제한은 그대로이며, 두 조건의24개 packet 모두 누락0이다.

**근거 회복1건(N03), 기존 충분 문항의 근거 회귀0건.** C10은 이미 충분했던 문항의 순위 개선이다. 출처 집합은10/12문항에서 같고, 순서까지 같은 packet은9/12개다. N02는 일부 보조 출처의 순서만 달라졌다. 총96개 top8 자리 중94개 출처가 유지됐다. 원문·단위·범위와 기존 인용 구간을 대조했으며, 단순히 최초 지정 gold ID의 포함 여부만으로 판정하지 않았다.

### C10: 필요 본표가 올라갔지만 표제 우위는 남음

| 출처 | 내용 | BM25: 원래→변형 | RRF: 원래→변형 |
| --- | --- | ---: | ---: |
| `104:5` | 요청한 연결 현금흐름표 | **3→1** | **8→4** |
| `486:4` | 별도 현금흐름표 | 4→2 | 10→6 |
| `400:295` | 연결 영업활동현금흐름 표제만 | 6→6 | 1→1 |
| `748:261` | 별도 영업활동현금흐름 표제만 | 7→7 | 2→2 |
| `395:290` | 연결 주당이익 표제만 | 132→140 | 3→3 |
| `401:296` | 연결 현금흐름 조정 상세값 | 762→109 | 후보 없음→후보 없음 |
| `749:262` | 별도 현금흐름 조정 상세값 | 892→120 | 후보 없음→후보 없음 |

`104:5`에는 원본에서 연결된 `연결 현금흐름표`, 2025/2024/2023 기간, 원 단위가 검색 입력에 들어갔다. 요청한 **35,544,145,039원과617,510,076,654원**은 기존과 동일한 원문으로 최종4위에 남는다. 별도 본표가 들어오면서 회계기준 개정 설명 `501:14`가 빠졌다. 새 별도 표의19,961,564,073원·399,059,004,756원은 대체 정답 근거로 인정하지 않았다.

동시에 Dense를 고정했으므로 두 검색 채널에 함께 등장하는 표제2개는 RRF1·2위를 유지한다. 주당이익 표제도3위다. **이번 변경은 표제 청크 우위나 연결/별도 혼동 가능성을 해결하지 않았다.** 인접 상세표 `401:296`은 표제·당기를 얻어도 BM25109위로, 후보 상한24 밖이다. 이 상세표 자체에는 C10의 요청 피연산자가 없다는 이전 진단도 그대로다.

점수 상승을 “의미적으로 올바른 제목의 효과”로만 해석할 수 없다. `104:5`의 점수는65.063199→71.990511로6.927312 증가했다. 두 관측 조건의 BM25 수식을 토큰별로 재구성하면:

- `까지`의 기여 증가가 **+3.630746**으로 순증의52.4%다. 원문 날짜의 `2025.12.31 까지` 등3회와 질문의 `소수 둘째 자리까지`가 어휘상 겹친 결과이며, 의미는 다르다.
- `름표`는0→1회로 **+2.488230** 증가해 제목 보존의 직접 일치를 보여준다. `2025`와 `원`도 기여한다.
- 다른 토큰은 길이·IDF 변화에 따라 증가하거나 감소한다. 이 분해는 관측 점수의 합계 확인이지, 각 토큰을 제거한 별도 실험이나 인과 기여율 추정이 아니다.

### N03: 직접 문맥 보완이 아닌 corpus 통계 효과

`998:2`의 매출액3,514,316/3,438,731백만원과 영업이익183,933백만원, 연결 제목·기간 열·단위가 최종8위로 회복됐다. 기존에 확인한 원본 XML 및 충분 근거 조건의 인용 구간과 일치한다. 그러나 이 청크는 표 뒤 설명문이 합쳐진 본문이라 이번 규칙에서 제외됐고, **검색 입력은 전혀 바뀌지 않았다.**

경쟁하던 표제 `802:266`도 입력이 그대로다. 두 문서의 토큰 빈도와 길이가 동일한 상태에서 corpus IDF·평균 길이가 변해 순위가 뒤집혔다. `998:2`는55.569841→55.682102, `802:266`은55.680348→55.333877이다. 후자의 `계산` 토큰 기여가 약0.406864 감소한 것이 주요 요인이다. 따라서 N03 회복을 “그 표의 원문 제목을 되살린 효과”로 설명하면 잘못이다. 새 순위도 top8의 마지막 자리여서 안정성·독립 표본 이득은 아직 검증하지 않았다.

## 검증과 적용 판단

- 동결 SHA256: `174dc10bb49764fb32ee7300ad54adfa6f4fba1f2c3b03ebe3defeb015da4d0e`. 규칙·실행 코드·프로토콜·테스트·의존성을 결과 전에 고정하고 변형1개만 실행했다.
- 두 원본을 재파싱해 canonical 투영2,240/2,240 일치, fallback0을 확인했다. 새 ingest나 앱 store 변경은 없다.723연결의 원본 표1,446개 byte witness와 전체 문맥을 별도로 재검증했다.
- 원래 Dense/BM25 후보·순서·점수·RRF top8·실제 packet을12/12 재현한 뒤 비교했다. 변형에서도 저장된 Dense192개 후보와 원래 출처 텍스트를 보존하고 독립 RRF 계산을 대조했다.
- 범용 fixture7개가 네트워크 차단 상태에서 통과했다. 잘못된 위치·문서 해시, 문맥 잘림, 중간 텍스트·다른 부모, 분할/혼합/값 없는 표 등을 거절한다. 문서 계약2개와 `git diff --check`도 통과했다.
- 기존 보호 파일763개는 변경 없이 검증했다. 최신 상태 문서2개만 갱신하며 그 이전 bytes를 별도 보존했다. 과거 실행·검토 결과와 사용자 문서는 그대로다.
- provider/embedding/답변 호출0, 추가 비용0. C09의 과거 계산 절차 `UNDETERMINED`와 C11의 과거 추가 해석 오류를 개선했다고 주장하지 않는다.

**이번12문항에서 C10 순위 개선과 필수 근거 무회귀 조건을 충족했다.** 다만 노출된 양성12문항·두 보고서의 assistant 비맹검 검토이며, 실제11개 보고서 store와 IDF가 다르다. Dense 표현, 모델 정확도, 거절 성능, 새 보고서 일반화는 `NOT_RUN`이다. 기존 키워드 제거 실패를 취소하거나 두 변형의 결합 효과를 주장하지 않는다.

실험은 여기서 종료하고 제품 기본값은 유지한다. 독립 표본에서 효과가 유지되는지 확인할 후보로 남기되, 결과에 맞춘 stopword·가중치·topK 조정이나 자동 후속 실행은 하지 않았다.
