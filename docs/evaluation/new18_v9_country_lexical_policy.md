# v9 국가·소재지 BM25 선택 정책 비교

상태: COMPLETE_OFFLINE_SOURCE_COMPARISON — 2026-10-17

명시적으로 선택하는 BM25 어휘 보완 정책을 최소 구현했다. 저장된 v9 Dense 후보와 RRF를 유지한 최종 12개 비교에서 U08의 법인–국가 연결표와 당기 중국 지역매출 표가 복구됐다. 새 18문항의 필수 근거는 **28/33 → 29/33**, 근거 회귀는 **0**이다. 답변 생성·정확도·출처 충실도 평가는 **NOT_RUN**이다.

## 구현과 활성화 경계

- 선언적 어휘: `src/config/retrieval_policy.py`의 `country_location_v1`.
- 일반 적용기: `src/storage/lexical_query.py`. 회사명·국가명·문항 ID·정답 수치에 따른 분기는 없다.
- 호출자가 `VectorStoreManager(experimental_lexical_policy_id="country_location_v1", ...)`를 명시할 때만 적용한다. 기본값은 `None`이며 API·Streamlit·환경변수에 자동 연결하지 않았다.
- 독립된 `나라/국가` 및 정책에 열거한 조사 형태에만 반응한다. `나라에서`, `나라별`, `국가별로` 등은 포함하고 `나라면`, `나라장터`, `국가채무` 같은 부분 문자열은 제외한다. `해외`, `어디`만 있는 질문은 보완하지 않는다.
- 맞는 규칙이 있으면 원래 질문에 없는 `국가 소재지`를 한 번씩만 덧붙인다. 기존 질문·어휘를 삭제하거나 반복 가중하지 않는다.
- 보완한 문자열은 BM25에만 전달한다. Dense·답변 질문·명시적 보고서 필터·문서 본문은 유지한다.
- 검색 trace에 원래 `query`, `bm25_query`, 정책 ID·맞은 규칙·추가 어휘를 남긴다. 기존 기본 캐시 키는 유지하고, 선택 정책에는 버전 ID와 실제 BM25 질문을 추가해 캐시를 분리한다. 캐시 적중 때도 동일한 정책 trace를 제공한다. 알 수 없는 정책은 store/provider 초기화 전에 거절한다.

이는 **질문과 원문 필드 사이의 어휘 보완**이다. 소재지를 고객의 매출 발생 국가로 판정하거나 법인명을 자동 연결하는 기능이 아니다. 정책의 어휘·반응 조건 변경에는 새 버전 ID가 필요하다.

## 고정한 비교 조건

실행 전에 `protocol.json`을 고정했다. 이전 [후보 원인 분석](new18_v9_u08_candidate_diagnosis.md)에서 검토한 `국가 소재지` 한 조건만 적용했고, 결과를 본 뒤 규칙·가중치를 조정하지 않았다.

| 항목 | 고정 조건 |
|---|---|
| 문항·보고서 | 새 18문항, 질문과 caller scope 동일 |
| 자료 | 저장된 v9 3,645청크의 본문·접두어·메타데이터·순서 |
| Dense | 각 질문의 저장된 16개 문서·점수·순서 그대로 |
| BM25 | 동일 전체 코퍼스로 메모리에서 재구성, 기존 tokenizer, k1=1.5/b=0.75/epsilon=0.25, 필터 적용 후 최대 24개 |
| 유일한 비교 변수 | 정책 off / `country_location_v1` on |
| RRF | 기존 코드, 상수 60, 양쪽 가중치 1, Dense 우선 동점 순서 |
| 최종 문맥 | 양쪽 12개, 전체 문서 단위 65,536바이트 상한 |
| 판정 | 기존 33개 필수 근거 기준과 원문 witness 유지 |
| 호출·변경 | 외부 API·임베딩·생성·judge 0회, $0, store 재구축·활성화 없음 |

실제 `VectorStoreManager.search(k=8)`를 저장된 Dense 반환 어댑터와 메모리 BM25로 실행해 기존 Dense16/BM25-24를 고정했다. 병합 직전 입력을 잡아 **동일 RRF 함수의 반환 길이만 12개로 투영**했다. `search(k=12)`로 후보까지 24/36개로 늘리지 않았다. 앱의 기본 top8을 변경한 실험은 아니다.

기존 arm의 BM25 후보·점수·메타데이터·전체 RRF 순서와 점수·top12 패킷이 **18/18 정확히 일치**한다. 두 arm의 Dense 후보도 모두 정확히 같다. 저장 sidecar에는 저장용 `table_payload_id`가 추가돼 있으므로, 재현에는 저장 당시 full-chunk 메타데이터를 사용했다. 기존 payload loader로 읽은 3,645개 메타데이터가 해당 저장 포인터를 제외하고 동일함을 확인했다. 재현 어댑터의 초기 포인터/loader 정합성 오류를 수정한 것이며 검색 정책이나 판정 기준을 바꾼 것은 아니다.

## U08 근거 복구

질문은 `한국 말고 어느 나라에서 매출을 많이 내고 있어? 나라별 규모도 알려줘.`이며, BM25 입력만 끝에 ` 국가 소재지`를 붙였다.

| 근거 청크의 끝 ID | 기존 최종 12개 | 정책 적용 BM25 / RRF 순위 | 확인한 의미 |
|---|---|---|---|
| `159:35` | 없음 | 1 / 2 | 연결 부문수익은 수익이 창출되는 지역별 위치 기준 |
| `161:37` | 없음 | 3 / 6 | **당기** 중국 수익 1,316,352,022천원, 기타 국가 919,408,932천원 |
| `593:61` | 없음 | 5 / 10 | Orion Food VINA → 베트남, Orion International Euro LLC → 러시아 |
| `78:2` | 있음 | Dense 4 / RRF 7 | Vina 당기 법인 매출 538,097백만원 |
| `82:6` | 있음 | Dense 3 / RRF 5 | Euro LLC 당기 법인 매출 339,436백만원 |

원문 `original:563–565`의 지역 기준·당기·천원·열 순서와 `original:1729`의 법인명–소재지 행을 확인했다. 법인 매출은 `original:173–174`의 백만원·2025 당기 열·에누리 차감 후 합계이며 **수출을 포함한다**. 따라서 중국 지역매출과 베트남/러시아 법인 매출을 제시한다면 서로 다른 집계 기준을 명시해야 한다. 소재지 표의 68,498,978/31,980,151천원은 투자 장부금액이며 매출이 아니다.

전체 12개 중 5개가 교체됐다. 기존 회계정책·판매경로 등 대신 지역별 기준·당기 값·전기 값·법인 소재지·본사 개요가 들어왔다. U08.2의 기존 근거 `78:2/79:3/82:6`은 본문과 메타데이터가 그대로 보존됐다.

새 `162:38`은 **전기** 중국 매출 1,265,157,571천원을 포함한다. 당기 표와 함께 전달되므로 기간 혼동 가능성은 남는다. `593:61` 앞부분의 인도 가치평가 문맥과 다른 투자 장부금액도 남아 있다. 실제 생성에서 이러한 문맥을 올바르게 해석하는지는 이번 비교로 확인하지 않았다.

## 검증·보존·남은 한계

- 신규 정책 테스트 8개 통과: 기본 off, 선택 조건/부분 문자열, 중복 방지, unknown policy 조기 거절, Dense 입력/필터/RRF 고정, 캐시·trace 분리.
- 정책·저장소 fallback·source scope·scope isolation 관련 테스트 **56개 통과**. 목 처리한 backend의 오류 로그는 외부 API 실패가 아니다.
- 문서 권위·길이 검사 2개, runtime domain-language audit, `git diff --check` 통과.
- 원문 파일과 **98개 근거 구간 해시**를 확인했다. 기존 33개 판정 기준과 원문 참조를 유지하고, 법인–국가 연결은 별도 보강 witness로 기록했다.
- 기존 store 6개/56파일 및 `.env`는 전후 해시·파일 목록으로 보존을 확인한다. 기존 실험 결과·관련 없는 parser 수정·Git HEAD/index도 유지한다. 최종 검증 결과는 `closeout.json`이 권위다.
- 이번 결과는 개발 과정에 노출된 질문의 오프라인 검색 근거 개선이다. 새로운 모델 답변의 정확도·필수 항목 누락·출처 충실도 개선을 주장하지 않는다.
- 국가 표현의 변형·간접 질문·부정 표현을 의미적으로 처리하지 않는다. default 활성화나 prompt 변경, 추가 호출 실험은 수행하지 않았다.
