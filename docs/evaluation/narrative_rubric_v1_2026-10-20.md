원 질문·gold·기존 답변·점수를 보존했다. 문항 ID는 원문을 가리키는 참조이고, 별도 rubric entry ID를 사용한다. 질문을 고치거나 보류를 해제하는 후속 데이터셋은 새 ID와 `supersedes`를 사용해야 한다.

기계 판독용 정의: [narrative_requirements_v1.json](../../benchmarks/rubrics/narrative_requirements_v1.json). 이 JSON은 runtime이나 evaluator에 자동 연결되지 않는다.

JSON의 `inputs` 해시는 실험 당시 로컬 원본에 대한 기록이다. 공개 문서에는 안내와
링크 정리가 추가되어 그 문서 파일 자체의 현재 해시와는 다를 수 있다. 정의 JSON은
원본 그대로이며, `MIX_T3_023` 제목의 회사명 오기는 아래 표시에서 현대자동차로
바로잡았다. 원 질문·필수 조건·점수·동결 JSON은 변경하지 않았다.

## 완전 정답의 뜻

**필수 요구 모두 충족 + 내용 정확 + 필수·추가 주장 모두 인용 근거로 지지**되어야 완전 정답이다. 선택 항목을 생략해도 감점하지 않는다. 선택 항목을 답변에 넣었다면 그 주장도 검증한다.

| 구분 | 적용 원칙 |
|---|---|
| 질문 요구·범위 | 명시된 수치·설명·대상·기간 및 이를 정확히 해석하기 위한 조건. |
| 요약 최소 기준 제안 | '주요 요인/사례'처럼 열린 요청의 최소 범위를 제안했다. 1개·2개라는 수는 원 질문에 없는 평가 선택이며 실행 전에 검토·고정해야 한다. |
| 선택 | 생략해도 완전성에 영향 없음. 추가한 사실은 정확성·근거 지지 평가 대상. |
| `any_of` | '또는/나'는 하나의 경로를 완결하면 충족. 서로 다른 경로의 값·범위를 섞지 않음. |
| `at_least` | 서로 다른 요인·사례를 센다. 같은 사실의 표현만 바꿔 중복 계산하지 않음. |
| 보류·해석 미확정 | 문항 전체는 `UNDETERMINED`. 판단 가능한 개별 주장 지지는 별도로 기록. |

단어가 일치할 필요는 없다. 같은 의미를 정확히 설명하고 원문이 지지하면 인정한다. 아래 숫자는 검산 기준이며 질문이 요구하지 않는 중간 계산·피연산자까지 답변에 전부 쓰도록 강제하지 않는다. 표시 정밀도에 맞는 반올림·단위 변환을 허용한다.

검색 근거 부족을 정직하게 표시한 답변도 요청을 빠뜨렸다면 완전 정답은 아니다. 이때 **요청 누락**과 **허위 주장**을 구별한다. 검색 packet의 부재는 전체 보고서의 부재를 증명하지 않는다. 공시 범위 자체를 설명하는 요구에서는 확인된 공시 한계가 답일 수 있지만, 검색 실패만으로 이 예외를 적용하지 않는다.

평가자는 문항별 R 항목에 답변 구절·인용 원문·표의 주체/열/단위를 함께 기록한다. 입력 근거 충분성, 정확성, 완전성, 필수 주장 지지, 추가 주장 지지, 실행 상태를 각각 남긴다. 출처 ID 유효성 검사만으로 의미적 근거 지지 PASS라고 하지 않는다. JSON에 비어 있는 평가 기록 템플릿을 포함했다.
