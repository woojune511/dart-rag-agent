# 문단·표 원문을 보존하는 후보 표현 점검

Date: 2026-09-29. Status: **COMPLETE_OFFLINE_NO_GO**.

후속 표현 `lossless_structural_catalog_v2`를 구현하고 유료 호출 없이 점검했다.
모든 원문·context·후보 ID·순서를 보존했지만, 별도 12문항의 로컬 요청 토큰은
**7.7%**만 감소했다. 기존의 50% 절감 기준에 못 미쳐 유료 비교로 진행하지 않는다.
이는 **구조화와 정확한 중복 제거만으로 얻은 절감량**이며, LLM 선택 정확도나
실제 비용·시간 개선을 평가한 결과가 아니다.

## 구현과 범위

[앞선 발췌 실험](compact_selection_feasibility.md)은 토큰을 54.8% 줄였으나
대표 후보에서 항목·기간·단위 단서를 잃었다. 이번에는 발췌량 조절 대신
본문 전체를 보존하는 별도 변환을 고정했다. 제품의 `SimpleRagAgent`와 공개 API는
변경하지 않았다. 코드는 로컬 실험 디렉터리에만 있다.

1. 선두의 기존 대괄호 메타데이터를 줄 단위로 통째로 보존한다. 기간·단위를
   새로 추론하거나 기존 표시를 수정하지 않는다.
2. 본문은 빈 줄과 `|` 포함 여부의 전환으로 묶는다. 표 형태 줄 묶음의 모든
   헤더·값·주석을 보존하며, 불분명한 flat 본문은 길어도 그대로 둔다.
3. 요청 안에서 **종류와 내용이 정확히 같은 묶음**만 공통 목록에 한 번 저장한다.
   동일한 context 필드·값도 공유하며, 각 출처에 소유 context와 순서 있는 원문
   참조를 유지한다. 중복 출현 횟수도 보존한다.
4. 선택 결과는 원래 출처 ID를 사용하도록 가상 입력에 명시한다. 실제 답변에
   전체 원문을 다시 전달하는 재구성 계약만 검사했으며 선택·답변 호출은 없다.

이 분할은 관측 가능한 텍스트 경계다. PDF/XML의 물리적 문단·병합 셀 복원이나
다단 헤더의 의미 연결을 검증한 것은 아니다. `|`가 있는 일반 문장도 해당 묶음이
될 수 있다. 내용이 사라지지는 않지만, LLM이 공통 목록의 참조를 정확히 따라갈지는
검증하지 않았다. 기존 prompt 바깥의 문서 표현/schema가 바뀐 가상 요청이며
provider 실행 packet으로 승인된 것이 아니다.

## 표본 고정과 측정

- 개발 확인: 앞선 고정 후보 비교의 6문항 × flat/table, 12개 입력 전부.
- 별도 평가: 저장된 `semantic_selection_new_questions_2026-09-29`의
  N01–N12 선택 요청 전부. 해당 실험에서 이미 허용한 후보 window를 그대로 사용했다.
  이번에 후보를 추가·제거하거나 새 검색을 하지 않았다.
- 규칙·대상·50% 절감 기준을 평가 요청의 측정 전에 해시로 고정했다. 결과를 보고
  문항을 교체하거나 규칙을 조정하지 않았다.
- 두 묶음 사이 고유 출처 ID 중복은 0개다. 그러나 평가 문항도 과거 실험에 노출된
  익숙한 보고서의 문항이므로, 새 회사나 독립 holdout 검증이라고 부르지 않는다.

| 항목 | 개발 확인 12입력 | 별도 평가 12문항 |
| --- | ---: | ---: |
| 후보 출현 수 | 391 | 394 |
| 고유 출처 ID | 387 | 355 |
| 전체 원문 요청 토큰 | 750,537 | 544,369 |
| 구조 목록 요청 토큰 | 724,045 | 502,222 |
| 감소율 | 3.53% | **7.74%** |
| 원문·context·순서 완전 복원 | 통과 | 통과 |

동일한 로컬 `cl100k_base`로 직렬화된 전체 요청을 센 값이다. 모델/provider
사용량 또는 청구액이 아니며, 출력·추론·답변 비용을 포함한 workflow 비용 절감을
뜻하지 않는다. 별도 평가의 입력별 변화는 0.3% 증가부터 23.7% 감소까지다.
개발 flat 입력 6개는 모두 약 0.1–0.3% 증가했다. 고유 본문이 대부분 남고 참조
목록에도 토큰이 필요하므로, 중복 제거 효과가 제한적이라는 해석과 부합한다.

## 검증 결과와 한계

- 네트워크를 차단한 계약 테스트 **12개 통과**. Unicode/CRLF/빈 원문,
  긴 불명확 표, 중복 내용과 서로 다른 기간 context, 반복 출현 순서,
  알 수 없는 참조·중복 출처·예상 밖 필드 거절을 검사했다.
- 24개 입력, 총 785개 후보 출현에서 모든 원문 문자·context 값·후보 순서를
  복원했다. 원문 범위와 출처별 연결도 기록했다.
- 이전 개발 검토의 단서 **34개 전부가 하나의 온전한 묶음 안에 남았다**.
  이것은 이전 실패 사례의 보존 확인이며 새로운 정확도 점수가 아니다.
- 별도 평가 12문항에 등장하는 저장된 witness 출현 **21개**의 전체 원문도
  동일하다. N01에서는 평가일·대상·기관·등급을 포함한 전체 표와 기존
  `multi_period` 표시가 각각 연결된 상태로 남는 것을 직접 확인했다.
- Provider·임베딩·새 ingest 호출 **0회**. LLM 의미 해석·선택·답변 정확도,
  실제 비용·지연·무응답 confusion matrix는 **NOT_RUN**이다.
- 실행 준비의 문법 오류 1개는 입력 고정·평가 전에 수정했다. 유료 오류 재시도나
  결과에 따른 알고리즘 변경은 없었다.

원문 완전 복원은 정보 보존의 증거다. 모델이 각 숫자의 기간·대상을 정확히
해석한다는 증거는 아니다. 기존 메타데이터가 잘못됐거나 원문 자체가 잘려 있다면
그 상태도 그대로 보존한다. 기존 DRAM witness 주석 불일치는 앞선 보고서의
별도 기록을 유지하며, 이번에 과거 점수를 재평가하지 않았다.

## 판단

정보 손실 문제는 이번 표현에서 제거했지만, 선택 호출 비용을 크게 줄이려던
목표에는 부족했다. 고정한 50% 절감 기준은 실패했으므로 이 안은 여기서 종료한다.
7.7%가 언제나 무가치하다는 뜻이나 LLM 선택 자체가 무의미하다는 결론은 아니다.
표현 변경만으로 기존 높은 선택 비용이 해결됐다고 주장할 수 없다는 판단이다.

현재 제품은 유지한다. 유료 비교·추가 검색·새 요약 모델·자동 후속 실험은 없다.
이후 비용 개선을 다시 검토한다면 표현 미세조정보다 **선택해야 하는 후보 범위나
별도 선택 호출의 필요성**을 다른 실험 축으로 다뤄야 한다. 그것은 근거 누락과
선택 품질을 다시 평가해야 하는 별도 과제이며 이번 구현에 포함하지 않았다.
