# DART RAG 평가 종합: 실패 원인, 답변 개선과 유지할 구현

작성일: 2026-10-15 · `OFFLINE_SYNTHESIS` · 추가 provider 호출 0회

**확인된 결과는 단일 원인으로 설명되지 않는다.** 원문을 잃거나 잘못된 주체를 붙인 파서 결함, 필요한 근거가 최종 top-8에서 밀리는 검색 문제, 충분한 근거를 받아도 관계·계산·인용을 틀리는 생성 문제가 각각 관측됐다. 일부 변경은 실제 답변을 개선했지만, 회귀·비용·검증 범위까지 고려했을 때 기본 경로를 대체할 만큼의 반복적인 이득은 입증하지 못했다.

현재 유지할 기준은 **수정된 파서와 구조 보존, 명시적 범위의 hybrid 검색, SimpleRagAgent의 답변 생성 1회, 출처 ID·응답 형식 검사**다. 이는 현 구현이 최적이라는 결론이 아니라, 확인된 원문 복구와 실행 계약은 유지하고 품질 이득이 충분히 검증되지 않은 추가 단계를 기본값에 넣지 않는 결정이다. 최신 모델 비교의 C11 개선도 유효한 국소 결과로 남긴다.

## 1. 이 문서의 근거와 읽는 기준

- **[확인]**: 기존 코드·계약·원문 대조 보고서·저장 산출물에서 확인한 관측이다. 동일 assistant의 의미 판정은 그 한계를 함께 표시한다.
- **[해석]**: 관측을 설명하는 제한적인 추론이다. 원인 하나의 독립 효과나 다른 문서로의 일반화를 뜻하지 않는다.
- **[미확인]**: 실행하지 않았거나, 비교 설계로 구별할 수 없거나, 판정을 유보한 부분이다.

이 문서는 기존 결과를 종합한 **docs-only 작업**이다. 새 검색·임베딩·답변·judge 호출, 새 원문 수집, store 변경, 기존 답변 재채점은 하지 않았다. 아래 숫자는 각 실행 당시의 표본·버전·판정 기준에 속한다. 과거 보고서의 검증을 이번에 전부 재실행했다고 주장하지 않는다. 주요 원문 보고서를 대조했고, 최신 모델 비교의 저장 집계와 실행 감사도 확인했다.

`P/F/U`는 해당 비교의 통과/확정 실패/판정 유보다. 최근 비교의 strict는 필수 내용·명시적 요구·계산 절차의 적용 기준·실제 인용 지원과 추가 주장까지 본다. U는 임의로 P나 F에 합치지 않는다. **실행 완료, 근거 충분성, 핵심 답의 정확성, 요청 충족, 인용 충실도, 거절은 서로 다른 지표**다. 반복 응답 수를 독립 문항 수로 세거나, 서로 다른 패널의 분모를 합친 전체 정확도를 만들지 않는다.

## 2. 전체 평가에서 확인한 출발점

### 2.1 전체 77문항과 구조 비교

| 평가 | 실제 범위 | 답변 가능 문항 | 거절 기준 충족 | 확인된 의미 |
| --- | --- | ---: | ---: | --- |
| Simple RAG 전체 평가 | 11개 기업의 2023 보고서, 77문항, 단회 | 30/55 | 18/19 | 77/77은 실행 완료다. 수치는 15/20, 요약·혼합은 15/35 통과 |
| 구조 비교 A: 일반 텍스트 | 같은 77문항의 새 답변 | 38/55 | 17/19 | 이 비교에서 답변 통과가 가장 많음 |
| 구조 비교 B: 문서 구조 | 같은 77문항의 새 답변 | 18/55 | 17/19 | 제목·절을 남기는 것만으로 개선되지 않음 |
| 구조 비교 C: 문서+표 구조 | 같은 77문항의 새 답변 | 32/55 | 18/19 | B보다는 좋지만 A를 넘지 못함 |

**[확인]** 3조건의 231개 답변은 모두 완료됐다. A와 C를 대응하면 A만 통과 11개, C만 통과 5개, 모두 통과 27개, 모두 실패 12개다. B와 C에서는 C만 통과 15개, B만 통과 1개였다. 표 구조가 유용한 사례는 있었지만 이 비교의 전체 우위로 이어지지 않았다. [전체 평가](simple_rag_full77_result.md), [3조건 비교](structure_full77_result.md)

**[확인]** 이 비교는 구조만 켜고 끈 실험이 아니다. 청크 수는 A 3,425 / B 8,214 / C 13,176개, 평균 전달 문맥은 40,791 / 25,686 / 27,024바이트였고 A의 입력 토큰은 C의 약 1.56배였다. 추출 보존·분할·접두어·전달 본문량이 함께 달라졌다. 원래 Simple RAG의 30/55와 별도 실행 C의 32/55를 전후 개선으로 계산하지 않는다.

**[해석]** 고정된 8개 청크에서 세분화가 필요한 정보를 여러 조각으로 분산시키면, 구조를 보존해도 여러 요청을 함께 충족하기 어려워질 수 있다. 평문의 넓은 본문이 복합 근거 확보에 유리했던 사례와 일치한다. 다만 청크 길이·구조·접두어 각각의 효과를 분리한 결과는 없다. “표 구조가 무용하다” 또는 “청크를 크게 하면 해결된다”는 결론은 지지되지 않는다.

**분모 경계:** 최초 주체·범위 충돌 3문항을 제외해 답변형 55개를 사용했다. 이후 현대차 판매보증충당부채의 연결/별도 정답 충돌도 확인됐다. 이를 추가 제외한 민감도는 원래 실행 30/54, 구조 비교 A/B/C 38/54·18/54·31/54다. 기존 판정과 분모는 원문에 보존하며 한쪽에 유리한 분모만 선택하지 않는다. 이 수치들은 **파서 v5 이전 평가**이며 현재 v5의 전체 답변 정확도가 아니다.

### 2.2 Planner·Compiler와 hybrid의 관측

**[확인]** 같은 근거를 준 개발 4문항에서 Planner·Compiler는 명확한 답변 품질 우위를 보이지 않았다. 비용은 Simple RAG의 3.47배, 관측 시간은 4.79배였다. 정확한 계산을 실행해도 요청한 소수 자릿수를 놓쳤고, 입력에 없는 정밀 잔액을 복구하지 못했다. 한 baseline 답변은 저장 결과를 재사용했으므로 동시 실행 지연 비교도 아니다. 실행·출처 보호의 구현 가치와 최종 답변 우위는 구별한다. [workflow 비교](portfolio_workflow_comparison_successor.md)

**[확인]** 별도의 노출된 NAVER 12문항에서는 hybrid가 답변 가능 9문항을 모두 정확·완전·출처 지원까지 충족한 반면 Dense-only는 5/9였다. 부족 근거 통제는 hybrid 2/3, Dense-only 3/3이었다. 따라서 BM25를 없애는 단순화도 기존 근거로 정당화되지 않는다. 이 소규모 결과를 전체 77문항이나 일반 질문으로 확대하지 않는다. [Dense-only 비교](vanilla_dense_comparison.md)

## 3. 실패 원인: 확인된 위치와 아직 분리하지 못한 원인

### 3.1 과거 전체 실패의 분해

구조 비교의 답변형 55문항×3조건에서 실패한 **77개 응답**을 분석했다. 실패한 독립 질문 77개가 아니다. 여러 문제가 함께 있으면 확인한 필수 요소 중 가장 앞 단계의 누락을 대표 분류로 삼았다. [실패 경계 감사](structure_full77_failure_boundaries.md)

| 실패 위치 | 응답 수 | 확인된 내용 | 여기서 말할 수 없는 것 |
| --- | ---: | --- | --- |
| 원문 보존·후보 생성 이전 | 16 | 14개는 corpus에 필요한 원문이 있으나 후보에 없음. 2개는 구조 조건에서 회계 문단 자체가 소실 | 16개가 모두 embedding 탓이라는 결론 |
| 후보에는 있으나 최종 선택에서 누락 | 39 | 대표 근거가 RRF 8위 밖. 해당 대표 근거는 BM25-only 34개, Dense-only 5개 | reranker를 넣으면 39개 답변이 모두 복구된다는 결론 |
| 필요한 근거 전달 후 답변·인용 실패 | 17 | 단위·인용 연결 6개, 해석·산술·요청 누락 11개 | 검색을 개선하면 이 실패도 자동 해결된다는 결론 |
| 실패 위치 유보 | 5 | 단위·행·열의 연결을 확정하기 어려움 | 임의로 파서 또는 모델 실패로 배정 |

**[확인]** 최종 선택 누락이 가장 많았고 저장된 231개 RRF 목록과 실제 답변 입력의 연결도 재현됐다. **[해석]** 당시의 우선 진단 대상은 최종 근거 선택이었다. 이후 실험은 이 가설을 검증했지만, 아래처럼 선택 개선의 국소 이득과 회귀가 함께 나왔다. 과거 감사의 “다음 후보”를 현재의 미실행 권고처럼 반복하지 않는다.

### 3.2 파싱·청킹: 실제 결함은 있었으나 전체 원인은 아니다

**[확인]** 이전 소제목의 주체가 다음 표에 남는 문제와 작은 회계정책 표를 기간·단위 라벨로 소비하는 결함이 재현·수정됐다. 현재 v5는 번호형·문단 서식·대괄호 제목의 소유 관계, 표 본문과 명시적 단위 보존, 구분자 정규식의 과도한 역추적 수정을 포함한다. 원문 복구가 직접 검증됐으므로 이 수정은 유지한다. [v5 채택 근거](../architecture/parser_v5_adoption.md), [표 본문 보존](table_context_hint_preservation.md)

**[확인]** 수정 뒤 v4의 노출된 7문항은 2회 모두 통과했고, 후속 v5에서는 필수 답·요구 14/14, strict 11/14, 두 번 모두 strict 통과 4/7이었다. v5의 남은 문제는 추가 주장에 대한 인용 누락과 문서 전체로 넓힌 부재 진술 등이었다. v5 채택은 명시적 원문 결함 수정에 대한 별도 결정이며, 답변 회귀 gate를 통과한 것으로 바꾸지 않았다. [v4 답변](table_context_v4_answer_regression.md), [v5 답변](paragraph_heading_v5_answer_regression.md)

**[미확인]** v4→v5 점수 차이가 파서 수정 때문이라는 통제 비교는 없다. 저장소와 새 확률적 답변이 함께 바뀌었다. v5에서 모든 제목·표 연결이 옳거나 전체 77문항 정답률이 향상됐다는 결과도 없다.

### 3.3 Dense·BM25·RRF: 구현과 검색 정책을 구분

| 검증 | 확인된 결과 | 판단 |
| --- | --- | --- |
| v5 저장 ANN16 대 정확 거리 순위 | 99.27% 일치, 답변형 55문항의 최종 입력 모두 동일, 대표 근거 전달 8→8 | 이 표본에서 ANN 근사 오차를 주요 누락 원인으로 볼 근거 부족 |
| 정확 Dense 후보 16→32 | 대표 근거 전달 8→8, 2개 회복·2개 손실 | 후보 확대가 최종 전달의 순이득으로 이어지지 않음 |
| 같은 Dense32/BM25 후보의 RRF 합계→최댓값 | 대표 근거 전달 8→8, 회복과 손실 교환 | 이 합산 변경은 미채택 |
| v3→v5 검색 감사 | 고정 대표 요소 27개 중 입력 도달 10→8, 추적한 corpus 소실 1→0 | 원문 복구와 최종 선택 개선은 다른 단계 |

위의 27개는 추적용 대표 요소이며 질문 전체의 충분성이나 정답률이 아니다. 이 검색 비교들은 답변을 생성하지 않았다. corpus 변경은 벡터·BM25 통계도 바꾸므로 v3→v5를 파서 단독 답변 회귀로 해석하지 않는다. [정확 검색](full77_v5_exact_dense.md), [후보 확대](full77_v5_dense32.md), [합산 변경](full77_v5_fusion_max.md), [v5 검색 감사](full77_v5_retrieval_audit.md)

**[확인]** Dense16/BM25≤24, 동일 가중 RRF60에서는 두 채널 중복 후보의 최소 점수 `1/76+1/84≈0.025063`이 단일 채널 1위의 최대 점수 `1/61≈0.016393`보다 높다. 따라서 한 채널만 찾은 필수 근거가 중복 후보 뒤로 밀릴 수 있다. 이는 재현된 산식의 성질이며 구현 버그가 아니다. **[미확인]** 다른 임베딩 모델·혼합 정책·선택기가 일반적으로 더 낫다는 결론은 없다. 정확 최근접 탐색이 맞아도 의미적 검색이 충분하다는 뜻은 아니다.

### 3.4 C10: 값 없는 표제 편중의 원인과 개선 범위

**[확인]** 조사한 표제·값 표 4쌍은 원본 XML부터 별도 TABLE이었다. 긴 표를 자르다가 값이 사라진 경우가 아니다. 청크 크기를 2,500→10,000으로 바꾼 일반 fixture에서도 이 경계는 유지됐다. 표제 `400:295`의 바로 다음 `401:296`은 조정 상세표이며, C10의 정답 표는 별도의 연결 현금흐름표 `104:5`다. 필요한 두 값은 원본·블록·청크·색인에 모두 남아 있었다. [원본·검색 경로 감사](header_chunk_origin_audit.md)

표제·기간은 구조 객체에 남아도 값 표의 평면 검색 입력에는 충분히 사용되지 않았다. 반면 짧은 표제는 제목 반복·접두어와 함께 높은 관련성 순위를 받았다. C10 본표는 정확 Dense 31위, BM25 3위, RRF 8위였고 값 없는 두 표제는 두 채널에 중복되어 RRF 1·2위였다. 저장 벡터의 ID 연결과 12질문의 ANN 192개 순서는 정확 거리 계산으로 재현됐으며 해당 검사에서 구현 오류는 발견되지 않았다. 표제 `400:295`의 임베딩 입력 419자 중 본문은 34자, 접두어는 385자였지만, 그 길이만의 독립 효과를 측정한 것은 아니다.

### 4.3 최신 72회 모델 비교의 효과와 미채택 이유

근거: [현재 runtime 계약](../architecture/agent_runtime_contract.md), [Compiler 비교 계약](../architecture/compiled_workflow_contract.md), [코드 지도](../overview/codebase_map.md), [파서 채택](../architecture/parser_v5_adoption.md), [기본 앱 캡션 격리 검증](../operations/release_readiness_2026-09-30.md).

**서로 다른 두 변경을 구별한다.** 기존의 opt-in 캡션 첨부는 검증된 날짜·단위 캡션을 답변 근거로 전달하는 구현이다. 최신 C10 실험은 제목을 포함한 표제·기간을 값 표의 검색 입력에 붙인 별도 변형이다. 앞 구현이 존재한다는 이유로 뒤 실험까지 제품에 채택됐다고 설명하지 않는다.

## 6. 남은 한계와 판단 경계

1. **현재 v5의 전체 답변 정확도는 미확인이다.** 과거 77문항 답변, v5 전체 검색 감사, v5의 소규모 답변 회귀는 서로 다른 증거다. 최근 두 보고서 12문항과 새 6문항으로 과거 전체 점수를 대체할 수 없다.
2. **검색의 잔여 개선 여지는 있다.** 별도 27문항 근거 용량 감사에서는 7개에 대해 후보 안의 필요한 묶음을 1–2개 청크·최대 7,963바이트로 구성할 수 있었다. 이는 검토자가 확인한 실현 가능한 입력이며 자동 선택기의 성공이나 전체 oracle 정확도가 아니다. 후보 밖 근거와 판정 보류 7문항도 남았다. [근거 용량 감사](evidence_capacity_audit.md)
3. **원문 연결과 의미적 소유는 다르다.** 물리적으로 인접한 표제, 유효한 출처 ID, 맞는 숫자만으로 올바른 회사·기간·연결/별도·인과관계를 보장하지 못한다. C10 인접 상세표와 C11 분류 오류가 이 차이를 보여 준다.
4. **정답·판정 기준에도 결함과 불확실성이 있다.** 연결/별도, 영업권/무형자산, 공시 비율/재계산, 비교 대상 전체, 주체·인과·기간 연결을 구분해야 한다. 보류 7문항은 기존 점수를 덮어쓰지 않고 후속 버전 계약으로 분리했다. 모든 실패를 gold 문제로 돌리지 않으며 확정 오류와 U를 유지한다. [평가 계약 정리](evaluation_contract_disposition_v1.md)
5. **새 문항도 독립 holdout과 같지 않다.** 질문·원문 선택·판정을 같은 assistant가 수행했고, 여러 패널은 익숙한 보고서·노출된 사례를 사용했다. 최신 reader 12문항은 새 두 보고서지만 해당 두 보고서만의 corpus 통계이며, 후속 ablation에서는 이미 노출된 표본이다. 최신 모델 비교의 새 6문항은 충분한 근거를 직접 고른 reader 평가다.
6. **무회귀 관측은 보장이 아니다.** 대부분 조건별 1–2회이며 C11 질문 비교만 한 문항에서 7회씩이다. 같은 low 조건의 C09 산술 오류도 실행에 따라 나타났다 사라졌다. 거절 문항 없는 패널로 거절 성능을 주장하지 않는다.
7. **실행 재현과 모델 불변성은 다르다.** 동일 embedding 입력의 벡터 차이, 새 ANN index의 후보 차이가 기록됐다. 모델 ID·effort 반환·해시 확인으로 제공자 내부 snapshot이나 내부 reasoning 과정을 증명할 수 없다. fresh paired embedding과 저장 packet 사용은 해당 비교의 혼입을 줄였을 뿐이다.
8. **기본 앱의 검증 범위는 제한적이다.** 산술 실행, 주장별 의미 지지, 전체 요청 누락 검증은 수행하지 않는다. 사후 Decimal 계산·원문 검토의 통과를 제품의 자동 검증으로 표시하지 않는다. 개별 실패용 규칙을 추가하지 않는 결정과 이 한계의 공개를 함께 유지한다.

## 7. 이 종합에서 확정하는 결정

**[확인된 사실]** 파서 결함과 원문 복구, 최종 선택 누락, 충분한 근거 이후의 생성 오류가 모두 존재했다. 일부 구조·선택·모델 변경은 실제 답변을 개선했다. 그러나 C10의 순위 개선처럼 답변 이득이 없거나, 캡션·선택처럼 회귀가 생기거나, 최신 모델 패널처럼 새 문항이 차이를 드러내지 못한 경우를 분리해야 한다.

**[종합 해석]** 이 프로젝트의 성능 정체는 구조를 저장하는 것만으로 필요한 정보를 검색·전달·해석·인용하는 전 과정이 좋아지지는 않는다는 데 있다. 더 많은 agent 단계나 메타데이터도 해당 실패 위치를 실제로 바꾸고 다른 성공을 보존해야 이득이 된다. 모든 문제를 LLM 성능, chunk size, RRF 또는 구현 버그 하나로 환원할 근거는 없다.

**[현재 결정]** 검증된 원문 복구와 단순 RAG 계약을 유지하고, 위 미채택 실험은 해당 결과로 종료한다. 기존 [포트폴리오 완료 범위](../overview/portfolio_scope.md)를 개별 실패에 맞춘 추가 튜닝으로 자동 재개하지 않는다. 후속 연구가 별도로 결정된다면 새 문서의 실제 검색부터 답변까지, baseline 실패와 기존 성공을 함께 포함하고 평가 기준을 사전에 고정해야 한다. 이는 남은 검증 조건이며 이번 작업에서 새 실험을 준비·승인·실행한 것은 아니다.

이번 변경은 이 문서 1개 추가다. 기존 source·설정·store·질문·gold·결과·현재 상태 문서는 그대로 보존한다. 기존 실험의 자세한 요청·출력·비용·봉인 기록은 각 연결 보고서가 가리키는 `benchmarks/results/**`에 있으며 Git ignored 로컬 증거다. 이 문서에 연결한 로컬 집계가 새 clone에도 포함된다고 가정하지 않는다.
