# 제목 범위 수정의 저장·검색·답변 전달 검증

2026-09-29. 사용자가 이전 소제목 잔류를 다시 수정·검증하도록 요청한 후,
이미 적용된 파서 수정의 경로 전체를 검증했다. 추가 제품 코드 변경은 필요하지 않았고,
휴대 가능한 통합 회귀 테스트3개를 추가했다. 외부 호출과 실제 저장소 변경은 없다.

## 원인과 수정 위치

기존 `financial_parser.py`의 plain 문단 처리는 새 번호형 제목을 일반 본문으로
처리해 이전 대괄호 주체의 적용 범위를 끝내지 못했다. 원문 등급 자체의 손상은 아니다.
현재 `_extract_plain_heading_parts`는 독립 번호형·굵은 인라인 제목을 인식하고,
`_push_heading`은 관측된 상위 번호 수준으로 복귀하면 이전 하위 주체를 닫는다.
정상적인 자회사 하위 항목은 유지한다. 원문 제목과 내용도 보존한다.

이 수정은 이전 [파서 수정](heading_scope_fix.md)과
[새 저장소 재구축](../operations/heading_scope_store_rebuild_2026-09-29.md)에서 이미 적용됐다.
이번 검토에서는 검색·답변 단계가 올바른 제목을 이전 제목으로 덮어쓰는 별도 버그가
검토 경로에서 재현되지 않았다. 전체 문서의 모든 제목이 옳다는 보장은 아니다.

## 새 통합 테스트

`tests/test_heading_scope_delivery.py`는 실제 XML 파싱과 prefix 생성부터
graph/table sidecar 저장·재로딩, 임시 Chroma 저장·재개방, BM25/RRF 검색,
`SimpleRagAgent`의 모델 입력과 응답 출처 투영까지 실행한다.
질문을 이전 주체→새 항목→이전 주체→새 항목 순서로 반복해 검색 캐시도 확인한다.
임베딩 벡터와 답변 모델만 고정된 합성 값이며, 네트워크는 차단한다.

| 테스트 | 검증 |
| --- | --- |
| 일반 번호형 제목 | 이전 주체가 새 표의 본문 prefix·metadata·모델 입력에 남지 않음 |
| 굵은 인라인 제목 | 같은 문단 안 제목 전환도 저장·검색 이후 유지됨 |
| 실제 하위 번호 항목 | 정상적인 상위 주체는 삭제하지 않고 모델 입력까지 보존됨 |

- 수정 전 HEAD 파서 클래스를 같은 테스트에 연결: **3개 모두 실패**, 실행 오류0.
  실패 지점은 이미 parser metadata이며, 전달 계층보다 앞에서 잘못된 주체가 생겼다.
- 현재 수정본: **3개 모두 통과**.
- 제목·표·정규식·단순 RAG·저장 실패 경계·store successor 관련 **58개 통과**.
- 제품 코드의 추가 변경이 없으므로 전체 벤치마크·유료 답변을 재실행하지 않았다.

## 실제 보고서와 기존 실행 기록 대조

KB금융·삼성전자의 원본 회사 개요를 수정 전/현재 파서로 다시 읽었다.
동일한 등급 표의 본문은 일치하고, 제목만 올바른 범위로 연결된다.

| 보고서 | 수정 전 | 현재 |
| --- | --- | --- |
| KB금융 | `[KB라이프생명]` | `아. 신용평가에 관한 사항 > (1) 신용평가 현황` |
| 삼성전자 | `[DX 부문]` | `사. 신용평가에 관한 사항` |

새 저장소에 저장된 제목·텍스트와 이전 회귀 평가의 **실제 provider 요청4개**
(각 질문2회)에 들어간 제목·텍스트까지 대조했다. 현재 파서→저장본→전달본이 일치한다.
이는 저장된 요청 검증이며 새 LLM 실행이나 의미 정확도 재평가가 아니다.

761개 보호 파일(제품 소스, 이전 회귀 기록, 원본/기존 저장소, `.env`)을 해시 대조한다.
산출물은 `benchmarks/results/heading_scope_delivery_verification_2026-09-29/`에
수정 전 파서 사본, 실패/성공 테스트 로그, 원문/저장본/요청 대조 결과로 남긴다.

## 적용 경계

제목 수정은 코드와 별도로 재구축한 v3 저장소에 반영돼 있다. 앱 `.env`는 기존
NAVER v2 저장소를 유지하므로 v3 파서와의 readiness mismatch는 남는다.
[직전 답변 회귀 검사](heading_scope_answer_regression.md)의 인용 누락1건으로
앱 전환 기준이 미달한 결정은 이번 제목 전달 검사로 변경하지 않았다.
인용 누락은 이전 소제목 잔류와 별개이며, 이번 요청에서 프롬프트를 조정하지 않았다.
