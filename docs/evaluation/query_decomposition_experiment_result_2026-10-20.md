# 질문 분해 실험 실행 중단과 원인 검증

2026-10-20에 승인된 12문항 진단 실험을 실행했다. **4번째 문항의 깊은 검색 대조군에서 실험 어댑터가 정상적인 원문 표현 차이를 충돌로 판정하여 중단했다.** Dense 경로는 원문 끝 공백을 보존하고 기존 BM25 경로는 제거한다. 두 표현을 바이트 단위로 같다고 가정한 어댑터의 오류다. 질문 분해의 성능 효과는 아직 판정할 수 없다.

실행 범위와 중단 기준은 [사전 설계](query_decomposition_experiment_design_2026-10-20.md)를 유지한다. 이 결과는 `INVALID_RUN`이며, 근거 충족 gate와 답변 평가는 `NOT_RUN`이다. `NO_EVIDENCE_GAIN` 또는 정확도 개선으로 해석하지 않는다.

## 실제 실행 범위

| 항목 | 관측 결과 |
|---|---|
| 고정 패널 | 기존 평가 12문항, 7개 회사와 보고서 |

| 중단 문항 | `SKH_T1_060`, D 깊은 검색 대조군의 후보 병합 |
| 저장된 실제 입력 묶음 | 앞 3문항 A/B/C/D와 4번째 A/B/C, 총 15개 |
| 질문 분해 호출 | 4회 |
| 질문 임베딩 호출 | 12회 |
| 답변 생성과 자동 평가 호출 | 0회 |
| 실제 HTTP 요청 | 16회, 모두 HTTP 200과 usage 정산 확인 |
| 재시도 | 0회 |
| usage 기준 추정 비용 | USD 0.00856812 |
| provider 실행 구간 | 약 40초, 사전 준비와 원문 검토 시간 제외 |

완료된 검색 문항은 `NAV_T3_007`, `MIX_T3_048`, `HYU_T2_010`이다. 4번째 문항은 불완전하며 나머지 8개는 시작하지 않았다. 일부 입력 묶음만으로 패널의 개선율을 계산하지 않았다. 새 60문항 검증도 실행하지 않았다.

질문 분해 입력에는 원래 질문과 고정 지시문만 전달했다. 정답, 평가 기준, 과거 실패 설명, 정답 source ID는 넣지 않았다. 답변 생성은 근거 충족 gate 이후에만 허용했으므로 이번 중단으로 발생하지 않았다.

## 중단 원인

동일 청크 `20240319000684:218:89`가 D 후보에서 Dense 25위와 BM25 71위로 나타났다. 문서 ID와 문맥 필드는 같았고, 본문 길이는 각각 1,976자와 1,975자였다. 차이는 마지막 ASCII 공백 한 글자였다.

`src/storage/structure_graph.py`의 `structure_graph_bm25_payload`는 기존부터 `str(node.get("text") or "").strip()`을 사용한다. 같은 파일의 `hydrate_document_from_structure_graph`는 그래프 본문을 그대로 보존한다. 실험의 `run.py:fuse`는 모든 후보의 동일 ID에 대해 두 본문이 완전히 같아야 한다고 검사했다. 따라서 실제 데이터 훼손이나 모델 실패 없이 중단 조건에 들어갔다.

충돌 청크는 기존 RRF 기준 18위로 최종 12개 밖이었다. 그러나 사전 중단 규칙은 전체 후보의 source 충돌에도 적용되므로 해당 청크를 제외하고 실행을 계속하지 않았다. 저장된 임베딩으로 별도 store 복사본에서 같은 충돌을 재현했으며, 진단 과정의 외부 호출은 0회였다.

이 문제는 **실험 어댑터의 source 표현 계약 오류**로 분류한다. 기본 제품의 답변 오류나 질문 분해 가설의 실패를 입증하는 결과는 아니다.

## 외부 호출 없는 수정안 검증

별도 `source_view_resolution_proposal.py`에 실험 어댑터 수정안을 작성했다. 원래 실행기의 파일과 결과는 보존했고, 앱 소스에는 적용하지 않았다.

수정안은 후보마다 고정된 그래프 원문과 source ID·문맥을 대조한다. Dense 본문은 원문과 정확히 같아야 하고, BM25 본문은 기존 코드가 만드는 `원문.strip()`과 정확히 같아야 한다. 임의의 공백 정규화나 숫자·단위 수정은 허용하지 않는다. 선택된 본문은 다시 쓰지 않으며, 기존 RRF 점수·동점 순서·마지막 후보 표현 선택도 유지한다.

| 검증 | 결과 |
|---|---|
| 저장된 15개 입력 묶음·trace·선택 문서와 점수 재현 | 모두 정확히 일치 |
| 원래 어댑터의 충돌 재현 | 재현 |
| 수정안의 중단 문항 D 선택 결과 | 기존 native RRF와 정확히 일치 |
| 정상적인 Dense/BM25 표현 차이 | 허용 |
| 숫자 변경, 내부 공백 변경, Dense 임의 trim, BM25 추가 공백 | 모두 거절 |
| 단위 문맥 변경, 다른 보고서, 알 수 없는 청크, 순위 내 중복 | 모두 거절 |
| 수정안 검증 중 외부 호출 | 0회 |

이 검증은 어댑터 호환성과 손상 차단에 관한 것이다. 검색 근거 충족이나 답변 정확도 개선의 증거가 아니다.

## 비용과 보존 확인

실행일의 [OpenAI 공식 가격표](https://developers.openai.com/api/docs/pricing)를 저장하고 usage를 정산했다. 아래 금액은 청구서 확정 금액이 아닌 토큰 사용량 기준 추정치다. reasoning 출력은 전체 출력에 포함되며 중복 합산하지 않았다.

| 분해 모델 비캐시 입력 | 1,093 | 0.002186 |
| 캐시 읽기와 쓰기 | 0 | 0 |
| reasoning 출력 | 216 | 0.002592 |
| 그 외 출력 | 308 | 0.003696 |
| 질문 임베딩 입력 | 724 | 0.00009412 |
| 합계 |  | **0.00856812** |

사전 보수적 예약 한도는 전체 USD 26.62943232로 승인 상한 USD 30 안에 있었다. 중단 시까지 요청에 예약한 USD 0.13074944는 실제 사용량 비용과 다르다.

원본 로그 40개 파일의 해시, 16개 요청 body와 SDK 재구성 wire 해시, 응답 usage, 고정 실행기와 평가 입력을 확인했다. 소스·설정·`.env`·기존 store·과거 평가 기록 등을 포함한 보호 대상 1,605개 파일과 Git HEAD·stage 내용이 유지되었다. 기본 앱 소스 수정, fresh ingest, 앱 재시작, 커밋·push는 수행하지 않았다.

`execution_result.json`의 `closed:false`는 내부 transport guard가 HTTP 오류로 닫히지 않았다는 필드다. 전체 실행 상태는 `STOPPED`이며 프로세스는 종료되고 해당 실행 승인은 소비된 상태다. 재개 가능한 실행으로 해석하지 않는다.

## 후속 실행 경계와 산출물

사전 설계의 첫 오류 중단 규칙에 따라 이번 실행은 종료했다. 수정안으로 유료 재실행하려면 새 버전과 새 출력 디렉터리를 사용하고, 원래 질문·분해 prompt·후보 수·RRF·판정 기준을 유지해야 한다. 이번 지출을 전체 예산에 포함하고, 이전 일부 출력과 새 출력을 골라 섞지 않는다. 동일한 실험 목적의 재실행 여부는 별도 작업으로 판단한다.

로컬 산출물은 `benchmarks/results/query_decomposition_v1_20261020_130222/`에 있으며 Git 추적 대상에서 제외된다.

- `decision.json`: 실행·평가·성능 주장 상태
- `stage1/`: 16개 요청과 응답, 비용 ledger, 분해 결과, 실제 입력 묶음, 해시 seal
- `collision_diagnosis.json`: 저장 임베딩으로 재현한 충돌
- `source_view_resolution_proposal.py`, `source_view_proposal_validation.json`: 적용하지 않은 수정안과 외부 호출 없는 검증
- `execution_integrity_audit.json`: 호출·usage·입력·원본 보존 확인
- `panel.json`, `evidence_units.json`, `preparation.json`: 실행 전에 고정한 12문항·필수 근거·설정

포트폴리오에서 현재 주장할 수 있는 것은 평가 어댑터의 오류를 재현하고 비용과 원본을 보존하며 수정안을 검증했다는 사실이다. 성능 상승 경험으로 사용하려면 전체 근거 gate와 답변 비교를 완료한 후 별도로 판정해야 한다.
