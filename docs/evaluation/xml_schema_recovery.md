Date: 2026-10-16. Classification: parser bug. Provider-free local verification;
no ingest, embeddings, store writes or active-store changes.

`xsi:noNamespaceSchemaLocation="dart4.xsd"`. At source line 96164, one `TD`
contains bare `<STS>` and `<CG>` labels, each with one opening occurrence and
no closing occurrence. Frozen v11 reports nine XML errors: eight tag mismatches
and one unfinished-tag error. Recovery without the guard corrupts subsequent
structure and entity decoding; this is not merely a harmless warning.

## Minimal owning change

Parser v12 (`financial_parser_v12_schema_literal_labels`) adds one schema-bound
sanitizer step and bundles the unmodified official schema. It derives the root,
element and mixed-content vocabulary locally on first use and caches it. The
runtime has no company, receipt or problem-label literals and makes no network
requests. The existing quote, ampersand and angle-boundary rules are preserved.

Recovery requires all of the following:

1. A schema-declared root with the real XML Schema instance namespace and a
   `dart4.xsd` basename declaration, case-insensitive. Other schemas/URLs do not
   enable the rule.
2. A bare opening name absent from the pinned schema, inside a known
   mixed-content parent with known ancestors. No closing token of that name may
   occur anywhere outside comments, CDATA, instructions or quoted attributes.
3. No DTD, namespace scope changes, incomplete markup or remaining mismatched/
   unclosed structure. Only the original token's angle brackets are escaped.

Paired, attributed, self-closing and qualified unknown elements remain markup;
defined structural tags are never converted to text. All remaining libxml
ERROR/FATAL diagnostics still reject the report before context generation or
indexing. No parse retry, synthetic closing tags or relaxed error gate was added.

This is a vocabulary and text-preservation rule, not full XSD validation.
OpenDART exports can flatten `DOCUMENT-HEADER`. An undefined misspelled name
meeting the same conditions is also preserved literally, not corrected into an
intended element; author intent and semantic accuracy are not inferred.

## Preservation evidence

The two source edits were frozen during the previous diagnostic, before this
implementation. Apply only those edits to the unchanged original, pass that
through the frozen v11 sanitizer, and parse with `recover=False` to construct
the independent reference. No expected output is generated by the new helper.

| Check | Result |
| --- | --- |
| POSCO errors before / after | 9 / 0 |
| Additional source edits | Exactly two bare labels escaped |
| Full sanitized XML vs frozen reference | Exact equality |
| Full tree serialization, including attributes and text/tails | Exact equality |
| Full decoded text vs reference | Exact equality: 1,438,544 characters |
| Other 13 reports vs v11 | Sanitized XML and serialized trees unchanged |
| Original hashes and source line counts | All 14 preserved |
| Actual POSCO `process_document` | 1,835 chunks, default section budgets |
| Chunk witnesses | 3/3: entire repaired cell plus two downstream entity contexts |

Relative to the old permissive recovery tree's 1,438,351 characters, 193
characters are restored: 136 ampersands, 26 opening and 26 closing angles, and
five label letters. No characters are removed in the text multiset comparison;
the stronger equality check above compares against the entire independent
reference, including order. In particular, `P&S` and `HMS No.1&2` retain their
delimiters. The guard previously prevented the damaged report from being
indexed; this count describes the permissively recovered tree.

The whole-tree comparison covers this file's XML text and structure. Three
chunk witnesses are bounded delivery checks, not proof of complete chunk
coverage, semantic correctness, retrieval quality or answer accuracy.
