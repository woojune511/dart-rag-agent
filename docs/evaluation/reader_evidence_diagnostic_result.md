# 새 보고서의 근거 전달·독해 진단 결과

2026-10-15. **COMPLETE_BOUNDED_DIAGNOSTIC**. 승인한 36임베딩+48답변 요청을 모두 완료했다. 오류·재시도·NOT_RUN 0, 보수적 추정 비용 **USD0.94056133/12**, 실행 223.82초. 제품 변경이나 후속 유료 실행은 없다.

**이번 표본에서는 검색 단계의 손실 1문항을 확인했다.** 필요한 영업실적 표는 BM25 5위에 있었지만 RRF 10위가 되어 최종8개에서 빠졌다. 현재 입력에서는 두 번 모두 답변을 거절했고, 충분한 원문을 주면 같은 모델이 두 번 모두 맞혔다. 전체 문제를 LLM 성능이나 RRF 구현 버그로 설명할 결과는 아니다. 양쪽에서 공통으로 관찰된 계산 절차의 판정 한계와 추가 분류 주장도 별도로 남긴다.

## N03: 원문은 있었고, 최종 선택에서 빠졌다

질문은 농심의2025년 연결 매출 증가율과 영업이익률을 직접 계산하고 피연산자·식·소수 둘째 자리를 제시하도록 요구했다.

- 필요한 표 `20260311003892:998:2`에는2025/2024 매출액3,514,316/3,438,731백만원,2025 영업이익183,933백만원, 연결 기준 제목·단위·당기/전기 열이 있다. 원본 XML과도 대조한 표다.
- 이 표는 **BM255위, Dense16에는 없음, RRF10위**였다. 최종8개에는 임금상승률·할인율, 교환사채, 주당이익의 제목/단위, 이익잉여금 처분 관련 청크가 들어갔다. 요청한 매출·영업이익 금액은 없었다. 입력 byte 제한으로 빠진 항목은0이다.
- 현재 답변은 두 번 모두 “제공된 증거”가 부족하다고 한정하여 거절했다. corpus 전체에 값이 없다고 꾸미거나 금액을 만들어내지 않았다.
- 충분 근거 입력에서는 두 번 모두 `(3,514,316−3,438,731)/3,438,731×100 =2.20%`, `183,933/3,514,316×100 =5.23%`를 정확히 답했다.

이번 N03의 Dense16/BM25≤24 후보는 **서로 겹치지 않는40개**였다. 동일 가중치 RRF에서는 각 후보의 점수가 `1/(K+개별순위)` 하나뿐이다. 따라서 `K≥0`를 바꿔도 순위1–4의 후보8개가 BM255위보다 앞선다. **이 사례는 RRF 상수만 조절해서 복구할 수 없다.** 이는 저장 순위의 수학적 성질이며 새 설정을 시험한 결과가 아니다.

동시에 검색용 표현의 구체적인 의심점을 발견했다. 최종8개 모두 본문에는 `매출액`과 `영업이익`이 없는데, 공통 `[키워드: ...]` 줄에는 두 용어가 들어 있었다. `[consolidation_scope: separate]`인 별도 주석에도 그 키워드 줄은 `연결 기준`을 넣는다. 특히 주당이익 제목·단위만 있는 짧은 청크에도 같은 확장이 붙는다.

소유 경로는 `src/ops/benchmark_runner.py`의 `_zero_cost_alias_terms`와 `_build_zero_cost_prefixed_text`다. 절 이름에 재무제표 등이 있으면 실제 청크 내용과 무관하게 공통 재무 키워드를 추가하고, canonical structural prefix가 이를 index text에 포함한다. **접두어가 relevance를 희석할 가능성은 가설**이다. 실제로 그 줄을 제거했을 때 순위나 답변이 개선되는지는 이번에 시험하지 않았다. 이 관측을 parser의 본문 누락이나 입증된 전체 성능 원인으로 바꾸지 않는다.

## 다른 출처와 공통 독해 한계

**N04는 지정 gold ID 부재를 검색 실패로 세면 틀리는 사례다.** 사전 선택한 위험관리 표58:1은 최종 입력에 없지만, MD&A의1000:4가 같은 USD 행과 단위·연결실체 설명을 제공한다. 실제 답변은 그 대체근거를 인용했고30,790,362천원,17,073,974천원,증가13,716,388천원을 두 번 모두 맞혔다. 원문과 의미가 같은 대체 출처를 인정한 동결 기준을 적용했다.

**C09의 보류는 정답 숫자 오류가 아니다.** 네 답변 모두90.94%,91.12%,-0.18%p와 피연산자를 맞혔다. 다만 변화량을 `90.94%−91.12%`로 표시했다. 원래 피연산자로 계산한 변화는 약−0.1770927295%p이며, 두 방법 모두 소수 둘째 자리에서는−0.18%p다. 실행 전 “중간 반올림 없이”를 고정했지만 이 출력만으로 내부 계산 순서를 확인할 수 없다. 보이는 값의 정확성과 절차 준수를 나눠 후자는 `UNDETERMINED`로 유지했다. 정확한 절차 검증을 주장하려면 관찰 가능한 계산 단계나 두 방법의 최종값이 다른 문항이 필요하다. 이번 점수나 질문을 사후 수정하지 않았다.

**C11은 원문을 충분히 줘도 남는 추가 해석 문제다.** 네 답변 모두 홈쇼핑을 “온라인 채널” 항목 안에 넣었다. 인용 원문70:2는 “홈쇼핑 및 온라인 채널”을 병렬로 열거하며,71:3의 온라인 확장 설명은 자사몰·온라인 커머스를 말한다. 홈쇼핑 전체를 온라인으로 분류할 관계는 제공하지 않는다. 명시적 필수 항목은 충족하므로 주 평가는 통과지만, 추가 주장까지 지지되어야 하는 엄격 평가는 실패다. 관대한 목록 편집으로 간주하는 민감도에서는 양쪽 모두1개씩 올라가므로 N03의 상대적 개선은 변하지 않는다.

충분 근거 N03 두 응답에는 수식 강조용 ANSI 제어문자가 포함됐다. 수치·식 판정과 별도로 표시상의 관찰로 기록했으며 원본 답변을 정리해서 덮어쓰지 않았다.

## 검증·사용량·한계

- 원본 HTTP 응답84개, exact request84개, 임베딩 배치36개의 float32 벡터, 답변 입력48개와 응답·사용량을 다시 연결해 검증했다. 모델은 반환값 기준 `gpt-5.6-terra`, service tier `default`다.
- native Dense 검색12개의 반환 거리와 저장 벡터의 L2거리를 대조했고, scoped exact top16 집합과도 **192/192 일치**했다. 이12질문에서 ANN 근사 검색 때문에 필수 후보가 사라졌다는 증거는 없다.
- RRF12개와 실제 `SimpleRagAgent` 입력을 독립 계산/캡처로 재구성했다. source text/context/ID와 scope가 일치하고 byte 누락0이다. 실행 전후 보호 파일440개와 기존 검사 대상2,751개가 일치했다. 해시·실행 검증은 의미 판정자의 독립성이나 전체 파서 정확도를 증명하지 않는다.
- 입력 토큰229,322, 출력13,077(그중 reasoning2,116), 임베딩1,617,941, cached input0이다. 준비 때 고정한 보수적 단가로 **USD0.94056133**이며, 일반 uncached input 단가로 계산하면USD0.82590033이다. 둘 다 사용량 기반 추정이며 실제 청구서가 아니다. [준비 문서의 공식 요금 근거](reader_evidence_diagnostic_preparation.md)를 따른다.
- 답변만의 보수적 비용은 현재 입력24회USD0.480011, 충분 근거24회USD0.250218이다. 충분 근거를 선택한 사람/assistant 비용은 포함하지 않았으므로 이를 실시간 selector의 비용 절감 결과로 해석하지 않는다. 전체 실행시간은223.82초이며 준비·원문 검토 시간과 제품 HTTP 지연은 별도다.
- 두 보고서의 source-authored 양성12문항, 같은 assistant의 비맹검 검토다. 실제 제품11개 보고서 corpus와 BM25 통계가 다르고, 질문·원문을 공유하는 반복도 독립 표본이 아니다. 일반 정확도, 거절 성능, 특정 모델의 우월성, 새로운 selector의 유효성 또는 전체 프로젝트의 실패 원인을 증명하지 않는다.

## 다음 판단

이번 표본에서는 모델 교체나 Planner/Compiler 재도입보다 **검색용 공통 키워드 접두어의 영향 검증**이 다음 단일 후보로 더 구체적이다. 먼저 provider-free로 BM25에서 그 줄의 기여와 제거 효과를 분리하고, 기존 청크·scope·Dense 후보·답변 원문은 고정하는 비교를 설계할 수 있다. 여러 질문의 회귀를 확인하기 전에는 새 임베딩이나 제품 반영으로 넘어가지 않는다. 이미 노출된 N03 하나에 맞춰 가중치·규칙을 조정하지 않는다.

이것은 다음 후보 제안이며 이번에 추가 ablation을 실행한 결과가 아니다. RRF 구현은 저장된 계약대로 동작했고, 검토한 필수 원문도 corpus에 보존됐다. 구조 보존이 유용해도 그 표현을 검색 후보와 최종 입력에 전달하는 과정에서 이득이 사라질 수 있다는 관측이 이번에도 이어졌다. 충분한 근거에서도 추가 해석과 계산 절차의 판정 문제는 남는다.
