# 다음 표의 표제와 기간을 보존하는 최소 수정

2026-10-16. **PASS_OFFLINE_SOURCE_PRESERVATION**. 외부 모델·임베딩·검색·reranker·judge API **0회**, 비용 **USD 0**. 기존 store와 `.env`는 유지하고 별도 메모리 파싱 결과로 비교했다.

**다음 값 표를 소개하는 기간 문단이 앞 표 뒤에 붙는 경계를 수정했다. U03의 당기 표제는 값 표의 문맥에 보존되고, U16의 전기말 현금 표에는 다음 당기말 소개문이 붙지 않는다. 새 18문항의 저장된 문맥에서 기존 필수 근거의 손실·회귀는 0개다.** 새 검색이나 답변 생성은 하지 않아 검색 순위·답변 정확도 개선은 아직 확인하지 않았다.

## 수정 범위

실패 층은 [직전 원문 진단](new18_u03_u16_regression_diagnosis.md)에서 확인한 parser/chunking의 표제 소유권이다. 다음의 일반적인 DART 구조만 사용하며 회사명·문항 ID·금액을 조건으로 넣지 않았다.

- [FinancialParser](../../src/processing/financial_parser.py)는 명시적 기간으로 끝나는 짧은 문단 또는 두 행의 표제·기간·단위 표를 인식한다. 단순히 문장 안에 ‘당기’가 나오는 일반 설명은 해당하지 않는다.
- [블록 수집](../../src/processing/block_collection.py)은 **같은 XML 부모·같은 heading scope**에서 바로 이어지는 값 표에만 연결한다. 빈 구분자·페이지 구분·단위 전용 표는 통과할 수 있지만, 다른 내용·별도 기간·부모/heading 변경·태그 사이 본문은 연결을 막는다. 400자 이하 표제를 온전히 원문 위치에 연결하며, 기존 source context를 밀어내거나 잘라야 하면 적용하지 않는다.
- [청킹](../../src/processing/chunking.py)은 연결된 다음 표제를 만나면 앞 청크를 먼저 닫는다. 기간 문단은 해당 짧은 값 표와 함께 묶이고, 별도 표 형태인 표제는 본문을 유지하면서 값 표의 `table_context`에도 보존한다. 긴 값 표를 분할해도 이 명시적 context는 모든 조각에 남는다.

원문 셀·행·열·값, 숫자 정규화, 질문, 생성 프롬프트, BM25·Dense·RRF 설정은 바꾸지 않았다. `period_focus`의 기존 추론도 변경하지 않았다. 값 표의 `period_focus=unknown`이 남는 경우에도 원문 기간 표제는 실제 전달되는 text/context에 보존된다. 물리적 표제 연결을 의미 해석의 정답 판정으로 취급하지 않는다.

이 변경은 새 ingest의 파싱·청킹에 적용되며, 기존 query-time 실험용 caption sidecar를 자동 활성화하지 않는다. [런타임 계약](../architecture/agent_runtime_contract.md)에 범위를 명시했고 parser schema를 **`financial_parser_v7_forward_table_captions`**로 올렸다. 기존 v5 활성 store와 v6 평가 store를 새 파서와 호환된다고 처리하지 않는다. `.env` 변경·store 재구축·재임베딩·활성화는 수행하지 않았다.

## 테스트와 남은 검증

신규 회귀 테스트는 **10개**다. 수정 전 실패를 확인한 기간 문단의 앞 표 혼입·별도 표제 전달·긴 표 분할 보존에 더해 일반 설명, 교차 heading/부모, 중간 내용·다른 기간, XML tail, 문맥 예산에서 기존 근거를 밀어내는 경우를 검사한다. 숫자나 특정 회사 질문을 맞히는 테스트가 아니다. 기존 parser/header/source-context/semantic 관련 focused suite 169개도 통과했다.

외부 네트워크가 차단된 최종 전체 unittest는 **2192개 통과**, 실패·오류·skip 0개다. 첫 전체 시도는 Windows event loop의 내부 socketpair까지 차단해 20개가 실패했고, 테스트 실행기의 loopback만 허용한 후 통과했다. 외부 통신 시도는 최종 실행에서 0개다. 이를 제품 수정이나 provider 성공으로 해석하지 않는다. 최종 전체 검사 (`../../benchmarks/results/new18_table_prefix_fix_2026-10-16/full_suite_accepted_result.json`, local artifact not included).

이번 확인은 원문·표 구조·고정 문맥의 근거 보존이다. **새 검색 순위, U03 지역 오독 감소, U16 기간 오독 감소, 답변 정확도·출처 충실도 회귀는 NOT_RUN**이다. 검색 입력 582개가 달라지므로 나중에 새로 임베딩·색인하면 순위도 달라질 수 있다. 이 고정 문맥 결과를 실제 v7 검색 성능으로 대신하지 않는다. 기존 RRF·기본 8개 조건과 과거 답변 평가 결과는 유지한다.
