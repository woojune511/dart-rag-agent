# 정규화 목차 선택과 절 내부 hybrid 검색: 준비 결과

2026-09-30. **COMPLETE_OFFLINE_SECTION_HYBRID_PREPARATION**.

검증된 원문 제목의 정규화 목차를 제시하고, 선택된 절 안에서 기존 검색 기법으로
원문을 좁히는 실험용 경로를 구현했다.11개 보고서·15,608개 source 참조를 보존하고
77개 입력에서 인터페이스·검색 범위·최종 packet을 provider-free로 검증했다.
**실제 LLM 절 선택·답변 생성·검색 품질 평가는 NOT_RUN**이다.
PageIndex 공식 구현을 실행한 결과나 제품 경로 변경이 아니다.

## 이번에 구현한 동작

`원문 위치가 검증된 정규화 목차 → 절 선택1회 → 선택 절들의 원문 합집합 → Dense16 + BM25 최대24 → RRF60 → 원문8개 → 기존 답변 입력`

1. 원본을 기존 parser로 복원하여 각 TITLE의 위치·문자를 이전 검증 트리와 대조한다.
2. 기존 `_build_section_path`가 반환하는 제목 배열을 사용한다. 배열 prefix를 가진
   부모가 유일한 경우에만 연결한다. 문자열 `>` 분할이나 제목 이름만의 연결을 사용하지 않는다.
3. 원문이 연결되지 않은 빈 가지는 탐색 목록에서 제외한다. 원문을 가진 가지에서
   부모 누락·중복 경로가 발견되면 중단한다. 원본·기존 트리는 수정하지 않는다.
4. 선택기에 질문, caller가 명시한 보고서 범위, 해당 보고서 전체 절 목록을 전달한다.
   목록은 ID·경로·부모ID·source 수이며 정답 주석·대표근거·원문 요약은 넣지 않는다.
5. 응답은 `selected_section_ids` 하나다. 같은 보고서의 보이는 ID0~3개만 허용하고,
   중복 ID나 부모와 자식의 동시 선택은 거절한다. 선택한 절은 하위 절 원문을 포함한다.
6. 선택 범위를 **후보를 뽑기 전에** 적용한다. 각 절에서 따로8개를 뽑거나 최초 top8을
   사후 필터링하지 않는다. 모든 선택 절의 합집합에서 Dense16/BM25 최대24를 뽑는다.
7. BM25의 corpus 전체 IDF·토큰화·동점 순서와 기존 RRF60을 유지한다. 빈 선택·선택기
   오류·부적합한 ID에서 전체 보고서 검색으로 확대하거나 모델을 재호출하지 않는다.
8. 최종8개를 기존 SimpleRagAgent의65,536바이트 원문 단위 입력 생성에 전달한다.
   원문을 잘라 넣거나9위 이후로 보충하지 않는다. 이번 실행은 생성 직전에 중단한다.

정규화 목차도 의미 정확도를 자동 보증하지 않는다. 문서 제목은 데이터로 취급하며
선택기 지시로 사용하지 않도록 프롬프트에 명시했다. 코드 검사는 ID·소유권·범위에
관한 것이고, LLM의 제목 해석이나 prompt injection 저항 성능 검증은 아니다.

## 검색 재현과 검사

이번 Dense 경로는 기존에 저장한 **정확 squared-L2 전체 순위**를 사용한다. 선택 절에
속한 ID만 통과시킨 뒤 처음16개를 가져오므로, 같은 거리의 부분집합 정확 검색과 같다.
BM25는 원문 전체로 동일 인덱스를 구성하고, 선택 범위를 적용한 뒤 상위24개를 뽑는다.
실제 Chroma ANN의 절별 검색을 실행한 것은 아니다. 이 차이를 숨겨 제품 그대로의
종단 비교라고 주장하지 않는다.

- 전체 보고서 범위로 재현한77개 Dense/BM25 후보 및 최종 packet은 이전 정확 검색
  baseline과 일치했다. BM25 IDF나 tie가 몰래 바뀌지 않았는지 이 비교로 확인했다.
- 77개 입력에 순서 기반 가짜 selector를 넣어1~3개 절 선택을 실행했다. 질문 의미나
  골드를 보지 않고 ID 순서로 선택했으므로 이 결과에 근거 회수율·정답률 점수를 붙이지 않는다.
- 선택 범위 밖 source가 후보·선택·입력에 섞이지 않는지, selector1회만 호출하는지,
  RRF와 원문 단위 packet이 동일 규칙으로 만들어지는지 확인했다.
- 실제 앱 입력 생성154개(A77/B77)를 확인했다. 별도 검증은 source→정규화 부모 경로
  15,608개, 모든 절의 하위 원문 집합, B77개 RRF·packet을 다시 계산했다.
- 계약 테스트8개 통과: 선택 합집합, 잘못된/중복/부모자식 ID, 응답 모양·범위, 빈 선택,
  catalog 변경·입력 초과, 오류 재호출 금지, 후보 이전 범위 적용, 물리적 중첩 정규화와 중복 거절.

## 초기 중단과 수정

최초 실행은 KB금융 문서에서 내용이 없는 `대표이사 등의 확인` 양식 가지가 동일
정규화 제목을 갖는 것을 발견해 `ambiguous_canonical_path`로 중단했다.
검색 replay0개·provider0회였다. 같은 조건으로 재시도하지 않고, 원문이 연결되지 않은
빈 가지는 선택 대상이 아니라는 규칙을 명시했다. 실험 전체에서 빈 가지20개를 제외했고
15,608개 source는 모두 유지됐다. 실제 내용을 가진 중복 경로를 거절하는 테스트는 유지한다.

첫 실행의 소스 snapshot·로그·실패 기록은 그대로 보존했다. 수정 실행은 attempt02에
분리 저장했다. 이것은 provider-free 준비 코드의 수정이며 유료 재시도가 아니다.

## 후속 유료 비교 설계안 — 아직 실행하지 않음

평가는 선택한 절 안에 대표근거가 있는지, 후보·top8·실제 packet에 전달되는지,
두 반복의 회복·손실, 빈/무효 선택, 토큰·비용·시간을 분리한다. B가 두 번 모두 전달하고
A가 전달하지 않은 primary 근거가2개 이상이며, A가 전달한 primary 근거의 손실이
어느 B 반복에도 없어야 후속 새 문항 검증을 고려한다. 통계적 우월성이나 전체 충분성
기준은 아니다. gate 미달이면 이 노출 패널에서 prompt·선택 절 수를 고쳐 재시험하지 않는다.

이 단계는 검색 메커니즘 확인이므로 실제 답변 정확도·기권 안전성은 평가하지 않는다.
선택 모델의 의미 정확도, 새로운 문항, 실제 ANN 및 답변 비교는 효과에 따라 별도로
판단한다. pilot_design.json은 설계이며 가격 확인·비용 예약·provider 실행 admission은 미완료다.
