# 후보 근거 압축의 오프라인 타당성 점검

Date: 2026-09-29. Status: **COMPLETE_OFFLINE_NO_GO**.

후보의 앞·중간·끝 발췌와 일부 표 메타데이터만 보여주는 `source_preview_v1`은
로컬 입력 토큰을 **54.8%** 줄였지만, 대표 근거의 항목·기간·단위 단서를
잃었다. 이 버전을 유료 선택 비교나 제품 경로에 적용하지 않는다.
LLM 선택·답변 정확도, 실제 provider 토큰·비용·지연은 **NOT_RUN**이다.

## 범위와 고정 규칙

[기존 고정 후보 비교](fixed_pool_selection_result.md)의 6문항 × flat/table
12개 입력을 그대로 재사용했다. 이전 성공 6개와 근거 선택 누락 6개가 포함된
노출된 개발 표본이며, 새 문항이나 독립 검증 표본이 아니다.
391개 후보 출현의 ID와 순서를 모두 보존했다. 검색·새 수집·임베딩·provider 호출은 0회다.

질문이나 정답을 받지 않는 변환 함수를 먼저 고정했다.

- 회사·보고서 연도·접수번호·보고서 종류·범위·단위가 기존 context에 있으면 복사한다.
- 절 경로 160자, 소제목 100자, 표 문맥 200자, 헤더 문맥 360자,
  저장된 행 이름 240자를 상한으로 한다. 긴 항목은 앞·뒤를 별도 원문 구간으로 표시한다.
- 선두의 기존 메타데이터 줄을 건너뛰고 본문 앞·중간·끝을 각각 240자 발췌한다.
  본문이 720자 이하면 전부 보존한다. 단어·행 경계는 복구하지 않는다.
- 각 발췌에 원본 필드와 문자 시작·끝 위치를 기록한다. 새 요약·의미 해석·셀 추론은 없다.
- 선택 이후에는 원본 ID로 전체 원문을 다시 가져오는 계약만 검증했다.
  실제 선택이나 답변 생성은 하지 않았다.

기존 선택 prompt와 바깥 질문·범위·후보 순서를 유지한 가상 요청을 만들었지만,
문서 객체의 schema와 내용은 압축 뷰로 바뀐다. 이 가상 요청은 provider에
제출할 수 있게 승인·검증한 실행 packet이 아니다.

## 토큰과 원문 보존

| 전체 원문 요청, 로컬 토큰 합계 | 750,537 |
| 압축 요청, 로컬 토큰 합계 | 338,938 |
| 감소율 | 54.84% |
| 후보 출현 / 검증한 원문 발췌 | 391 / 1,685 |

두 요청을 동일한 `cl100k_base`로 직렬화하여 센 상대 비교다. Provider의
메시지 오버헤드나 모델 토크나이저 사용량을 재현한 값이 아니므로, 기존
실험의 provider 토큰이나 달러 비용과 직접 비교하지 않는다.
출력·추론·답변 비용도 없으므로 총 workflow 비용 54.8% 절감을 뜻하지 않는다.

초기 `o200k_base`는 로컬 cache가 없어 차단된 다운로드 시도로 준비가 중단됐다.
projection과 의미 검토 전에 로컬에 있는 `cl100k_base`로 측정 도구만 바꾸었다.
이전 profile/build 파일도 보존했다. 유료 호출 재시도는 없었다.

## 대표 근거의 단서 검토

원문과 압축 뷰를 보며 12개 입력의 대표 후보 13개를 검토했다. 질문에 필요한
항목명·기간·단위·대상 관계의 정확한 구절을 evaluation-only 파일에 기록했다.
이 구절들은 변환 함수나 가상 모델 입력에 들어가지 않는다.
노출된 표본에 대한 assistant의 비맹검 검토이며 독립 평가자 검증이 아니다.

**9/12 입력에서 대표 후보의 단서 손실이 관측됐다. 이는 9개 모델 오답이나
전체 후보 집합의 근거 소실률이 아니다.** 다른 후보의 대체 근거를 전수 배제하지
않았고, 해당 후보가 여전히 선택될 가능성도 있다. 나머지 3개 역시 모든 필수
요구와 혼동 가능성을 통과했다는 뜻이 아니다. 예를 들어 CEL_T3_040 flat은
당기 구절은 보존하지만 중간 발췌가 전기 표 내부에서 시작해 추가 혼동 여지가 있다.

표의 `period_focus`·`unit_hint`는 기존 parser가 저장한 표시다. 이번 검토는
그 표시의 금융 의미가 옳다는 보증이 아니라 압축 과정의 정보 손실 확인이다.
context의 보고서 연도만으로 표가 당기 수치임을 보증할 수 없다.
또한 v1의 `partial=false`는 짧은 본문에서도 선두 메타데이터 생략을 표시하지
못한다. 이를 계약 테스트로 기록했으며, 의미 완전성 신호로 쓰지 않는다.

### 이전 witness 주석의 불일치

SKH_T2_061 table의 옛 `original_witness`인 `20240319000684:41:0`을
다시 읽으면 63%는 다음 원재료 투입 비중이다.

> 반도체 부문 | 원재료 | 소 계 | 소 계 | 6,966,653 | 63% | -

이 후보를 DRAM 매출 비중 근거로 세지 않았다. 옛 LLM이 실제 선택한
`20240319000684:654:2`에는 “전체 매출 중 DRAM과 NAND가 각각 63%와 29%”라는
원문이 있으며, 새 발췌에도 남아 있다. 이전 raw 응답·주석·점수는 수정하지
않았다. 이 발견은 옛 대표 witness 주석의 한계이며, 과거 전체 감사의 재평가를
수행했다는 뜻은 아니다.

## 판단과 후속 범위

토큰 50% 절감, 후보 보존, 원문 재구성 기준은 통과했다. 검토한 구분 단서를
잃지 않는 기준은 실패했다. **v1은 여기서 종료**하며, 같은 사례를 보면서
폭이나 키워드를 조정하거나 LLM 비교를 자동 실행하지 않는다.

다음 설계에서 먼저 검토할 일반 문제는 두 가지다. 첫째, 기존 기간·단위와
구조 표시는 임의 본문 발췌와 분리해 보존해야 한다. 둘째, 긴 청크의 고정
위치 발췌는 질문과 관련된 내부 문단을 놓치므로 문단·표 단위의 발견 가능성을
별도로 보장해야 한다. 단순 발췌량 증가는 해결을 보증하지 않는다.
후속안의 효과는 별도 고정 표본으로 확인해야 하며 이번 산출물에는 포함하지 않는다.

## 산출물과 재현

로컬·미공개 산출물:
`benchmarks/results/compact_selection_feasibility_2026-09-29/`.

- `profile.json`, `compact.py`, `build.py`: 고정 규칙과 projection.
- `compact_panel.json`, `token_metrics.json`, `build_result.json`: 입력과 측정.
- `review.py`, `review.json`: 원문 위치가 있는 평가 전용 단서 검토·최종 판단.
- `test_compact.py`, `test_results.txt`: 9개 provider-free 계약 테스트.
- `input_seal.json`, `projection_seal.json`, `verification.json`, `completion_seal.json`:
  원본·변환·최종 파일 해시 검증. 기존 소스와 실험 파일 2,246개를 보호했다.

생성 파일은 배타적 생성으로 덮어쓰기를 거절한다. 재현은 원본을 보존하는 별도
출력 디렉터리에서 수행해야 한다. `build_result.json`의 `PENDING`은 projection
시점 상태이며 최종 리뷰는 `review.json`이다. 기본 `SimpleRagAgent`, 공개 API,
옛 실험 산출물은 변경하지 않았다. 변경된 current 문서는 의도한 handoff 갱신이다.
