# 원장 기반 출처 선택 단일화

2026-09-28. 실험 경로의 계약 수정 및 무호출 검증 완료. 실제 모델 평가와 제품 적용은 하지 않았다.

## 문제와 변경

[직전 실행](agentic_ledger_addressed_result.md)의 네 번째 문항에서 모델은 입력에 있는
출처를 원장의 단서에 인용했지만 별도 `selected_ids`에는 넣지 않았다. 출처와 구간은
유효했으나 두 선택 표현의 불일치로 실행이 중단됐다.

새 실험 경로는 모델 출력 스키마에서 `selected_ids`를 제거한다. 모델은 각 요구의
`evidence`와 `qualifications`에 출처와 원문 구간을 선택한다. 코드는 원장 순서,
각 항목의 evidence → qualifications 순서로 참조를 읽고, 처음 등장한 출처만 모은다.
같은 출처를 여러 요구가 참조하는 원장 자체는 유지한다.

이 목록을 다음 검색의 보존 출처와 답변의 전체 원문 목록에 사용한다. 기록용
`selected_ids`/`retained_ids`는 코드가 만든 관측값이며 모델이 다시 작성하는 필드가 아니다.
모델의 충분성 판단, 검색 질의, 원장 수정 사유 계약은 유지한다.

| 경계 | 처리 |
| --- | --- |
| 근거 없이 단서에서만 인용된 출처 | 동일하게 포함 |
| 반복 참조 | 원장 유지, 전달 원문만 중복 제거 |
| 서로 다른 출처 8개 초과 | 자동 절삭 없이 거절 |
| 미노출·미등록·다른 보고서 출처 또는 잘못된 구간 | 거절 |
| 다음 검색 문맥에 보존 출처가 안 들어감 | 중단 |
| 답변 문맥에 원장 또는 참조 원문이 안 들어감 | 중단 |
| 참조가 전혀 없음 | 빈 근거 패킷; 기존 결정적 기권 경로 사용 |

원문은 기존 256자 조각 좌표로 그대로 복사하며 의미 정확성은 검증하지 않는다.
기본 API/Streamlit의 `SimpleRagAgent`는 변경하지 않았다.

## 확인 결과

- 계약 테스트 **24/24**: 중복·단서 출처·8/9개 경계·비노출·범위·원장 전이·문맥 초과·과거 실패 패턴 포함.
- 네트워크 차단 모의 실행 **42회**: 여섯 입력에서 각각 결정 3회, 답변 2회, 검색 임베딩 2회. 실제 검색 질의나 답변 품질 평가가 아니다.
- 오류 주입 및 보고서 범위 통제 **15개** 통과. 재시도 없음.
- 결정 패킷 18개, 답변 패킷 12개, 추가 검색 기록 12개를 재구성해 코드 파생 출처와 일치함을 확인.
- 모의 검색에서 용량 때문에 새 후보 원문 8건이 제외됐으나 보존 출처 누락은 0건. 전체 후보 무누락을 주장하지 않는다.
- 고유 원문 **5,239개**의 조각 연결 복원 확인. 보호 파일 **1,438개**, 직전 manifest **1,043개** 및 완료 seal **394개**의 해시 일치. 새 준비물 **314개** 봉인.
- **새 provider 호출 0회, 실제 provider 비용 USD0, 품질 평가 NOT_RUN.** CLI와 함수 진입점에서 live 실행을 막았다. 모의 예산 상수는 이전 하네스에서 유지한 테스트 설정이며 새 지출 승인이나 실제 비용이 아니다.

처음 테스트는 저장 응답의 첫 output 항목을 메시지라고 가정해 23개 통과, 1개 읽기 오류가
났다. `message/output_text`를 찾아 읽는 별도 테스트 파일로 고쳤고 24개가 통과했다.
실험 엔진과 초기 실패 기록은 유지했다.

## 과거 실패를 다루는 방식과 한계

실패와 같은 출처·구간을 가진 별도 진단 입력에서 `907:3`, `909:5`, `214:124`가 모두
전달된다. 이는 **원장이 참조하는 3개 출처**다. 과거 `selected_ids`와 합쳐 5개를
전달하는 방식이 아니므로, 원장에 참조되지 않은 과거 선택 2개는 추가하지 않는다.
이 변화가 실제 답변에 주는 영향은 아직 평가하지 않았다.

실제 과거 출력은 원래 계약에서 여전히 거절되고, 새 계약에서도 폐기한 필드 때문에
거절된다. 자동 변환·재실행·점수 수정은 하지 않았다. 삼성의 검색 누락과 셀트리온의
성급한 충분성 판단은 이 수정으로 해결됐다고 볼 수 없다.

로컬 산출물은 `benchmarks/results/agentic_ledger_single_selection_2026-09-28/`에 있다.
`experiment.py`는 통합 모의 실행 경로, `ledger_contract.py`는 계약 발췌,
`contract_checks_corrected.py`는 최종 테스트, `audit.json`과 `readiness_seal.json`은
검증·무결성 기록이다. 기존 write-once 결과에 덮어쓰는 재실행은 지원하지 않는다.
실험 산출물은 Git 추적 대상에 넣지 않았다.
