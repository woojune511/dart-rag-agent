# U08·U09·U14 reranker 회귀 원인 진단

2026-10-15 · `COMPLETE_OFFLINE_DIAGNOSIS` · 새 외부 요청·모델 로드·로컬 forward·답변 생성 **모두 0회 / $0**

**저장 기록과 실행 코드 범위에서 질문/본문 연결, 토큰 구성, yes/no 계산, 정렬 오류는 발견하지 못했다. 기존 입력에 잘못 읽히기 쉬운 생성 접두어가 있으며, 이 설정의 reranker는 실제 값보다 관련 설명을 높게 평가했다. 다만 접두어와 모델 자체의 기여도는 분리되지 않았다.**

[완료된 비교](new18_reranker_evidence_comparison.md)의 622쌍 입력·두 로짓·순위를 재검사하고, 세 문항의 최종 24개 원문을 직접 검토했다. 기존 질문·gold·후보·점수·top8·판정은 변경하지 않았다. 답변 정확도와 출처 충실도는 새로 평가하지 않았다. 같은 assistant의 비맹검 분석이며 독립 검토는 아니다.

## 구현 점검: 확인된 사실

| 점검 | 결과 |
|---|---|
| 질문·후보·실행 기록·점수 연결 | 622/622의 질문, chunk UID, 순서, 입력 해시 일치. 다른 문항의 점수가 섞이지 않음 |
| 저장 검색 본문 보존 | 622/622가 기존 Dense/BM25 후보 본문과 같음. 접두어도 현재의 순수 생성 함수로 정확히 재구성 |
| 채팅 입력 구성 | 고정 revision의 로컬 `tokenizer_config.json`에서 `enable_thinking=False`로 렌더링한 문자열·토큰이 622/622 일치 |
| query/document 위치 | `<Instruct>` → 원래 `<Query>` → 저장 본문의 `<Document>` 순서. ID·순위·gold를 추가하지 않음 |
| yes/no 토큰 | `yes=9693`, `no=2152`; 각각 단일 토큰이며 decode 결과 일치 |
| 절단·특수 토큰 | 무절단, 최대 3,055/32,768토큰. 본문에 채팅 경계/think 토큰 삽입 없음 |
| 마지막 위치 | batch1, padding 없음, attention mask 모두1. 설치된 Qwen3 코드에서 `logits_to_keep=1`은 마지막 hidden state만 LM head로 전달함 |
| 추론 모드 | 기존 runner는 `model.eval()`·`inference_mode()`·CPU FP32·cache off. 모델 로드 기록 및 코드와 고정 설정 일치 |
| 점수 산식 | 저장 yes/no 로짓의 FP32 차이가 622/622에서 저장 점수와 정확히 같음 |
| 확률 변환·순위 | 두 로짓 softmax와 저장 sigmoid 최대 차이 약 **8.46×10⁻⁸**. 전체 후보 순서가 **18/18 동일** |
| 문맥 선택 | 기존 RRF 문맥18개 및 reranker 문맥18개를 그대로 재현. 모두 top8, 출처 본문/ID/context 및 byte 한도 일치 |
| 동일 입력 확인 | U15의 서로 다른 날짜 표제 UID 6개는 토큰 입력과 점수가 정확히 같음. 동점은 고정 합집합 순서로 처리됨 |

산식은 `s = logit_yes − logit_no`, `p_yes = exp(logit_yes)/(exp(logit_yes)+exp(logit_no)) = sigmoid(s)`다. 따라서 이 기록에서 차이 점수 대신 두 로짓 softmax를 써도 선택 결과는 바뀌지 않는다. 이는 yes/no 사이에 정규화한 점수이며, 실제 근거 충족 확률로 보정된 수치가 아니다.

검증의 한계도 있다. 저장된 것은 두 로짓이며 전체 vocabulary logits/hidden state는 없다. 이번에는 모델 forward를 다시 실행하지 않았으므로 **실제 forward의 수치 정확성, 다른 backend·정밀도와의 동등성까지 독립 검증한 것은 아니다.** prefix/instruction의 의미적 적합성도 토큰 일치와 별개다.

앞선 실행의 Windows launcher PID 감시 오류는 확인된 운영상 결함이다. 실제 worker 감독을 중간에 부착했으며, 입력·점수 계산·횟수는 바꾸지 않았다. 그 감시 오류가 특정 문항의 순위 회귀를 만들었다는 근거는 없다. 따라서 이번 결론은 모든 구현에 오류가 없다는 선언이 아니다.

**U08:** `78:2`에는 Orion Food Vina 법인 합계538,097백만원, `79:3`에는 Orion Food 법인 합계1,321,812백만원, `82:6`에는 Orion International Euro 법인 합계339,436백만원과 연도 열이 실제로 있다. 이를 국가 총액이나 연결 제거 후 국가 매출이라고 바꿔 읽어서는 안 된다. 모델에는 회사명·연도·값이 온전히 전달됐지만 국가명과 법인명 간 연결 설명은 별도 청크에 분산돼 있다. 1위 `9:9`의 1조4,000억원은 한국 김 산업의2024 수출액으로, 오리온 해외 매출 규모를 답하지 못한다. 모든40개 후보의 yes−no가 음수이며, 1위도 두 토큰 정규화 값은 약0.147이다. 고정 규칙은 절대 threshold 없이8개를 선택하므로 이 숫자는 거절 판정으로 사용하지 않았다.

**U09:** 1위 `436:312`의 본문은 “이 현금흐름이 유의적으로 더 이른 기간에 발생하거나, 유의적으로 다른 금액일 것으로 기대하지 않는다”는63자 설명이다. 점수6.556, 두 토큰 정규화 값 약0.9986이어도 연결 이익·실현 영업현금흐름 금액은 없다. 반대로 실제 이익표 `925:1`은 약0.9950이지만11위로 잘린다. 4위 `125:1`은2,454자의 긴 자료로, 중간에서 시작된 법인별 **별도** 재무현황과 미래5년 가정이 섞여 있다. 따라서 단순히 짧은 청크만 선호해서 생긴 결과로 설명할 수도 없다.

**U14:** `45:1`에는 `TR | 영업손익 | (53,107)`과 `호텔&레저 등 | 영업손익 | 60,854`, 전기 비교 열과 연결조정이 보존돼 있다. 원문 `original:113/116/117/118`의 사업 범위·백만원 단위·표를 대조했다. 해당 입력은1,423토큰으로 절단되지 않았다. 다만 본문은 `TR`과 `제53기` 같은 축을 사용하며, 질문의 ‘면세점’·‘2025년’과의 연결 일부는 다른 설명/보고서 문맥에 의존한다.

**이전 설명 정정:** 앞선 보고서와 수동 주석은 `45:1`과 `1019:1`을 함께 부문 손익 제공 자료로 표현했다. **해당 부문 금액을 실제 제공하는 것은 `45:1`이다.** `1019:1`은 연결 전사 손익표이며 부문 금액의 독립 대체 근거가 아니다. `1019:1`의28위 하락을 별도의 부문 근거 손실로 중복 해석하지 않는다. `45:1` 소실은 그대로여서 U14.1/U14.2의P→F와 전체 합계는 바뀌지 않는다. 이전 봉인 파일은 그대로 보존하고 이 문서와 새 주석에 정정한다.

## 값 없는 표제의 영향

‘표제만 있음’은 제목·기간·단위만 있고 본문 행이나 설명이 없는 청크로 한정했다. **세 문항 top8에서 각각 U08=0개, U09=1개, U14=0개**다. 지역분류 정의, 배당 주석, 사업 소개, 금액 없는 설명문은 따로 분류했다.

U09의 `149:25`는 실제 값 없는 표제로5위를 차지한다. 원본 XML에서도 `original:540`은 표제용 TABLE, 다음 `original:541`은 값 TABLE로 분리돼 있다. 값은 파싱에서 삭제되지 않았고 `150:26`으로 같은 후보 합집합에 남아17위다. 따라서 **원문의 표제/값 분리 + 독립 청크 점수화**가 함께 관측된다. 이 값 표는 종속기업의 별도 기준 현금흐름이어서, 표제에 붙이더라도 요청한 그룹 연결 총액의 정답 근거가 되는 것은 아니다.

저장 점수를 고정하고 `149:25` 하나만 제외하는 순위 산술에서는 대체 이익표 `925:1`이11→10위, `920:0`이34→33위다. top8 이익 근거는 여전히 복구되지 않는다. 이는 새 점수를 얻은 실험이나 채택한 필터가 아니다. U08·U14에는 표제만 있는 top8 자체가 없으므로 표제 삭제만으로 회귀를 설명하거나 해결했다고 할 수 없다. 이전 U15의 표제4개 선택은 별도의 관측 사실이다.

## 입력 접두어: 결함과 인과관계의 구분

**생성 접두어의 잡음은 확인됐다.** reranker adapter가 새로 만든 정보가 아니라, 기존 색인/검색 본문에 있던 표현을 그대로 전달한 결과다. 소유 경로는 [prefix 생성](../../src/ops/benchmark_runner.py), [표 metadata 추출](../../src/processing/financial_parser.py), [청크별 metadata 상속](../../src/processing/chunking.py)이다.

1. **본문에 없는 공통 재무 단어와 범위 신호.** `_zero_cost_alias_terms`는 섹션명에 ‘재무제표’ 등이 있으면 ‘매출, 연결 기준, 재무, 손익, 영업이익, 매출액’을 함께 붙인다. 실제로 별도 범위의 `792:260`, `591:59`, `541:16`, `525:0`, `533:1`에도 ‘연결 기준’이 붙는다. 접두어를 원문 사실처럼 읽으면 잘못된 범위 단서가 된다. U09 top8의 **8개 모두** 본문에는 ‘영업이익’이 없는데 접두어에만 그 단어가 있다. 단어 부재만으로 모든 이익 개념의 부재를 판정한 것은 아니며, 본문의 실제 항목/범위는 위에서 별도 검토했다.
2. **분할된 행과 맞지 않는 전체 표의 값 요약.** U08 세 매출 청크의 `[table_value_labels]`는 모두 같은 내용으로 시작한다. 첫 값 ‘내 수326,471’은 전체 표의 `(주)오리온 / 비스킷 / 2025` 행에 속하며, 세 청크의 본문에는 없다. parser가 전체 표 앞40개 값의 label/value를 만들고 chunking이 이를 그대로 상속한 뒤 prefix에서420자로 줄인다. 원문에 없는 숫자를 창작한 것은 아니지만, 다른 법인 행 앞에 주체·기간을 생략한 값이 노출되는 **입력 표현상의 결함**이다. 본문 자체의 법인·기간·값은 보존됐다.
3. **단일 metadata가 혼합 단위를 대표하지 못함.** U09 `925:1`의 `[unit_hint: 원]`과 본문 주표의 ‘단위: 백만원’이 다르다. 같은 표의 EPS는 원 단위다. 원문 단위는 살아 있으나 scalar hint를 표 전체 단위로 해석하면 틀린다. 이것이11위 순위를 유발했는지는 미검증이다.

구조 metadata와 공통 단어를 모두 합친 접두어 비중도 크다. 아래 비율은 **prefix와 본문을 각각 토큰화한 길이의 합** 중 prefix 비중이며, system/instruction/query는 제외했다. attention이나 점수 기여도를 측정한 수치가 아니다.

| 입력 | 생성 prefix 토큰 / 본문 토큰 | prefix 비중 |
|---|---:|---:|
| U08 배당 주석 `83:7` |152 /18 |89.4% |
| U09 시기 설명 `436:312` |215 /37 |85.3% |
| U09 값 없는 표제 `149:25` |212 /51 |80.6% |

**여기서 확인하지 못한 것:** 이 접두어를 제거했을 때 어느 점수가 얼마나 변하는지, 공통 키워드 한 줄과 구조 metadata 중 어느 것이 원인인지다. 과거 [BM25 키워드 제거 비교](keyword_prefix_bm25_ablation.md)는 다른 문항·검색 채널의 결과여서 이번 reranker의 인과 증거로 옮겨 쓸 수 없다. U08의1위는 prefix 비중13.1%, U14의1위는9.4%이며, 둘 다 공통 재무 키워드 묶음이 없는 사업 설명이다. 접두어만으로 전체 실패를 설명하기에도 반례가 있다.

## 모델 한계에 대해 말할 수 있는 범위

**관측 사실:** 고정된 모델·입력·질문에서 주제 관련성과 필수 수치의 실제 가용성이 일치하지 않았다. 기간·연결/별도·산업/회사·실현/추정·전사/부문의 차이를 만족하지 않는 자료가 상위로 올라왔다. 각 query-document를 독립 채점한 후8개를 고르며, 여러 청크를 결합한 요청 충족도나 결과 집합의 중복/빈 부분을 평가하는 절차는 없다.

**가설:** U08의 국가↔법인, U14의 면세↔TR/연도↔기수처럼 분산된 축 연결, U09의 이익+현금흐름을 동시에 채워야 하는 요청이 점수화에 부담을 주었을 수 있다. 공통 단어·불완전한 metadata와 generic web-search instruction이 주제 관련성은 높지만 값을 주지 않는 자료를 유리하게 만들었을 가능성도 있다. 이는 입력·출력과 양립하는 설명이며 내부 attention이나 학습 원인을 확인한 결과는 아니다.

저장된 다른 질문에서도 같은 본문이 사용돼 추가 실행 없이 대조했다. `920:0`은 U07에서1위/8.401, U09에서34위/2.997이다. `925:1`은 U07에서2위/6.709, U09에서11위/5.294다. 본문·prefix·context 해시가 동일하다. 이 모델이 해당 한국어 손익표를 모든 질문에서 낮게 평가하는 것은 아니다. 다만 원래 질문과 후보 집합이 달라 순위 차이를 특정 단어 하나의 효과로 해석하지 않는다. U14의 `45:1`은 U13에서도23위여서 이 한 표의 처리 난점은 남는다. 전사표 `1019:1`이 U13에서1위라는 사실은 부문표 처리 성공을 증명하지 않는다.

**미확인:** 0.6B라는 크기, 한국어 능력, instruction 언어, 표 학습 부족, 긴 입력, FP32/SDPA 수치 경로 중 어느 것이 원인인지는 분리하지 않았다. 절단은 배제했고 짧은 자료만 선택하지 않는 반례는 있지만, 길이에 따른 희석까지 배제하지는 못한다. 다른 모델·raw 본문·질문 재작성·정밀도 대조 및 실제 답변 평가는 모두 `NOT_RUN`이다. 모든 reranker의 실패로 일반화하지 않는다.
