## 이번 비교가 답할 질문

[동결된 문제 세트](evidence_selection_problemset.md)의 실패를 일반적인 의미
재정렬이나 기존 집합 선택 접근으로 해결할 수 있는지 먼저 확인한다.
아직 독자 기법의 필요성이나 기술적 기여를 입증한 단계가 아니다.

| 고정 항목 | 설정 |
| --- | --- |
| 표본 | 기존 6질문 × 3후보 조건 = 18입력; 독립 표본 18개가 아님 |
| 후보 | 입력당 원문 발췌 6개; 두 방식의 내용과 순서 동일 |
| 선택 한도 | 최대 3개; 빈 선택 허용; 선택 ID 중복/외부 ID 거절 |
| 모델 | `gpt-5.6-terra`, reasoning `low`, Standard, 출력 상한 8,192 |
| 호출 | 입력마다 방식별 1회, 합계 36회; 입력별 먼저 실행할 방식 교대 |
| 출력 | 선택 ID, 전체 후보 충분 여부, 선택 근거 충분 여부, 부족 정보 요약 |
| 공통 범위 | 선택만 수행. 답변 생성·재검색·embedding·유료 채점 없음 |

두 방식 모두 근거 충분 여부를 함께 묻는다. 따라서 평범한 reranker 전체를
대표하는 성능 비교가 아니라, **동일 출력 과제에서 선택 지시를 바꾼 비교**다.
실제 사용 토큰과 시간은 같다고 가정하지 않고 방식별로 별도 집계한다.

## 방법과 선행 연구의 경계

`relevance`: 개별 문서의 의미 관련성 순서로 가장 유용한 근거를 최대 3개 선택.
`set_iri_adapted`: 필요한 정보와 이를 제공하는 문서를 파악한 뒤, 정보 요구를
함께 충족하는 상호 보완적인 근거 집합을 최대 3개 선택.

[SETR 논문 §3](https://arxiv.org/html/2507.06838v2#S3)과
[공식 프롬프트 코드](https://github.com/LGAI-Research/SetR/blob/d1ac78b7e41f7c6a2cd8d582934fbba02893f343/generate_data.py)
를 확인했다. 코드의 `rank_zephyr_prompt`와 `selection_IRI_prompt`가 비교 개념의
참고다. upstream commit은 `d1ac78b7e41f7c6a2cd8d582934fbba02893f343`으로 기록했다.

이번 실험은 **SETR의 정확한 재현이 아니다**. 원본은 정보 요구별 분석을 출력하고
선택 수를 제한하지 않으며, 순위 방식은 전체 후보 순위를 반환한다. 논문의
SETR 모델은 별도 학습된 모델이다. 여기서는 같은 Terra 모델, JSON 결정만 출력,
최대 3개, 충분성 보고를 공통 적용한다. 후보도 한국어 DART 발췌 6개이며
실제 검색으로 얻은 20개 후보가 아니다. 원문 문장·표 줄바꿈을 그대로 유지한다.
학습, 원본 텍스트 정규화 및 논문의 end-to-end QA 평가는 수행하지 않는다.

따라서 `set_iri_adapted`의 실패를 SETR 자체의 실패로 표현하거나, 이 변형을
새로운 자체 기술로 주장하지 않는다. 회사·질문별 예시나 정답 단서는 두 지시에 없다.

## 사전 고정 평가와 다음 결정

모델에는 입력 JSON만 전달한다. 정답, 조건 이름, 요구별 정답 ID 및 숫자 기준은
전달하지 않는다. 선택 결과를 저장한 뒤 별도 `score.py`가 동결 주석을 읽는다.

- 완전 후보 12개: 선택 근거가 모든 주석 요구를 포함하는지 방식별·조건별 집계.
- 필수 근거 제거 6개: 전체 후보 부족을 인식했는지 별도 집계. 0개 요구 충족과
  올바른 부족 인식은 다른 지표다.
- 선택한 집합의 실제 주석 충족 여부와 모델의 `selected_sufficient` 선언을 비교.
- 기간 간·연결/별도 간 비교가 질문에서 요구된 경우, 이를 부당하게 거절했는지는
  충분성 선언과 부족 정보 요약을 원문에 대조해 검토한다.
- 동등한 대체 근거가 발견되면 별도 검토 기록에 남긴다. 원래 주석 점수와 검토 후
  해석을 함께 보고하며 원본 gold를 덮어쓰지 않는다.
- ERROR/NOT_RUN은 별도 보고한다. 미실행을 오답으로 넣거나 미완료 비교를 완료로
  표현하지 않는다. 충분성 문구의 의미와 숫자 오용은 ID 검사만으로 판정하지 않는다.

일반 의미 선택으로 해결되면 그 접근을 재사용하고 새 구성요소 설계를 중단한다.
집합 선택 변형만 개선되면 선행 기법의 적용 효과로 보고한다. 양쪽에 문제가 남아도
바로 독자 기법을 만들지 않는다. 서로 다른 질문 2개 이상에서 같은 실패 원인이
관측되는지, 주석 오류·예산 중단·원문 누락인지 먼저 판별한다. 이 수는 탐색적 설계
착수 조건이며 통계적 유의성이나 일반화 증거가 아니다.

반복되는 잔여 실패가 확인된 경우에만 그 원인을 겨냥한 단일 구성요소를 설계한다.
기술적 기여 주장은 이후 구성요소 제거 실험과 새 평가 패널까지 필요하다.
이번 후보 조건 간 텍스트 길이는 일치하지 않으며, 개발에 노출된 소규모 자체
작성 세트다. RRF/검색 recall, 정답률, 낯선 기업으로의 일반화는 이번 비교 대상이 아니다.

## 비용과 중단 조건

공식 [가격표](https://developers.openai.com/api/docs/pricing)와
[모델 문서](https://developers.openai.com/api/docs/models/gpt-5.6-terra)를 확인했다.
Standard 입력은 100만 토큰당 USD2, cache write는 USD2.50, 출력은 USD12다.
실행 guard는 모든 입력을 더 높은 USD2.50로 계산하고 할인은 적용하지 않는다.

| 항목 | 동결 값 |
| --- | ---: |
| 입력 예약량 | 총 301,430; 단일 요청 최대 11,872 |
| 출력 예약량 | 총 294,912; reasoning 포함 요청별 최대 8,192 |
| 36회 전체 보수적 예약액 | USD4.292519 |
| 제안 실행 상한 | **USD4.30** |
| 이번 준비의 provider 호출 / 추가 과금 | **0 / USD0** |

입력 예약은 정확한 서버 token count가 아니라, 요청 JSON UTF-8 byte 수 + 1,024의
보수적 로컬 추정이다. USD4.30은 이 요율·예약 정책의 실행 한도이며 실제 청구서
확인이 아니다. 실제 사용량이 관측되면 별도 추정 비용을 기록한다. 사용량이
없거나 실패한 요청은 예약액을 유지하고 중단한다. 서비스는 공식 Responses
endpoint와 Standard로 고정한다.

SDK retry 0, timeout 90초, 20초 heartbeat. 첫 오류·형식 위반·선택 ID 위반·불완전
응답·저장 실패에서 중단하고 이후 요청은 NOT_RUN으로 남긴다. 자동 재시작·resume은
없다. 정확한 요청 순서/본문 hash와 manifest에 연결된 새 1회 승인이 필요하다.
기존 실험의 소비된 승인을 재사용하지 않는다.

- `compare.py`: 36개 요청 생성, 실제 SDK/mock HTTP rehearsal, 승인 후 단일 실행.
- `requests/`, `manifest.json`: 검토 가능한 정확한 요청과 파일 hash/비용 계약.
