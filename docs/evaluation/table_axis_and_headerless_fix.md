# 넓은 표의 축과 헤더 없는 값 표 보존 수정

2026-10-16. **PASS_OFFLINE_SOURCE_PRESERVATION**. 외부 모델·임베딩·검색 API 0회, USD 0. 기존 store와 `.env`는 유지했다.

**이미 분할되는 넓은 표의 행·열 대응을 복구하고, 헤더 없는 단일 값 행 두 곳의 구조화 기록을 되살렸다. 새 18문항의 저장된 8개·12개 문맥은 수정 전후 36개 모두 동일하며, 기존 필수 근거 회귀는 0개다.** 새 검색이나 답변 생성의 개선을 측정한 결과는 아니다.

## 변경 범위

[직전 진단](table_handling_current_audit.md)의 두 재현 결함만 수정했다. 회사명·문항 ID·금액을 분기 조건으로 쓰지 않는다.

- [청킹](../../src/processing/chunking.py)은 이미 분할되는 넓은 표를 원본 grid 좌표로 투영한다. 빈 셀을 유지하고, 선행 숫자 ID와 그 뒤의 행 이름·단위 등 연속 축을 각 열 조각에 반복한다. 명시된 모든 헤더 행을 함께 보존하며, 행 분할은 셀 중간을 자르지 않는다. 기존 분할 진입 조건은 유지해 작은 표는 통째로 전달한다.
- [파서](../../src/processing/financial_parser.py)는 원본 grid와 헤더 수를 청커에 내부 필드로 전달한다. 이 필드는 저장 metadata에 추가하지 않는다. 헤더 수가 0이면 값 행을 `table_header_context`에 잘못 복제하지 않는다.
- [행 기록](../../src/processing/table_records.py)은 명시적 헤더가 없는 **단일 행**, 명명된 텍스트 축, 비기간 숫자 값만 있는 경우에 헤더 0행을 인정한다. 원문 열 좌표와 단위를 유지하고 존재하지 않는 열 이름을 만들지 않는다. 명시 THEAD/TH·연도처럼 보이는 숫자·텍스트 표제·다중 행의 기존 추론은 유지한다.

파서 schema는 **`financial_parser_v8_table_axes_headerless_values`**로 올렸다. [런타임 계약](../architecture/agent_runtime_contract.md)에 변경 범위와 제한을 명시했고, 이전 v7도 새 schema로 자동 채택하지 않는 manifest 검사를 추가했다. 기존 v5 앱 store와 v6 평가 store는 재구축·재임베딩·활성화하지 않았다.

## 실제 원문 수정 전후

| 대상 | 수정 전 | 수정 후 |

| HD 28열 지급보증 표 후속 조각 | 행 이름·통화 단위가 빠지고, 빈 첫 헤더를 잃어 헤더 위치가 어긋남 | 원문 열 좌표로 투영하며 행 이름과 `천USD·천CNY·천NOK·천EUR`를 숫자 행에 함께 표시 |
| HD 표의 헤더 | 문자열을 다시 나눠 잘린 조각. 후속 행 조각에는 첫 헤더 행만 반복 | 원문이 명시한 **3개 헤더 행**을 모든 조각에 반복 |

HD 표의 원문 9행·28열을 직접 대조했다. 세 조각 전체에서 **본문 셀 위치 168개와 그중 숫자 열 위치 108개**가 원문 값·좌표 그대로 남는다. 행 축 반복과 열 창 겹침에 따른 중복은 허용하되 새 셀이나 빠진 셀은 없다. 조각 길이는 기존 2,458/383/553자에서 2,448/1,512/696자로 바뀌었다. 원문 좌표 검사 (`../../benchmarks/results/table_axis_fix_2026-10-16/wide_original_preservation.json`, local artifact not included).

호텔신라 원문 두 곳은 THEAD가 없는 한 행 표다. 단위 추론값은 이전과 동일하게 미확정이며, 새 단위를 추정하지 않았다. 행 단위가 명시된 HD 표의 기존 전역 `unit_hint=백만원`도 이번에 바꾸지 않았다. **원문 단위 문자열과 기존 metadata의 보존은 단위 해석의 정확성 인증이 아니다.**

## 새 18문항의 필수 근거 회귀

직전 v7 고정 문맥의 실제 출처 위치와 본문을 새 파싱 결과에 대응시켰다. 저장된 top12 합집합 **183개 출처 모두 유일하게 대응**했고, 1개 출처를 여러 청크로 늘려 넣지 않았다. 원래 질문·scope·출처 순서와 8개/12개 개수를 유지했다.

**18문항 × 2조건의 문맥 36개가 모두 수정 전후 동일하다.** 따라서 기존 33개 필수 기준을 조건별로 대조한 66개 근거 판정은 그대로이며, 출처·바이트 한도에 따른 누락도 0개다. 최대 packet은 **47,514 UTF-8 bytes**로 65,536 상한 안에 있다.

## 검증과 남은 제한

신규 회귀 테스트는 넓은 표 **15개**, 헤더 없는 값 표 **7개**다. 수정 전 실패를 확인한 뒤, 숫자 ID·다중 행 축·빈 셀·병합/다중 헤더·셀 내 구분자·작은 표 유지와 명시 헤더 우선 등을 검증했다. 관련 **69개**, 외부 네트워크를 차단한 전체 **2,214개** 테스트가 통과했고 실패·오류·skip은 0개다. 전체 실행의 외부 연결 시도는 0개이며 Windows 내부 loopback socket 46개만 허용했다. 전체 결과 (`../../benchmarks/results/table_axis_fix_2026-10-16/full_suite_result.json`, local artifact not included).

아주 긴 헤더와 값 행 하나는 셀 대응을 깨지 않도록 통째로 보존하므로 soft character target을 넘을 수 있다. 기존 packet byte 상한은 유지한다. 셀 안의 literal `|`도 보존하지만 평문 표시 자체의 구분자 모호성은 남는다. 다중 행의 헤더 없는 표, 연도처럼 보이는 값, 기간 중복 판정, 행/표 단위 충돌은 이번 수정 범위가 아니다.

이번 변경 전 보호 대상 2,582개에서 소스·계약·현재 상태 문서 8개만 허용한 변경으로 기록한다. 기존 `.env`, 앱/평가 store, 원문과 과거 실험은 전후 해시로 보존한다. 기존 DB는 열지 않았으며 전체 테스트의 임시 fixture store는 별도다. 새 자료는 별도 묶음 (`../../benchmarks/results/table_axis_fix_2026-10-16/`, local artifact not included), 최종 해시는 closeout (`../../benchmarks/results/table_axis_fix_2026-10-16/closeout.json`, local artifact not included)에 남긴다. commit·push·store 재구축은 하지 않았다.
