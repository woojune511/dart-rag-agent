## 실행과 평가 조건

- 원래 질문 77개와 명시적 보고서 접수번호 범위를 유지했다. 정답·평가 체크포인트는 생성 입력에 넣지 않았다.
- 10월 18일 저장된 질문별 **Dense 16 / BM25 최대 24 후보**와 동일한 RRF 순위를 재사용했다. A는 top-8, B는 그 순위의 top-12다. 검색·임베딩·질문 분해 호출은 추가하지 않았다.
- 이는 **같은 후보 안에서 최종 문맥 창을 늘리는 비교**다. 네이티브 `search(k=12)`의 후보 확대(Dense 24 / BM25 36)를 시험한 결과가 아니다.
- 현재 `SimpleRagAgent`의 답변 생성·출처 ID 검사 경로를 사용했다. `gpt-5.6-terra`, reasoning `low`, 출력 상한 8,192토큰, 동일 프롬프트/schema, default tier, Responses `store=false`, retry 0을 고정했다.
- 문항별 A→B / B→A 순서를 번갈아 실행했다. 조건별 77회, 총 154회이며 재생성·튜닝은 없었다.
- 양쪽 입력 한도는 전체 source 단위 **65,536바이트**다. 77문항 모두 A의 실제 전달 source가 B에 포함됨을 확인했다. B가 항상 12개 source를 받은 것은 아니다.
- 사전 기준과 출력을 봉인한 뒤 조건명을 가린 154개 응답을 인용 원문·구조 문맥과 대조했다. **154개 초기 판정을 봉인한 후 조건 매핑을 열었다.** 같은 assistant의 검토이고 문맥 길이로 조건을 짐작할 수 있어 독립 평가나 완전한 블라인드 평가는 아니다.
- 완전 정답은 **내용 정확성·필수 요구 충족·인용 근거 충실성이 모두 PASS**인 답변이다. 안전한 부분 답변도 요청한 핵심 값을 빠뜨리면 완전 정답으로 세지 않는다. 근거 충실성은 모든 중요 사실 주장에 대한 인용 지지이며 출처 ID 유효성과 다르다.
- 수치 계산은 사후 Decimal 검산과 피연산자의 기간·대상·단위 대조로 확인했다. 최종 값의 표시 정밀도 오류는 정확성에, 근거 없는 원인·기간·범위 연결은 근거 충실성에 반영했다. 이것은 앱에 내장된 산술·의미 검증 기능이 아니다.

기존 분모는 [평가 계약 처분](evaluation_contract_disposition_v1.md)을 그대로 따른다. 일반 답변 48개, 거절 19개, 기존 정답 충돌·보류 10개다. **77개 모두 실행했지만 정답률 분모를 77로 만들지 않았다.** 과거 criteria 파일의 54개와 보류 6개 처분도 원본 그대로 보존했고, 이번 실행 전 protocol/panel에 공통 48개를 명시했다.

보류 10개는 `KBF_T1_017`, `POS_T1_075`, `POS_T2_058`, `HYU_T3_036`, `KAK_T3_055`, `SKH_T2_061`, `MIX_T3_063`, `SAM_T2_027`, `CEL_T2_073`, `HYU_T2_035`다. 이들의 내용 정확성·완전 정답은 판정 보류하고, 실제 답변 주장의 근거 지지만 별도로 검토했다.

## 소규모 실험과 다른 이유

앞선 12문항 실험 (로컬 기록: `top8_top12_answer_ab_result_2026-10-20.md`)은 실패 사례를 중심으로 선택한 답변 가능 10개를 두 번씩 생성했다. 완전 정답 4/20→14/20은 그 선택된 패널의 관측이다.

이번 전체 실행 안에서 같은 10개 질문만 보면 **3/10→6/10**, 나머지 일반 답변 38개는 **30/38→28/38**이다. 이전 두 반복과 이번 한 반복은 합산하지 않는다. 나머지 38개도 과거 개발·평가에 노출됐으므로 새 holdout은 아니다.

이전 실험에서 확인한 핵심 근거 복구 네 문항은 이번에도 개선됐다. 다만 전체에서는 이미 잘 답하던 문항의 회귀와 생성 변동이 드러났다. 따라서 “검색 창을 8에서 12로 늘리면 일반 정답률이 50%p 오른다”는 설명은 사용할 수 없다. 설명할 수 있는 경험은 **소규모 개선을 전체로 검증하고, 답변 완성도와 근거 충실성의 상충을 발견해 기본값 변경을 보류한 과정**이다.
