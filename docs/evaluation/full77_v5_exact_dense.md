2026-09-30. **COMPLETE_OFFLINE_EXACT_DENSE_COMPARISON**. 추가 API 비용 **USD0**.

현재 Chroma의 Dense16은 정확한 거리 기준16개와 **99.27% 일치**했다.
정확 검색으로 바꾸어도 고정 대표근거의 실제 입력 도달은 **8→8**, 긍정55문항의

ANN 설정을 바꿀 근거는 얻지 못했다. 모셔널·셀트리온 해외매출 표는 정확 검색에서도

## 벡터와 정확 순위 검증

- 저장된 재사용 벡터와 당시 생성한56개 벡터를 원래 순서대로 재구성했다.
  **15,608개 전체**의 ID·원문·float32 벡터 해시가 저장소 readback 기록과 일치한다.
  그 기록·벡터 원본과 이번 재구성 결과의 해시를 보존했다. Chroma 저장소를 열지 않았다.
- 77개 질문 벡터는 이전 봉인과 일치한다. 각 질문의 명시적 보고서 범위 안에서만 전수 계산했다.
- 실제 저장 index의 `l2` 설정에 맞춰 float32 벡터를 float64로 승격하고
  `sum((x-q)^2)`를 계산했다. 정규화하거나 cosine으로 바꾸지 않았다.
- 모든 거리를 별도 norm/dot 식으로 교차 확인했다(절대 오차1e-10).
  정확 거리 동률은 chunk UID 사전순으로 고정했다. 경계 동률 허용차는 사전 고정1e-7이다.
- 저장된 ANN 거리와 재계산 거리의 최대 절대 차이는 약1.10e-6으로 사전 한도5e-6 안이다.
- 표 metadata는 제품의 기존 sidecar loader로 복구했다. 저장된 모든 A Dense 후보와
  전체 원문·metadata의 동일성을 검증해 검색 순위 이외의 입력 변경을 차단했다.

## 결론과 다음 검토 경계

이번 고정 대표근거에서는 **근사 검색 오차를 없애도 최종 입력이 개선되지 않았다**.
따라서 현재 결과만으로 HNSW 설정 변경이나 정확 검색의 제품 적용을 진행하지 않는다.
다음 실험을 별도로 한다면 Dense16→32만 바꾸고 BM2524·RRF60·최종8개를 고정해,
17–30위 근거가 후보에 들어온 뒤 실제 입력까지 도달하는지 볼 수 있다.
이는 제안일 뿐 이번 실행에는 포함하지 않았다. 후보 확대는 다른 근거를 밀어낼 수도 있으며,
RRF를 함께 바꾸거나 LLM selector를 추가하면 원인을 구분하기 어려워진다.

새 답변 성능·일반화·독립 평가·전체 의미 검증 주장은 없다. 기존 strict11/14 답변 회귀
미달과 별도 파서 채택 결정은 그대로다. runtime 변경·원본 store 변경·commit·push·유료 후속은 없다.
