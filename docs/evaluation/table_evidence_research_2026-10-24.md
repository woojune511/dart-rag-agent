# 표 근거 전달 개선: 결과와 적용 범위

[평가 목록](README.md) · [공개 실험 코드·산출물 목록](../../benchmarks/published/README.md)

표의 값과 행·열·기간·단위가 모델 입력에 함께 남도록 보강했을 때 **일부 필수
항목 누락과 답변 오류가 줄었다.** 다만 모든 조건에서 정확도가 오른 것은 아니며,
문맥 크기와 비용 증가를 감수할 만큼 기본 앱에서 이득이 반복됐다고 보기는 어렵다.
이 문서는 2026-10-24까지 저장된 결과를 종합한다. 공개 작업에서 새 모델 평가를
실행하거나 과거 판정을 바꾸지 않았다.

## 무엇을 개선했나

누락은 원문·파싱, 후보 검색, 최종 선택, 답변 입력 전달, 모델 독해에서 각각 발생했다.
파서 v12는 다음 표의 표제·기간이 앞 표에 붙는 현상, 넓은 표의 열 대응,
헤더 없는 값 표, 기간 중복 판정과 행별 단위를 수정한다. 이 구현과 계약 테스트를
공개 소스에 포함했다. 보고서 선택 UI와 답변 옆 근거 생략·검색 저하 표시도 포함한다.

별도 실험의 `table_fact_units`는 기존 청크에 연결된 표 객체와 원본 XML을 대조해
숫자 값, 행·열의 물리적 위치, 헤더와 연결 문맥을 묶는다. 해시·XPath·셀 위치와
원문 문자열을 확인하고, 표별 중복과 UTF-8 바이트 예산을 검사한다. 후보·순위·선택
문서·기존 본문은 유지하고, 의존 셀을 포함한 값 묶음 전체가 들어갈 때만 첨부한다.
이 검사는 **원문 연결 검사**이며 기간·주체의 의미 해석이나 답변 정확성 보증이 아니다.

## 실제 답변 비교

A는 기존 전달 64KiB, C는 표 보강 160KiB다. 각 비교 안에서는 질문·모델·프롬프트·
검색 결과·순서가 고정됐다. 같은 질문의 반복 답변이므로 아래 분모를 독립 표본 수로
해석하지 않는다. 완전 통과는 정확도·필수 항목·출처 충실도 기준을 모두 충족한 답변이다.

| 고정 조건 / 답변 대상 | 정확도 A→C | 필수 항목 충족 A→C | 출처 충실도 A→C | 완전 통과 A→C |
| --- | ---: | ---: | ---: | ---: |
| Sol, top-12, 기존 77문항 중 46개 × 2회 | 83/92 → 86/92 | 84/92 → 86/92 | 89/92 → 90/92 | 83/92 → 84/92 |
| Sol, top-12, 새 보고서 18문항 중 15개 × 2회 | 28/30 → 30/30 | 28/30 → 30/30 | 27/30 → 28/30 | 26/30 → 28/30 |
| Terra, 앱 top-8, 같은 18문항 중 15개 × 2회 | 28/30 → 28/30 | 28/30 → 28/30 | 28/30 → 30/30 | 26/30 → 28/30 |

근거: [77문항 보고서](../../benchmarks/results/table_fact_answer_full77_20261023/report.md),
[새 18문항 보고서](../../benchmarks/results/table_fact_holdout18_preparation_20261023/execution/report.md),
[앱 조건 보고서](../../benchmarks/results/table_fact_app_top8_answers_20261024/report.md).

- 기존 77문항의 거절은 36/38로 같았다. 별도 진단·보류 12문항의 출처 충실도는
  22/24에서 19/24로 낮아졌다. 이를 답변 대상 46문항의 개선에 섞어 숨기지 않는다.
- 새 18문항의 거절은 Sol 5/6→6/6, Terra 4/6→5/6이었다. `abstained` 표시와 실제
  거절 문장이 불일치한 경우도 있어 두 항목을 구분했다.
- 77문항의 필수 항목 기록에서 누락은 12→6, 부분 충족은 4→2로 줄었다.
  Motional의 지분·장부금액·순손실은 복구됐지만 요청한 손익 전체는 여전히 불완전했다.
- 새 보고서는 준비 당시 기존 평가에 쓰지 않았던 3개 공시다. 질문은 실사용 상황을
  가정해 직접 작성했고 실제 사용자 로그가 아니다. 첫 실행 이후의 Terra 비교에서는
  이미 노출된 문항이다. 모두 assistant 원문 대조이며 독립적인 사람 gold 평가가 아니다.

## 표 보강, 문맥 크기, 모델 효과를 어떻게 구분하나

Sol 비교의 양쪽 모델이 같으므로 그 안의 개선을 모델 업그레이드 탓으로 설명할 수
없다. 이때 query reformulation, Nori, 스키마 검색, reranker, Planner를 추가하지도 않았다.
다만 A→C는 **표 표현과 최대 예산을 함께 바꾼 효과**다. 표 형식만의 효과로 단정할 수 없다.

[12문항 예비 실험](../../benchmarks/results/table_fact_answer_pilot_20261023/report.md)은
기존 64KiB / 보강 64KiB / 보강 160KiB를 비교했다. 답변 대상 8개 × 2회의 정확도는
8→8→10/16, 완전 통과는 8→8→9/16이었다. 큰 표에 필요한 값 묶음이 64KiB에서
탈락하고 160KiB에서 전달되는 사례가 확인됐다. 이는 **보강된 표현 안에서의 예산 효과**이며
원래 표현의 예산만 늘리는 독립적인 2×2 실험은 아니다.

Terra/top-8의 보강 입력은 모두 64KiB 안에 들어갔다(최대 63,978 bytes). 이 패널은
160KiB 상한이 필요하다는 근거가 아니다. Sol/top-12와 Terra/top-8 사이에서는 모델과
선택 개수가 함께 달라져 두 결과의 차이를 모델 하나의 인과 효과로 분리할 수 없다.

## 비용과 채택 판단

77문항 Sol 비교에서 C의 입력 토큰은 A의 2.11배, 생성 추정 비용은 1.96배였다.
전체 성공 생성 비용은 약 $9.94이며, 503 실패 요청의 미확정 비용은 별도 상한으로
기록했다. 새 18문항의 Sol 실행은 문서·질문 임베딩과 생성을 합쳐 약 $1.90,
Terra/top-8의 저장 입력 생성 비교는 약 $1.08이었다. 이는 당시 usage 기반 추정이며
청구서나 현재 가격이 아니다. 실행 범위가 달라 총액만으로 모델 효율을 비교하지 않는다.

**유지:** v12 원문 구조 보존, 기존 단위·기간 metadata 전달, UI의 보고서 선택과
생략·검색 저하 안내. Simple RAG의 기본 모델·top-8·64KiB는 그대로다.

**실험으로 보존:** 검증된 표 값 묶음 전달과 160KiB 비교 코드. 일부 개선은 확인했지만
반복·비용·앱 조건의 이득이 제한돼 기본 경로에 연결하지 않는다. BM25 국가·소재지
정책도 명시적 opt-in으로만 남으며 default는 꺼져 있다.

**미채택 결과도 공개:** 행 검색, 표 스키마 혼합, Kiwi/Nori·IDF, 구조 라벨 중복 TF,
가중 RRF·CC/DBSF·reranker, 질문 분해 등. 전달 개선 후 스키마 검색을 다시 적용해도
삼성 연결 배당금 근거 손실이 남았다. [재검증 보고서](../../benchmarks/results/table_schema_fact_interaction_offline_20261023/report.md).

남은 한계는 후보 자체가 없는 근거, top-k 선택 손실, 잘못된 기간·주체 해석,
추가 주장에 대한 인용 누락, 작은 평가 패널과 기준 민감성이다. 원문 연결 검사의
통과나 평균 점수 상승을 모든 질문에 대한 의미 검증·일반화로 확대하지 않는다.
