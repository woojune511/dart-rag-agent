# 현재 표 처리의 정확성과 남은 결함

2026-10-16. 현재 미커밋 v7 소스, 저장된 3개 원문과 파싱 결과, 기존 새 18문항 검색·답변 기록을 점검했다. 외부 모델/API 호출 0회, 비용 USD 0이다. 이번 작업은 진단이며 런타임·기존 store·`.env`를 변경하지 않았다.

**원문 표를 보존하는 기능은 있지만, 표를 정확하게 잘라 검색하고 답변까지 사용하는 과정은 아직 충분하지 않다.** 정상적인 병합 셀·명시적 헤더는 복원하지만, 넓은 표의 축 대응과 일부 구조화 기록에서 재현 가능한 결함이 남아 있다. 이와 별개로, 정확한 표가 전달돼도 모델이 열이나 기간을 잘못 읽었던 실제 답변이 있다.

## 단계별 판정

| 단계 | 현재 확인된 상태 | 판정의 범위 |
|---|---|---|
| XML과 셀 복원 | 정상 ROWSPAN/COLSPAN·명시적 다중 THEAD 대조 통과. U03의 빈 첫 헤더와 지역별 금액도 원문대로 보존 | 모든 DART 표의 정확성 인증은 아님 |
| 표제·기간 연결 | v7이 확인된 다음 표제를 해당 값 표로 옮김. 3개 원문 4,424블록·3,234표의 기존 내용/구조 유지 | 이전에 잘못 추론한 메타데이터도 그대로 유지될 수 있음 |
| 표 청킹 | 넓은 표의 후속 조각에서 행 라벨이 빠지고, 빈 첫 헤더가 있으면 열 위치도 어긋남 | 현행 코드와 실제 HD 원문 산출물에서 확인 |
| 구조화 값·기간·단위 | 헤더 없는 값 표의 기록 누락, 기간명 중복 판정, 행별 단위 미반영이 존재 | 원문 본문 손실과 구분해야 함 |
| 검색 | 고정 top8에서 필수 근거 26/33, top12에서 27/33. U16 당기 현금은 RRF 17위 | 기존 v6 검색 기록이며 v7 새 검색은 미실행 |
| 답변 생성 | 평문 표와 일부 context를 전달. 형식·출처 ID만 검사하며 행열 연결·기간·단위·산술은 검증하지 않음 | 정확한 입력이 있어도 실제 오독이 관측됨 |
| 현재 store 적용 | 코드 v7, 기존 앱 store v5, 새 18문항 평가 store v6 | 두 manifest 모두 현재 계약으로 mismatch/ready=false. 실행 중 서버 상태를 관측한 것은 아님 |

[직전 표제 수정](new18_table_prefix_preservation_fix.md)의 3,645개 청크 보존과 전체 2,192개 테스트 통과는 해당 변경의 회귀 검사다. 표의 모든 의미가 정확하다는 결론은 아니며, 아래 결함은 그 검사와 양립한다.

## 새로 확인한 현행 결함

### 넓은 표에서 행 이름과 열 위치가 유지되지 않음

[열 분할](../../src/processing/chunking.py)은 원본 grid 대신 `" | "`로 다시 나눈 문자열을 `cells[start:end]`로 자른다. 두 번째 열 창부터는 앞쪽 행 이름 열을 반복하지 않는다. 회사·질문과 무관한 41열 예제에서 `Alpha / 1…40`은 후속 조각에 `22…40`만 남는다.

첫 헤더 셀이 비어 있으면 [전체 텍스트 정규화](../../src/processing/financial_parser.py)의 `.strip()` 때문에 `" | C01"`이 `"| C01"`이 된다. 이 문자열을 다시 나눌 때 첫 빈 셀을 잃는다. 실제 `_collect_blocks → _chunk_blocks` 경로에서 **후속 조각의 헤더는 C23…C40, 값은 22…40**으로 어긋났다. 원본 grid는 41열로 보존돼 있으므로 손상 위치는 문자열 기반 청킹이다.

실제 HD 원문의 28열 지급보증 표에서도 같은 경계가 보인다. 청크 `1052:453`은 통화별 네 행의 이름 없이 숫자 행만 남고, 첫 헤더는 5셀, 숫자 행은 6셀이다. 전체 `table_object_json`과 헤더 metadata에는 원본 축이 남지만, 기본 생성 경로는 전체 구조화 레코드를 보내지 않는다. 행 라벨 목록 prefix도 각 숫자 행과 직접 결합되지 않는다.

해당 표의 세 조각 `1050:451`, `1051:452`, `1052:453`은 **저장된 622개 후보에 하나도 없다.** 따라서 이 결함을 최근 U03·U16 오답의 원인으로 해석하지 않는다. 기존 새 18문항으로 검증하지 못한 일반적인 청킹 결함이다.

### 헤더 없는 한 행짜리 값 표가 구조화 기록에서 사라짐

[헤더 추론](../../src/processing/table_records.py)은 명시적 헤더가 없으면 최소 한 행을 헤더로 잡는다. 호텔신라 원문의 “보통주식수 전환가능상품(교환사채)의 잠재적 효과 | 2,135,000” 표 두 곳에서 유일한 값 행 전체가 `header_rows`로 들어가고 `rows=[]`, `values=[]`가 된다.

원문 32502행 (`../../benchmarks/results/new_report_user_eval_2026-10-15/sources/20260311004398/original.xml#L32502`, local artifact not included)과 60104행의 표를 현행 코드로 다시 읽어 동일한 결과를 확인했다. 숫자와 문장은 청크 본문에 남는다. 따라서 원문 삭제가 아니라 **구조화 값 기록의 누락**이다. 이 두 표에 관한 답변 오류는 이번에 평가하지 않았다.

### 단일 상대 기간을 여러 기간으로 표시함

`extract_period_labels`는 부분 문자열을 각각 찾는다. `당기말`은 `당기`와 `당기말`, `전전기말`은 `전기·전전기·전기말·전전기말`로 추출된다. 이어서 `_infer_period_focus`는 라벨이 두 개 이상이면 `multi_period`로 정한다.

저장된 3개 원문에서 이런 상대 기간 중첩만으로 `multi_period`가 된 표는 **56개**다. 구성은 추가 검사 기록 (`../../benchmarks/results/table_handling_audit_2026-10-16/extended_checks.json`, local artifact not included)에 있다. 이는 56개 답변 오류가 아니라 메타데이터의 잘못된 분류다. 원문 기간 문자열은 남는다. v7 표제 연결은 이 기존 추론을 바꾸지 않았다.

### 표 전체 단위가 행별 단위에도 일괄 복사됨

HD 지급보증 표의 직전 원문 표제에는 `(단위 : 백만원)`이 있지만, 값 행에는 각각 `(천USD)`, `(천CNY)`, `(천NOK)`, `(천EUR)`가 명시돼 있다. 현행 재파싱에서 USD 36,000, CNY 156,000, NOK 143,747, EUR 48,000의 `cell.unit_hint`는 모두 `백만원`이다.

다른 표의 단위가 잘못 넘어온 것으로 확인된 사례는 아니다. **원문의 표 단위와 행별 단위가 혼재하는데, 구조화 기록은 표 단위만 모든 셀에 복사한다.** 원문 행 단위를 함께 읽어야 하지만 위 넓은 표 후속 조각에서는 행 이름도 빠진다. 이 조합이 오답을 만들 가능성은 있으나, 실제 답변 영향은 아직 측정하지 않았다.

## 구조를 저장하는 것과 모델에 전달하는 것은 다름

[SimpleRagAgent](../../src/agent/simple_rag.py)는 저장된 `page_content`와 [허용 context 필드](../../src/config/simple_rag.py)를 전달한다. 전체 `table_object_json`, 행·값 레코드, 셀별 열 연결, 원문 `source_contexts`는 별도 전달하지 않는다. 검색 입력의 값 요약은 주로 “행 라벨 + 값”이며 열 이름과의 대응을 담지 않는다. 본문 표와 헤더 context는 남으므로 열 정보 전체가 사라지는 것은 아니다.

이번 3,645개 청크 중 표 청크는 3,314개이고, 분할 표 청크는 251개다. 분할 251개 모두 전체 헤더 context와 table object를 갖는다. 이는 다중 헤더 전체가 삭제됐다는 주장과는 맞지 않는다. 표 청크의 `unit_hint`는 2,353개에 있지만 `unit` 키는 없어, 이 corpus에서는 생성 context의 `unit` 필드가 비어 있고 prefix·본문·표제에 단위 전달을 의존한다.

U03은 내부 값 기록에 `북미 → 1,611,950백만원`이 정확히 있고 실제 전송 표도 올바랐다. 그런데 기존 12개 문맥 첫 답변은 북미·아시아·유럽 금액을 바꿔 연결했다. 동일한 전송 본문의 두 번째 답변은 정확했다. 이는 [원문 추적](new18_u03_u16_regression_diagnosis.md)으로 확인한 생성 오류다.

U16은 전기말 현금 표 뒤에 다음 당기말 표제가 붙었던 청킹 결함을 v7에서 수정했다. 기존 v6 저장 검색에서는 당기 현금이 RRF 17위로 제외됐고 1년 리스 근거가 빠져 있었다. v7의 새 검색 결과는 미평가이므로 표제 수정이 그 근거까지 복구했다고 볼 수 없다. 기존 [8개와 12개 답변 비교](new18_rrf_window_answer_result.md)는 엄격 통과 23/36→24/36, 두 번 모두 통과한 문항 11/18→11/18이며, U03·U16 정확도 회귀가 있었다. v7 이후의 답변 품질 결과로 대체하지 않는다.

## 다음 작업의 우선순위

1. **넓은 표 분할을 먼저 바로잡는다.** 원본 grid와 열 좌표를 기준으로 자르고, 각 조각에 필요한 행 축·해당 열 헤더·빈 셀·값이 함께 남는 계약을 검증한다. 문자 기반 재분할 경계의 재현 결함이므로 모델 호출 없이 확인할 수 있다.
2. **헤더 없는 값 표의 기록 누락을 별도로 수정한다.** “첫 행은 반드시 헤더”라는 가정을 없애되, 실제 표제와 다중 헤더를 값으로 잘못 만드는 회귀를 함께 확인한다. 기간 중복 판정과 단위의 선언 위치 보존도 각각 독립된 변경으로 다룬다.
3. **안정화된 셀·축 연결만 생성 입력에 명시하는 비교를 준비한다.** 검증된 행·열·값·기간·단위 관계를 드러내는 표현은 후보가 될 수 있다. 현행 구조화 기록을 무검증으로 모두 노출하는 것은 위 결함도 함께 전달하므로 우선하지 않는다. 답변 개선 여부는 동일 검색 결과를 사용한 별도 대조가 필요하다.

현재 확인된 결함은 후보 수·RRF 가중치·reasoning effort만 바꿔 해결되는 종류가 아니다. 기본 RRF·문맥 8개는 유지하며, 이 진단에서 재색인·모델 비교·자동 Compiler 연결은 수행하지 않았다.

## 검증과 보존

진단 묶음 (`../../benchmarks/results/table_handling_audit_2026-10-16/`, local artifact not included)에 generic 대조, 현행 전체 청킹 경로, 원본 XML 위치·해시, 실제 파싱 산출물, 후보 노출 여부를 저장했다. 관측 기록 (`../../benchmarks/results/table_handling_audit_2026-10-16/observations.json`, local artifact not included)의 기간 세트 54개는 `당기말·전기말·전전기말` 범위이고, 추가 검사는 `전전기` 중첩 2개까지 포함해 총 56개다.

이번 관련 테스트는 **56개 통과**, 실패·오류·skip 0개다. 결과 (`../../benchmarks/results/table_handling_audit_2026-10-16/focused_tests.json`, local artifact not included)의 외부 네트워크 시도도 0개다. 기존 전체 2,192개 검사는 직전 수정의 결과이며 이번에 다시 실행하지 않았다. 현재 파서 네 파일의 해시가 직전 3,645개 전체 재현에서 승인된 소스와 일치함을 확인했다.

최종 보존 검사 (`../../benchmarks/results/table_handling_audit_2026-10-16/closeout.json`, local artifact not included)는 기존 소스·문서·원문·과거 실험·store·`.env`를 포함한 2,571개 파일의 전후 해시를 비교한다. DB를 열거나 재구축하지 않았다. 새 진단 파일과 이 보고서만 추가했다. 새 답변 생성, 새 검색 순위, 일반 DART 정확도는 이번 평가 범위가 아니다.
