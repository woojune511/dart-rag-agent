# U08 법인 국가 근거의 검색 후보 누락 원인

상태: **COMPLETE_OFFLINE_CANDIDATE_DIAGNOSIS** · 2026-10-17 · 추가 외부 호출 0회, USD0.

U08의 관계 근거는 원문·v9 청크·색인에 남아 있고 검색 범위도 통과한다. 누락의 직접
원인은 **Dense의 낮은 관련도 순위와 BM25의 질문·문서 어휘 불일치**다. BM25는 질문의
“나라”와 표의 “소재지”를 연결하지 못하고, “한국”을 회계정책의 “한국채택국제회계기준”에도
매칭한다. 필터 누락, 벡터와 문서의 혼선, 임베딩 입력 잘림, 근사 검색의 상위 후보 누락은
이번 U08 기록에서 확인되지 않았다. RRF에 들어오기 전부터 관계 표가 후보에 없다.

가장 작은 후속 실험안은 **원질문과 Dense는 유지하고 BM25에만 국가·소재지 검색어를
보완하는 선택적 정책**이다. 한 번의 고정된 오프라인 대조에서 관계 근거 3개가 BM25
24개 안으로 들어왔고, 가장 높은 근거는 RRF 10위였다. 문맥 12개에는 들어가지만
8개에는 여전히 빠진다. 실제 답변 개선과 새 18문항의 회귀는 이번 분석에서 평가하지 않았다.

## 재현한 조건과 실제 순위

질문은 “한국 말고 어느 나라에서 매출을 많이 내고 있어? 나라별 규모도 알려줘.”다.
동결된 v9 전체 3,645개 문서와 저장 문서·질문 벡터를 사용했다. 회사·접수번호·
보고서 종류·연도를 제한하면 오리온 문서 1,092개가 남는다. 아래 순위는 이 범위 안에서
계산했으며, 모든 관계 근거가 같은 범위 검사를 통과했다.

| 청크 | 관계 근거의 종류 | 정확한 Dense 순위 | BM25 순위 | BM25 점수 |
|---|---|---:|---:|---:|
| 73:20 | 공장 소재지, Euro Co., Ltd. 표기 | 84 | 0점으로 제외 | 0 |
| 124:0 | 연결주석의 LLC 소재지·재무현황 | 211 | 104 | 4.141663 |
| 126:2 | LLC 회사명·소재지의 구분된 행 | 304 | 757 | 2.091160 |
| 592:60 | 별도주석의 LLC 투자·소재지 | 389 | 709 | 2.259582 |
| 593:61 | LLC 회사명·소재지의 구분된 행 | 751 | 701 | 2.275555 |

청크 ID 앞의 보고서 번호는 모두 `20260318001320`이다. 공장 표의 Co., Ltd.와
LLC의 동일성을 여기서 추정하지 않았다. 정확한 LLC 명칭의 소재지 행은 나머지 네 청크에서
확인된다. 0점 문서 사이의 안정 정렬 순서는 관련도 차이를 뜻하지 않는다.

Dense는 저장 float32 벡터의 L2 제곱 거리를 전체 범위에서 다시 계산했다.
그 상위 16개 ID·순서는 실제 HNSW 결과와 모두 같고, 거리 오차는 최대 약 0.00000125다.
16위 경계 거리는 1.267739이며 가장 가까운 LLC 근거 `124:0`은 1.460829다.
16개를 24개나 32개로 늘리는 정도로는 이 근거에 도달하지 않는다.

BM25도 당시 전체 코퍼스에 `BM25Okapi(k1=1.5, b=0.75, epsilon=0.25)`를 적용해
상위 24개 ID·순서·점수를 재현했다. 24위 경계는 7.109734다. 보고서 필터는
점수 계산 후 후보를 고르기 전에 적용되며, 필터 밖 문서가 후보 예산을 차지한 경우가 아니다.
IDF 통계의 모집단은 전체 3,645개다.

## BM25에서 확인된 원인

[tokenize_ko](../../src/storage/bm25_index.py)는 한국어 문자 bigram을 사용한다.
질문의 “나라에서”는 `나라 / 라에 / 에서`, “나라별”은 `나라 / 라별`로 나뉜다.
**나라·라별은 전체 색인 문서에서 빈도 0**이므로 핵심 국가 구분 의도가 점수에 기여하지 못한다.
원문 관계 표의 `소재지`는 `소재 / 재지`이고, 실제 값은 러시아·베트남 등이다.
기본 검색에는 이 어휘를 이어주는 확장이나 법인명을 이용한 보조 조회가 없다.

반면 질문의 “한국 말고”에서 `한국`은 양의 검색 단어이고 `말고`는 매칭이 없다.
“한국”은 한국 매출 제외라는 의미와 무관하게 회계기준 명칭 안에서도 일치한다.
이것은 문자 BM25의 의미·부정 처리 한계이며, 한국을 전역 불용어로 제거할 근거는 아니다.

| 문서 | BM25 순위·총점 | 주요 점수 기여 |
|---|---|---|
| 136:12 회계정책 관련 청크 | 3위·13.7050 | 한국 4.9502, 있어 4.2107, 에서 2.4698, 매출 2.0743 |
| 533:1 별도 회계정책 | 5위·10.8567 | 한국 5.0775, 있어 3.1037, 에서 1.6377, 매출 1.0378 |
| 126:2 회사명·소재지 표 | 757위·2.0912 | 매출만 2.0912 |

`136:12`의 한국 3회와 있어 1회는 검색 입력 앞부분의 표 설명 복사에서,
매출 2회는 공통 키워드 줄에서 나온다. `126:2`의 매출 3회는 본문 1회와
공통 키워드 줄 2회다. `매출`은 3,645개 중 2,738개 문서에 등장하며,
구현의 음수 IDF 보정으로 양의 가중치를 받는다. 원문 표보다 일반적인 회계 설명이
질문의 여러 단편과 더 많이 겹쳐 높은 점수를 받는 구조가 실제 점수에서 확인된다.

길이 보정도 기여한다. 평균 길이는 약 330토큰인데 `124:0`·`592:60`은
각각 1,146·1,197토큰이다. 다만 길이 보정만 없애도 관계 근거는 후보에 들지 않았다.

## Dense에서 확인한 사실과 추정

문서 벡터가 잘못 붙거나 입력이 잘린 것은 아니다. 관계 청크 5개와 U08 질문에 대해
실제 과거 임베딩 요청의 token-array 해시·전체 텍스트 해시를 동결 준비 기록과
대조했고, 실제 응답 벡터가 저장 numpy 배열과 일치하는지도 확인했다.
범위 내 모든 벡터의 정확한 순위와 실제 Dense16이 일치하므로 **이 사례의 원인을
HNSW가 더 가까운 관계 표를 놓친 것으로 설명할 수 없다.**

검색 단위의 내용에는 개선 여지가 보인다. `126:2`는 할인율·CAPM·민감도 설명으로
시작한 뒤 회사명·소재지 표와 재무현황을 함께 담는다. `593:61`도 인도 투자
손상평가 설명 뒤에 소재지 표가 나온다. 두 청크의 metadata 표제도 각각 일반 연결주석
설명과 종속기업투자 설명이다. 관계 행은 보존됐지만 매출 질문에 필요한 관계만
집중해서 표현한 검색 단위는 아니다.

이런 주제 혼합과 일반 표제, 영어 법인명, 질문에 법인명·소재지 표현이 없는 점이
Dense의 낮은 관련도에 기여했을 가능성은 있다. **각 요소의 인과 효과는 추정**이다.
문장이나 접두어를 바꾼 새 임베딩을 만들지 않았으므로, 청킹 또는 임베딩 모델 중
어느 하나만의 원인이라고 결론 내리지 않는다.

## 고정한 세 가지 오프라인 진단 대조

점수를 계산하기 전에 세 조건을 `probe_protocol.json`에 고정했다. 같은 문서,
질문, 범위에서 각각 한 항목만 바꿨고 Dense16·BM25-24·RRF60은 유지했다.
기존 실패를 본 뒤 설계한 U08 진단이므로 독립 검증 성과로 해석하지 않는다.

| 조건 | 관계 근거의 BM25 후보 포함 | 해석 |
|---|---|---|
| 길이 보정만 b=0 | 0개, 가장 높은 LLC 근거 104→33위 | 길이 영향은 있지만 단독 원인은 아님 |
| 모든 문서의 `[키워드: ...]` 줄만 제거 | 0개 | 이 공통 줄 제거만으로는 해결되지 않음. Dense 접두어 효과는 미측정 |
| BM25 질문 끝에 정확히 `국가 소재지` 추가 | 3개 | 원문 열 이름과의 어휘 연결로 후보가 복구됨 |

마지막 조건의 결과는 다음과 같다.

| 관계 근거 | 기존 BM25 | 변경 BM25 | 변경 RRF |
|---|---:|---:|---:|
| 126:2 | 757 | 11 | 22 |
| 592:60 | 709 | 19 | 35 |
| 593:61 | 701 | 5 | 10 |

국가·소재지 말고 회사명, 러시아, 법인명, 청크 ID, 정답 숫자는 검색어에 넣지 않았다.
연결 지역별 수익 표 `161:37`도 RRF 6위에 들어오지만, 전기 표 `162:38`과
본점 주소 `13:0`도 함께 올라온다. 후보 복구와 불필요한 자료 유입을 함께 봐야 한다.

같은 답변 입력 형식으로 투영한 문맥은 8개 25,979 bytes, 12개 33,826 bytes이며
65,536-byte 한도 안에서 생략이 없다. LLC–러시아 행은 12개에서만 전달된다.
이 입력은 저장만 했으며 답변 생성에는 전송하지 않았다. 기존 U08 필수 근거의 완전성이나
새 18문항 전체 회귀를 새로 판정한 결과도 아니다.

## 제안하는 최소 변경과 채택 조건

**먼저 실험할 변경은 BM25 전용의 선택적 어휘 보완이다.**
`나라→국가`는 개념 별칭, `소재지`는 관련 원문 열의 검색 힌트로 분리해 선언한다.
소재지를 고객의 매출 발생 국가와 동의어로 처리하지 않는다.
한 질문에서 해당 개념이 반복돼도 보완어는 한 번만 붙인다. 이번 진단의 정확한
lexical query는 원질문 뒤에 `국가 소재지`를 한 번 붙인 문자열이다.
회사·국가·평가 ID를 runtime 분기에 넣거나 Euro–러시아 관계를 생성해서 붙이지 않는다.

구현 범위는 다음으로 제한할 수 있다.

1. `src/config/retrieval_policy.py`에 검토 가능한 개념 별칭과 관련 열 힌트를 둔다.
2. `VectorStoreManager.search`에서 선택적 정책을 받은 경우에만 일반적인 별칭
   확장 함수를 적용하고, `collect_bm25_results`에 보완한 검색어를 전달한다.
   Dense와 답변에는 원질문을 그대로 사용한다. 추가 API나 임베딩, store 재구축은 필요 없다.
3. 실제 lexical query와 policy ID를 검색 trace에 기록하고, 검색 캐시 키에도 유효
   검색어·정책 버전을 반영한다. 원문 본문·metadata·출처 ID는 바꾸지 않는다.

이것은 **후보 복구용 최소 변경안**이다. 현재 RRF에서 8개만 전달하면 해당 관계 근거는
계속 빠진다. 8개 고정까지 해결하려면 관계 근거의 포함을 고려하는 선택 방법을 별도로
검증해야 하며, 이번에 가중치·강제 삽입·행 축약을 추가하지 않았다.

채택 전에는 새 18문항 전체의 필수 근거와 기존 출처 보존을 오프라인으로 비교하고,
다른 문서의 자연스러운 국가 질문, 부정 표현, 고객 지역과 법인 소재지가 다른 질문을
함께 확인해야 한다. 의미가 비슷하다는 이유로 소재지를 매출 지역으로 단정하거나,
연결 지역별 수익과 개별 법인 매출을 합치면 실패로 판정한다. 실제 답변 비교는 별도 단계다.

## 산출물과 보존

로컬 경로: `benchmarks/results/new18_v9_u08_candidate_diagnosis_2026-10-17/`.

- `baseline_reconstruction.json`: 범위 내 1,092개 전체 순위, 점수·토큰별 기여와 입력 해시.
- `embedding_input_audit.json`: 실제 과거 요청·응답과 대상 벡터 6개의 연결 검증.
- `probe_protocol.json`·`diagnostic_probe_results.json`: 세 조건과 후보·RRF 변화.
- `proposal_context_projections.json`: 전송하지 않은 8개·12개 원문 문맥.
- `diagnosis.json`: 확인 사실·추정·최소 변경 제안 및 미실행 평가.
- `closeout.json`: 기존 파일·store·환경 보존 검사와 최종 산출물 해시.

현재 runtime 코드는 변경하지 않았다. 기존 실험 결과와 store 6개·56파일,
`.env`는 해시로 보존하며 현재 상태 문서 두 곳에 분석 결과와 링크를 반영한다.
