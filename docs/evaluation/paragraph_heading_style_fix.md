# 문단 서식의 소제목 보존 수정

2026-09-29 · **CODE_VERIFIED_STORE_REBUILD_PENDING**

NAVER 직원 현황 주석에 이전 소제목이 붙은 원인은 일반 문단 파서가 `P` 자체의
제목 서식을 읽지 않은 것이었다. 해당 원문을 다시 파싱하면
`라. 타회사 임원겸직 현황` 대신 **`마. 직원 등 현황`**이 직원 표와 주석에 연결된다.
현재 저장소를 고친 결과가 아니라 수정한 파서와 테스트 경로의 결과다.

## 원인과 최종 수정

원문은 다음처럼 제목을 `P`의 직접 텍스트에 넣고 본문을 자식 `SPAN`에 넣는다.

```xml
<P USERMARK=" B">마. 직원 등 현황
  <SPAN USERMARK=" !B">공시대상기간 중 ...</SPAN>
</P>
```

`FinancialParser._extract_plain_heading_parts()`는 문단 전체 또는 일부 `SPAN`만
제목 후보로 보았다. 제목과 본문이 섞인 문단 전체는 제목 조건을 통과하지 못했고,
`P`의 직접 텍스트에 붙은 `B`는 읽지 않아 이전 제목 스택이 계속 적용됐다.
검색기나 답변 모델이 이전 요청 상태를 보관한 버그가 아니다.

최종 변경은 이 함수의 **문단 서식 누락**에 한정한다.

- `P.USERMARK`의 명시적 `B`/`!B` 토큰을 순서대로 읽는다.
- 굵은 문단의 직접 텍스트, 서식을 상속받는 자식 `SPAN`, 부모에 속하는 tail을 제목 후보로 읽는다.
- 같은 위치에 이미 인식된 제목이 있으면 문단 서식 후보로 덮어쓰지 않는다.
- 원문 본문을 삭제하거나 숫자·회사·문항별 분기를 추가하지 않는다. 원문 XPath와 문자 범위를 보존한다.

기존 `SPAN` 후보 판정은 유지했다. 특히 기존의 `"B" in USERMARK` 규칙은 `!B`나
일부 글꼴 이름도 후보로 취급할 수 있어, 정확한 굵기 판정과 동일하지 않다.
이 규칙까지 제거하는 안은 다른 보고서의 기존 제목을 놓쳤고, 일반 줄바꿈이나
독립 `SPAN`을 모두 제목 경계로 보는 안은 잘린 본문 참조를 제목으로 잘못 인식했다.
이 넓은 후보들은 채택하지 않았다. 진단 코드·결과·테스트를 산출물에 보존했으며,
최종 코드가 모든 서식/제목 경계 문제를 해결했다고 주장하지 않는다.

## 최종 검증

| 검증 | 결과 |
|---|---|
| 전체 unittest | **2,163 통과**, 74.19초 |

| 최종 새 테스트의 수정 전 코드 대조 | 9개 중 5개 실패, 오류0; 실제로 이전 동작을 구별함 |

| 표 | 12,181개 표의 본문·격자·단위 동일 |
| 원문 제목 위치 | 24,308회 XPath/문자 구간 대응 확인; 의미 정확도 인증은 아님 |
| 대상 NAVER 주석 | 원문 주석·후속 chunk 모두 `마. 직원 등 현황` 확인 |

마지막 전달 테스트는 합성 문서와 임베딩·답변 stub을 사용한다. 실제 NAVER 원문 검사는
파싱과 chunk 단계에서 따로 수행했다. 실제 앱의 NAVER 재검색이나 새 모델 답변 평가로 표현하지 않는다.
표 소제목 변화는33개(NAVER13, POSCO12, SK이노베이션5, 카카오뱅크3)에서 관찰됐지만,
이를33개 오류 수정이나 전체 제목의 의미 검증으로 세지 않는다.
