# 공통 키워드 줄 제거 reranker 대조

2026-10-16 · `COMPLETE_SOURCE_GATE_NOT_MET` · 새 로컬 forward **622회**, 외부 API **0회 / $0**, 실행 **20분 39.6초**

**키워드 줄 제거는 원래 reranker보다 일부 근거를 복구했지만, 현재 RRF를 대체할 기준은 충족하지 못했다.** U08의 제한된 법인 매출 근거와 U09의 연결 이익 근거가 복구됐다. U14의 부문 손익은 여전히 빠졌다. HD 경영진단 핵심 근거와 원래 reranker의 충족 항목23개는 모두 보존됐다.

이 문서는 **최종8개 안의 필수 근거 가용성**을 비교한다. 답변 생성·정확도·필수 항목 누락·출처 충실도의 실제 답변 평가는 `NOT_RUN`이다. 기존 답변 점수와 U04의 넓은 질문에 대한 답변 판정U를 바꾸지 않는다. 세 보고서의 assistant 작성 질문18개를 같은 assistant가 비맹검으로 검토했으며, 독립 검토나 미노출 평가가 아니다.

## 단일 변경과 고정 조건

[이전 진단](new18_reranker_regression_diagnosis.md)에서 제안한 대로 **reranker의 Document 입력에서 생성된 `[키워드: …]` 한 줄과 바로 뒤 개행만 제거**했다. 622쌍 각각에서 나머지 문자가 같음을 검증했다. 회사·연도·섹션·표제·기간·단위·행/값 요약과 실제 본문은 그대로다. 따라서 이 결과는 전체 metadata 제거, 특정 재무 단어 하나의 제거, Dense/BM25 재색인의 결과가 아니다.

최종 근거 packet은 선택된 청크의 **원래 전체 text/context/source ID**를 사용한다. 검색·생성 문맥까지 수정하는 다른 변수를 섞지 않기 위해서다. 따라서 packet에 키워드 줄이 보이더라도 점수화 입력에는 그 줄이 없다. 실제 모델 입력은 `frozen_pairs.json`의 `ranking_document_text`·`model_body`·`input_ids`에 보존했다. manifest의 상속된 `input.document_projection` 설명은 원래 입력을 기술하며, 이번 변경은 최상위 `sole_scoring_input_change`와 `final_source_projection`에 명시되어 있다.

## 전체 비교

P는 해당 필수 근거 충족, F는 부족, U는 기존에 선언한 범위 해석 불확정이다. 문항 전체P는 그 문항의 모든 필수 그룹이P인 경우다. **답변 정답률이 아니다.**

| 방식 | 필수 그룹33개 | 모든 필수 근거가 있는 문항18개 |
|---|---:|---:|
| 현재 RRF | **26P / 7F** | **13P / 5F** |
| 원래 Qwen 입력 | **23P / 9F / 1U** | **12P / 5F / 1U** |
| 키워드 줄 제거 | **26P / 7F** | **13P / 5F** |

- **원래 reranker 대비:** 기존P **23/23 보존**, 신규P→F/U 없음. U08.2·U09.2는F→P, U03.2는U→P다. 기존 전체 충족 문항12/12를 보존했다.
- **현재 RRF 대비:** 기존P **24/26 보존**. U04.1·U16.1을 얻는 대신 **U14.1·U14.2를 잃는다**. 기존 전체 충족 문항은12/13 보존이며 U14가 탈락한다. 총합이 같다는 이유로 동등한 결과로 보지 않는다.
- 실행 전 고정한 기준인 네 회귀 항목 모두 복구·RRF 충족26개 모두 보존·최소27개 충족·전체 충족14문항을 만족하지 못했다. **원래 reranker 개선과 RRF 대체 가능성은 별개다.**

U03의 이전U를 별도 범위도 허용하여P로 보던 민감도 기준에서는 원래 reranker가24P/9F, 전체13P/5F였다. 그 기준으로도 이번26P/7F의 신규 개선은 U08.2·U09.2이며, U14 회귀와 기준 미충족은 같다. 과거 봉인 판정은 수정하지 않았다.

## 표제·접두어 원인에 관해 확인한 범위

순수 표제는 제목·기간·단위만 있고 본문 행이나 설명이 없는 청크로 한정했다.

|---|---:|---:|
| U08 | 0 | 0 |
| U09 | 1 | 0 |
| U14 | 0 | 0 |
| U15 | 4 | 4 |

U15에서는 부문 표제 `542:17`이 빠지는 대신 별도 사채의 날짜·단위 표제 `974:14`가 들어왔다. U03의 국내/해외 매출 표제와 U10의 환율 민감도 표제도 계속 선택된다. U04에는 새 값 없는 사채 표제 `1098:24`가8위에 들어왔다. 따라서 **키워드 제거가 표제 편중을 전반적으로 해결했다고 볼 수 없다.**

확인된 사실은 이 고정 설정에서 키워드 줄 제거 후 선택과 필수 근거 가용성이 일부 개선됐고, U14 및 여러 불필요한 자료의 높은 순위는 남았다는 것이다. 키워드 한 줄만으로 모든 실패를 설명할 수 없다. 앞선 진단의 전체 표 값 요약 상속, 혼합 단위 hint, 국가↔법인·면세↔TR처럼 분산된 축 연결은 이번에도 변경하지 않았다.

공통 단어가 모델의 주제 관련성 판단을 왜곡했을 수 있다는 설명은 U09 결과와 양립한다. 그러나 **개별 단어의 효과, 입력 길이 감소의 효과, 모델 크기·한국어 성능·instruction·표 처리 능력의 기여를 분리한 것은 아니다.** 원래 점수는 저장값이고 새 입력만1회 실행했으므로 반복 실행 변동도 측정하지 않았다. 다른 보고서·모델·답변 품질로 일반화하지 않는다.

## 실행·보존 및 결정

실행은9,000초 상한 중 **1,239.638초**, 감독된 추론 구간은1,231.658초였다. 실제 worker peak RSS는4,000,567,296bytes(약3.73GiB)로8GiB 미만이다. 모델 실행 전 실제 worker PID의 시간·메모리 감독을 연결했고, 모델 없는2초 종료 probe로 감독 경로를 확인했다. 완료 후 worker 종료도 확인했다. 모델 가중치 재다운로드·외부 모델 API·검색·임베딩·답변 생성·judge·추가 forward·재시도는 모두0회다.

후처리 검증에서 새 읽기 전용 보조 파일 `inspect.py`가 Python 표준 모듈과 이름이 겹쳐 import에 실패했다. `review_saved_sources.py`로 이름을 바꾼 뒤 검증을 완료했다. 모델 로드 후 작성된 보조 파일이며, 실패는 추론 완료 후 발생했다. 고정 inference 코드·입력·점수는 수정하지 않았고 **모델 재실행도 없었다**.

실행 종료 시 보호 파일 **1,802개 전부의 SHA256이 일치**했다. 최종 정리에서는 `CONTEXT.md`와 `docs/overview/project_status.md`의 현재 상태 문단·갱신 날짜만 바꾸고 나머지1,800개를 보존한다. 기존 store·별도 평가 store·`.env`·원본 XML·기존 실험·사용자 소스 변경을 유지한다. 앱의 기존 v5 store/v6 parser manifest 불일치 상태도 바꾸지 않는다. 새 기록은 별도 ignored 디렉터리에 두며 stage·commit·push하지 않는다.

**현재 RRF와 runtime을 유지한다.** 이 실험은 접두어 한 줄이 선택 실패의 일부에 기여할 수 있음을 확인했지만, U14를 보존하면서 전체 필수 근거를 늘리는 대안은 되지 못했다. 추가 입력 수정·모델 실행·답변 생성·runtime 채택은 하지 않았다.
