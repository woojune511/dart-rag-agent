# 일반 텍스트 청킹과 DART 문서 처리: 10문항 파일럿

2026-10-21. **완전 정답은 두 방식 모두 6/8(75%)이며, 두 번째 반복에서도 같았다.** DART 처리는 삼성전기 재고자산 문항을 개선했지만 같은 회사의 취득 현금지출 문항에서 회귀했다. 전체 정확도 우위는 확인하지 못했다. 총 API 사용량 기준 추정 비용은 **$0.80021666**이다.

## 비교 조건과 범위

동일한 원본 보고서, 질문, Sol 6.1 low, 답변 프롬프트·스키마, 임베딩 모델, 검색 알고리즘, 문맥 상한을 사용했다. 변경한 것은 원문을 검색·답변용 청크로 만드는 처리 방식이다.

| 조건 | 일반 텍스트 방식 | DART 처리 방식 |
|---|---|---|
| 원문 처리 | lxml HTML의 텍스트 노드 추출, 공백 정리 | 현재 로컬 v12 FinancialParser |
| 청킹 | recursive 2,500자 / overlap 320자 | canonical structural selective v2, 2,500/320 설정 |
| 검색·답변용 정보 | 본문과 공통 보고서 메타데이터 | 표·절 구조, 단위·기간·제목 문맥과 기존 prefix |
| 전체 청크 | 338 | 2,242 |
| 공통 검색 | exact L2 Dense top-24 + 양수 BM25 top-24, RRF60 → top-12 | 동일 |
| 공통 문맥 상한 | 65,536 bytes 및 전체 요청의 cl100k 기준 12,000토큰 | 동일 |
| 모델 | `gpt-6.1-sol`, reasoning low, max output 8,192 | 동일 |
| 전달 청크 평균 | 4.5개 | 9.6개 |
| 실제 API 입력 평균 | 7,650.3토큰 | 8,054.1토큰 |

`text-embedding-3-large`, 3,072차원으로 두 코퍼스를 각각 임베딩했다. 질문 임베딩은 두 방식이 공유한다. 보고서 범위는 명시적 접수번호로 고정했다. 질문 재작성·분해·reranker·Compiler는 사용하지 않았다.

문맥 상한을 넘는 청크는 통째로 제외했다. 따라서 top-12 검색을 했다고 12개 청크가 모두 전달되지는 않는다. cl100k는 공통 예산용 대리 토크나이저이고 실제 Sol 토큰 수와 같지 않다. 같은 상한을 적용했지만 실제 입력 토큰 수까지 동일하게 맞춘 실험은 아니다.

제품 앱의 설정은 변경하지 않았다. 이 비교는 동일한 기존 답변 지시문과 `RagAnswer`를 쓰는 별도 Responses API 하네스에서 실행했다. 현재 앱 전체의 배포 검증이나 기존 77문항 결과의 재현은 아니다.

## 자료와 사전 고정

- [농심 2025 사업보고서](https://dart.fss.or.kr/dsaf001/main.do?rcpNo=20260311003892): 기존 reader 실험에서 사용한 보고서다. 신규 holdout으로 보지 않는다. 일부 문항 주제도 기존 평가와 겹친다.
- [삼성전기 2025 사업보고서](https://dart.fss.or.kr/dsaf001/main.do?rcpNo=20260310003071): 확인한 기존 데이터셋·수집 manifest에서 같은 보고서 사용 이력을 찾지 못했다. 모델 학습 미노출을 뜻하지 않는다.

처음에는 새 회사 두 곳을 생각했으나 선정 후 기존 기록 확인에서 농심의 노출 이력을 발견했다. 원문 확인 후 회사를 교체하지 않는 규칙에 따라 농심은 그대로 유지하고, 기존 보고서 재평가와 신규 보고서 평가를 구분했다.

회사·질문은 원문 검토 전 `selection_lock.json`, `question_seed.json`으로 고정했다. 정답은 원본 XML의 수치와 보고서의 연결 재무제표·사업 설명을 확인하여 작성했다. 검색·모델 호출 전 `rubric.json`과 소스·코퍼스·실행 코드 174개 파일의 해시를 `freeze.json`에 고정했다. 원본 XML에 전사한 정답 숫자가 존재하는지 검사했고, 결과 생성 후 입력 해시가 유지되는지 재검사했다.

회사별 수치·계산 3문항, 서술형 1문항, 일별 매출을 요구하는 유보 대조군 1문항이다. **정답형 8문항과 유보 대조군 2문항을 분리**한다. 방식별로 2회씩, 총 40회 답변을 생성했다. 각 질문에서 1회차는 일반→DART, 2회차는 DART→일반 순서다. 반복할 때는 검색 결과와 전달 packet을 고정했다. 반복 실행을 독립된 새 질문으로 세지 않는다.

수치 문항은 필요한 두 피연산자·기간·연결 범위·단위와 계산 결과를 모두 요구했다. 원문의 표시 정밀도에 맞는 단위 변환·반올림을 허용했다. 서술형은 사전에 정한 사업 구분과 대표 제품을 모두 요구하고 선택 정보의 오류도 확인했다. 기준을 만든 assistant가 직접 채점했으므로 독립·블라인드 평가는 아니다.

## 개선과 회귀의 근거

### 삼성전기 재고자산: 필요한 분모가 전달됨

일반 방식은 재고자산 2,412,997백만원과 반올림된 구성비율 16.5%를 받았으나 자산총계가 없어 정확한 계산을 유보했다. 원문과 코퍼스에는 자산총계가 있었으며 `generic:18`은 Dense 8위·BM25 34위, 후보 병합 후 RRF 16위였다. top-12 밖이므로 전달되지 않았다.

DART의 요약연결재무정보 `97:0`은 Dense 6위·BM25 22위·RRF 6위로 전달됐다. 재고자산 **2,412,996,843,057원**, 자산총계 **14,595,895,255,468원**, 2025년 말·연결·원 단위 정보가 함께 들어 있었다. 두 답변 모두 **16.53%**를 계산했다.

### 삼성전기 현금지출: 필요한 표가 순위에서 밀림

일반 방식의 연결 현금흐름표 `generic:24`는 Dense 9위·BM25 20위·RRF 4위로 전달됐다. 두 답변 모두 유형자산 **1,192,112,995,578원**, 무형자산 **54,210,548,833원**, 합계 **1,246,323,544,411원**을 맞혔다.

DART 코퍼스에도 두 숫자를 가진 현금흐름표 `106:5`가 있었다. 하지만 Dense 263위·BM25 11위였고, 후보 병합 후 **RRF 22위**로 top-12에서 탈락했다. 최종 packet에는 주로 자산 변동 주석이 들어왔다. 모델은 ‘취득 및 자본적지출’을 현금지출로 바꾸어 쓰지 않고 두 번 모두 유보했다.

이는 이번 실행에서 **원문 파싱 소실이나 산술 오류가 아니라 최종 근거 선택 실패**로 확인된다. 다만 DART 표현의 어떤 부분이 순위를 바꿨는지는 이 두 조건만으로 분리할 수 없다. 청크 경계·표 표현·제목·정책 prefix·메타데이터가 함께 달라졌다.

### 공통 실패: 농심 현금지출

정답은 유형자산 **67,592,589,702원**, 무형자산 **262,618,117원**, 합계 **67,855,207,819원**이다. 일반 코퍼스의 `generic:27`은 Dense 28위·BM25 44위로 후보에 들지 못했다. DART의 `104:6`은 BM25 18위로 후보에는 들어왔으나 RRF 31위로 탈락했다. 두 방식 모두 올바른 현금흐름표를 보유했지만 최종 답변에 전달하지 못했다.

위 순위는 추가 API 호출 없이 저장된 임베딩과 동일 BM25·RRF를 재계산하여 확인했고, 기존 top-12와 일치하는지 검사했다. 숫자 문자열 존재 검사만으로 의미적 근거 충분성을 판정하지 않았다.

답변 생성비는 DART가 약 **6.2%** 높았고, 코퍼스 구축까지 포함한 이번 작은 실행에서는 약 **39.1%** 높았다. DART 코퍼스 임베딩 비용은 약 **2.27배**였다. 전체 실행은 임베딩 45회·답변 40회, 약 317초였다. 오류·재시도·모델 대체는 없었다. 평균 답변 호출 시간은 일반 6.03초, DART 6.55초다.

두 번째 반복은 같은 packet의 prompt cache를 사용했다. 일반 생성비는 1회차 $0.213643 / 2회차 $0.029347, DART는 $0.225548 / $0.032471이었다. 따라서 전체 평균을 새로운 질문 한 건의 비용으로 일반화하지 않는다. 구축비도 질문 수에 따라 상각된다.

실제 응답의 입력·출력·cache read/write 사용량에 [공식 API 가격](https://developers.openai.com/api/docs/pricing)을 적용한 추정치다. Sol standard의 100만 토큰당 입력 $2, cache read $0.10, 30분 cache write $2.50, 출력 $10 및 embedding-large $0.13을 사용했다. 청구서 대조 금액은 아니다.

## 해석과 남겨둔 자료

이번 결과는 **DART 구조·문맥을 보존하는 처리가 특정 표 질문에 도움을 줄 수 있지만, 더 나은 최종 검색을 보장하지는 않는다**는 사례다. 개선과 회귀가 상쇄됐으므로 ‘일반 RAG보다 정확하다’는 주장을 뒷받침하지 못한다. 두 회사의 작은 표본이고 농심은 기존 노출 자료다. 일반 방식도 가능한 여러 RAG 구현 중 하나이며, 이 비교를 일반 RAG 전체에 대한 우열로 확대하지 않는다. 구조 하나만의 인과 효과나 모집단 통계적 우위를 입증한 실험도 아니다.

실행 후 runtime·prompt·검색 규칙을 바꾸거나 재실험하지 않았다. 정답형 한 건의 개선을 근거로 제품 기본값을 변경하지 않았다. 실험 자료는 Git에서 제외되는 이 폴더에 보존했다.

- `selection_lock.json`, `pre_source_protocol.json`, `question_seed.json`: 원문 확인 전 선정과 설계.
- `acquisition.json`, `sources/`: 공식 원본 및 해시.
- `rubric.json`, `gold_source_excerpts.json`: 호출 전 채점 기준과 정답 근거.
- `freeze.json`, `preflight.json`: 코드·입력 고정 및 호출·비용 한도.
- `packets/`, `retrieval.json`, `rank_diagnosis.json`: 실제 문맥과 순위 추적.
- `live/`, `raw_seal.json`, `ledger.jsonl`: 실제 요청·응답·사용량, 원본 결과 봉인.
- `review/`, `judgements.json`, `arithmetic_review.json`, `summary.json`: 답변별 검토 근거와 집계.

사용한 소스는 HEAD `1d09627d8ec79ab29c337d31bcb1a4f5aae9251b`에 기존 로컬 v12 변경이 있는 상태다. GitHub main과 동일한 소스라고 주장하지 않는다. 정확한 소스 바이트는 `freeze.json`의 파일별 해시로 식별한다. 이번 작업은 제품 소스·기존 저장소·기존 실험 결과를 수정하지 않았다.
