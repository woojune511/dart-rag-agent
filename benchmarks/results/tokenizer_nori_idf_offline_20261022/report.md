## 고정한 조건과 바꾼 조건

| 조건 | 한국어 분석 | IDF |

원본 **16,051청크**, 질문, 명시적 보고서 범위, 저장된 **Dense 16개**, **BM25 최대 24개**, 동일 가중치 **RRF60**, **최종 12개**, 원문 전체 청크와 **65,536 UTF-8 바이트** 한도를 고정했다. 바이트 초과 시 해당 청크를 제외하고, 13위 이하에서 보충하지 않는다. 표 행 검색·캡션 확장·압축·질의 확장은 사용하지 않았다. 전체 코퍼스에서 IDF를 계산한 다음 기존 보고서 범위를 적용했다. 이 실험의 최종 12개는 앱 기본값 8개를 바꾸지 않는다.

Nori는 **Lucene 9.12.3 / MIXED**이며, 공백과 문장부호를 포함한 질문·청크 전체를 분석했다. `leftPOS`가 `E,J,SP,SSC,SSO,SC,SE`인 토큰만 제외하고 나머지 한글 형태를 보존했다. 기존 영어·숫자 분리 규칙과 출현 횟수는 유지했다. 사용자 사전·별칭·개별 금칙어는 없다. 이는 분절, 복합어 전개, 품사 필터가 함께 달라지는 **패키지 비교**다. 각 요소의 효과를 따로 분리한 실험은 아니다. [Nori tokenizer](https://lucene.apache.org/core/9_12_3/analysis/nori/org/apache/lucene/analysis/ko/KoreanTokenizer.html), [품사 필터 구현](https://raw.githubusercontent.com/apache/lucene/releases/lucene/9.12.3/lucene/analysis/nori/src/java/org/apache/lucene/analysis/ko/KoreanPartOfSpeechStopFilter.java).

양수 IDF는 `log1p((N-df+0.5)/(df+0.5))`로 고정했다. `k1=1.5`, `b=0.75`, 문서 길이·질문 토큰 중복 계산은 기존 방식이다. MIXED의 겹치는 토큰도 길이에 포함한다. **Lucene 전체 BM25 구현을 재현한 실험은 아니다**. [Lucene BM25Similarity](https://lucene.apache.org/core/9_12_3/core/org/apache/lucene/search/similarities/BM25Similarity.html).

분석기와 IDF만 교차한 설계는 [동결 프로토콜](protocol.json)과 실행 전 해시 (`seal.json`, local artifact not included)에 남겼다. 점수를 본 뒤 조건을 조정하거나 추가 조건을 실행하지 않았다.

## `매대` 문제에서 확인한 것

실제 질문은 **미국 시장 판매대수 증가와 IRA 등 보호무역주의 대응**이었다. 기존 bigram은 `판매대수`와 `판매대리` 양쪽에서 `매대`를 만들었다.

무관한 **금융상품판매대리·중개업** 청크 `20240313001451:46:6`은 A12에서 BM25 6위·RRF 9위로 문맥에 들어갔다. BM25 총점 **58.91 중 9.78**을 `매대`가 주었고, 단일 토큰 중 가장 큰 기여였다. N12에서는 `매대` 기여가 **0**, BM25 16위·RRF 27위가 되어 문맥에서 빠졌다. 실제 원인 후보를 점수 분해로 확인한 결과다. 다만 Nori가 여러 토큰을 함께 바꾸므로, 전체 순위 이동을 `매대` 하나의 단독 효과라고 하지는 않는다.

다른 금융상품·소비자보호 청크 `20240313001451:57:17`은 `매대` 기여가 사라져도 N12의 **RRF 4위**에 남았다. 저장된 **Dense 4위**였고 `보호·시장·성장·판매` 등의 겹침도 남았다. 따라서 잘못된 형태소 경계를 고쳐도, 다른 단어의 다의성과 Dense 후보를 RRF가 합치는 문제가 함께 남는다. 점수 분해 (`mechanism_diagnostics.json`, local artifact not included), `매대` 청크 대조 (`maedae_scoped_audit.json`, local artifact not included).

Nori가 의미를 보장하는 것도 아니다. 실제 전체 질문에서는 `판매/대수`가 나왔지만, 독립 입력 `판매대수의`는 `판매대/판매/대/수의`로 분석됐다. 반면 실제 진열대를 뜻하는 “상품을 매대에 놓았다”에서는 `매대`가 남았다. 금칙어 삭제로 만든 결과는 아니다. 합성 계약 검사 **7개 통과**는 경계·부정 표현·숫자·실행 계약의 제한된 확인이며, 모든 단어의 정답 분석을 뜻하지 않는다. 합성 입력 토큰 (`fixture_tokens.json`, local artifact not included), 검사 결과 (`contract_result.json`, local artifact not included).

IDF 문제도 구분해야 한다. 모든 16,051청크에 있는 `2023`은 현재 bigram IDF에서 **1.9737**, 양수 IDF에서 **0.000031**이었다. 반면 희소한 `매대`는 **5.8412→5.8441**로 거의 줄지 않았다. IDF 변경은 공통 접두어 가중치 문제를 완화하지만 잘못된 희소 토큰 자체를 알아보지 못한다. 양수식이 모든 흔한 토큰의 가중치를 낮추는 것도 아니다. Nori의 `하`는 **0.0383→0.7125**로 높아졌다.

## 판정과 한계

사전 기준은 **기준선 필수 근거 전부 보존 + 기존 누락 최소 1개 복구 + 검토 범위 내 새 필수 출처 회귀 없음**이었다. L12는 패널 복구가 없고 추가 손실이 있다. N12·NL12는 패널 보존부터 실패했다. **세 조건 모두 후속 답변 평가 대상으로 채택하지 않으며, 운영 구현은 유지한다.**

확인된 사실은 잘못된 경계 토큰의 높은 점수 기여, 변경 후 해당 기여 제거, 남아 있는 Dense 상위 잡음, 최종 순위에서의 필수 근거 탈락이다. 추정은 문맥을 이해하는 후보 평가나 의미 단위 검색이 이를 함께 줄일 수 있다는 것이다. 이번 실험은 그 대안을 검증하지 않았다. 다음 작업을 한다면 특정 토큰 사전이나 문항 예외를 더 붙이기보다, **이미 후보에 있는 정답 근거를 무관한 후보와 구별해 최종 문맥에 보존하는 능력**을 먼저 검증하는 편이 이번 관측에 부합한다.

77문항은 개발 과정에 노출됐고 26단위 패널은 선택된 일부다. 새 답변의 정확도·완전성·출처 충실도·거절 성능은 측정하지 않았다. 한 번의 결정적 오프라인 비교이므로 신뢰구간이나 통계적 유의성을 주장하지 않는다. 현재 설정의 관측을 다른 보고서나 다른 Nori 설정으로 일반화하지 않는다. 원문 보존과 의미 정확도, 부분 근거 복구와 문항 해결을 분리한다.

## 실행·보존 검사

기준선 77개 BM25 순위·점수와 저장 문맥을 재현했다. 최종 검사는 **308개 문맥**의 Dense 동일성, 보고서 범위, RRF 산술·동률 순서, 원문·메타데이터, 최종 개수·바이트 한도를 확인했다. 동결 파일 **107개**와 보호 파일 **2,144개**의 해시가 유지됐고 Git 상태도 같았다. 활성 store의 파일 목록도 같았다. 이번에는 SQLite를 초기화하거나 열어 쓰지 않았으며, 검사 시점의 SQLite 파일 바이트도 동일하다. 보존 기록 (`preservation.json`, local artifact not included), [최종 검사](final_validation.json).

공개 의존성은 실험 폴더 안에만 준비했다. Microsoft OpenJDK와 Lucene JAR의 출처·검증값은 [의존성 명세](dependency_manifest.json)에 남겼다. 모델·문서 업로드는 없었고, 점수 실행의 Python 네트워크 연결/DNS와 Java 소켓 권한을 차단했다. 공식 다운로드 정보는 [Microsoft OpenJDK](https://learn.microsoft.com/en-us/java/openjdk/download)를 사용했다.

준비 중 Adoptium 메타데이터 HTTP 403과 잘못 추정한 체크섬 링크를 수정했다. 별도로 분석 스크립트를 결과 생성 전에 호출해 `results.json` 부재 오류가 한 번 났고, 실행 완료 뒤 분석을 수행했다. **점수 실행의 충돌·재실행은 없었다.** 준비 이상 기록 (`setup_anomalies.json`, local artifact not included), 분석 순서 이상 기록 (`analysis_anomalies.json`, local artifact not included).

원시 실행 기록의 `REVIEW_PENDING`은 점수 계산 직후 상태를 보존한 것이다. 출처 검토를 마친 최종 상태는 [completion.json](completion.json)에 기록했다. ARS 인계 검사 (`ledger_check.json`, local artifact not included)는 도구 실행·파일 해시의 인계를 확인하며 의미 검증을 대신하지 않는다.
