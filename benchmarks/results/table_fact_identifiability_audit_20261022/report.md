**필수 숫자와 관계 상당수는 기존 표와 원문 연결 정보에서 식별할 수 있다. 그러나 현재 정규화 필드만으로 안전하게 사실을 조회할 수 있는 상태는 아니다.** 선택된 청크에 붙은 전체 표 객체가 답변 문맥에 전달되지 않는 경우, 단위·기간·주체 필드가 잘못 연결된 경우, 필요한 두 번째 표가 후보에 없는 경우가 함께 확인됐다. 따라서 다음 우선순위는 검증된 표 근거를 묶어 전달하는 경로이며, 후보 부족은 별도 문제로 다뤄야 한다.

여기서 “식별 가능”은 정답 후보를 알고 원문 행·열과 연결 문맥을 대조한 판정이다. 사용자 질문에서 필요한 사실을 자동으로 찾아내는 성능이나 답변 개선을 측정한 결과는 아니다.

## 검토 범위와 판정 방법

77문항 전체를 저장된 판정과 대조했다. 기존 구분인 일반 답변 46문항, 거절 19문항, 진단·HOLD 12문항을 유지했다. 과거 Sol top8의 재판정, Sol top12, facets 답변 중 실패·근거 충실도 문제가 있던 15문항과 기존 출처 변경 검토의 합집합 39문항을 검토했다. 여기에 거절 정책 경계 2문항을 별도로 대조했다. 그중 19문항을 표 구조·원문·실제 전달 문맥의 집중 사례로 정리했다. 나머지 36문항은 저장 결과 선별만 했으며 새 정답 판정을 내리지 않았다.

집중 19문항의 구분은 표와 연결 문맥에서 대상 사실을 읽을 수 있는 16건, 순위 모집단을 정해야 하는 조건부 1건, 저장된 표의 주체 연결이 부족한 1건, 핵심 근거가 표가 아닌 문단인 1건이다. 이 수치는 **전체 문항을 표만으로 해결한 비율이 아니다.** 원인 설명·전략·범위 해석은 별도 본문이 필요한 경우가 많다.

검증에 사용한 것은 저장된 Dense·BM25 후보, RRF 순위, 실제 생성 입력, v12의 gzip 내보내기, 표 객체와 원본 DART 문서다. 슬림 corpus에 필드가 없다는 이유로 구조가 없다고 판정하지 않았다. 원문 해시·표 XPath·문맥 span을 대조했고, 원본의 비정상 XML 문자는 기존 sanitizer로 메모리에서 처리한 뒤 strict parse했다. 일부 문맥은 긴 문단의 일부 span이므로 전체 XML node 문자열 동일성을 요구하지 않았다.

`A12`는 저장된 기존 검색의 최종 12개, `N12`는 Nori, `F12`는 Nori 구조 라벨 중복 집계 분리, `S12`는 이전 표 스키마 실험이다. 아래 순위는 모두 기존 산출물에서 읽었다. 새로 점수를 계산하지 않았다.

## 다음 개선 우선순위

### 1 검증된 표 근거를 묶어 전달하는 경로

다음 검증 대상은 **값 + 전체 행·열 머리글 + 적용 기간 + 주체·연결/별도 범위 + 단위 + 각 원문 위치**를 하나의 근거로 취급하는 방식이다. 기존 `table_object`와 `source_contexts`를 우선 사용하되, 혼합 단위·취득일·주체 연결을 먼저 확인해야 한다. 미확정 축은 미확정으로 남겨야 하며 회사명이나 문항별 예외로 채우면 안 된다.

작업 범위는 새 질문 분류기·Planner·새 파서 도입이 아니라, 기존 후보에 있는 구조를 실제 모델 입력으로 보존할 수 있는지다. 앞선 행 표현·스키마 실험은 검색 표현과 점수를 바꿔 기존 청크를 선택했다. 이번에 확인한 “전체 표 metadata에는 있지만 선택된 본문에는 없는 셀”은 전달 경계도 함께 검증해야 한다는 차이가 있다.

다음 검증에서는 후보·순서·문맥 예산을 고정하고, 필요한 사실의 원문 연결 보존, 잘못된 기간·주체·단위 연결, 기존 필수 근거의 밀려남을 따로 측정하는 것이 타당하다. 정답을 알고 수동으로 골라 넣은 상한 진단은 자동 검색 성과로 보고하지 않는다. 자동 선택 검증 시에는 benchmark ID·회사명 분기·정답 숫자 주입을 금지한다. **잘못 연결된 사실이 생기거나 다른 필수 근거를 잃으면 채택하지 않는 것**이 우선 종료 기준이다.

### 2 후보에 없는 필수 표를 위한 별도 조회 단위

SK하이닉스 자산·Motional 손익처럼 후보 부재가 확인된 경우에는 표·사실 단위의 후보 경로를 검토할 근거가 있다. 같은 후보의 RRF 가중치 조정은 이 문제를 해결하지 못한다. 다만 현재 unit/period scalar를 그대로 hard filter로 쓰면 잘못된 필드를 신뢰하게 된다. 1단계의 원문 연결 계약을 전제로, 동일한 계산의 필요한 항목들을 함께 확보하는지와 후보 수·비용을 비교해야 한다. 이 경로의 실제 개선 효과는 아직 확인되지 않았다.

### 3 의미 해석과 평가 경계는 별도로 유지

원인·전략·향후 계획은 본문 근거를 유지하고, 표의 연결/별도·순액/총액·기말잔액/기간손익을 임의로 바꾸지 않는다. 이미 근거가 있는 생성 오류와 실험 계약 오류는 검색 개선의 성공 지표에서 뺀다. HOLD를 해제하지 않고, 기존 77문항을 반복해서 맞춘 결과를 새 문서 일반화 성능으로 표현하지 않는다.

현재 근거로는 Nori·RRF 미세 조정, 무조건적인 문맥 확대, 새 임베딩·리랭커·LLM 요약표 생성보다 1단계의 우선순위가 높다. 이는 관측된 실패 경계에 따른 **다음 검증의 우선순위**이며 이미 입증된 성능 개선안은 아니다.
