# 문맥 예산 64KiB와 160KiB의 77문항 비교

**160KiB에서 Motional의 누락된 투자 근거 두 항목이 복구됐다. 기존 64KiB 근거의 소실은 없었다. 이 사례의 해당 누락은 예산을 늘리는 것만으로 해소할 수 있었다.** 다만 손익 표 등 처음부터 전달 대상에 없던 근거는 복구되지 않았고, 새 답변은 생성하지 않았다.

상한은 2.5배지만 실제 총 문맥은 **20.54% 증가**했다. 상한보다 작은 문맥은 더 늘어나지 않아 중앙값도 같았다. 이 값은 UTF-8 JSON 바이트이며 모델 토큰 수, 과금액 또는 답변 지연의 측정값이 아니다.

## Motional: 투자 근거 복구와 전체 질문 미완료를 구분

질문은 2023년 타법인출자 현황 또는 주석을 바탕으로 지분율, 투자장부금액, 요약손익을 요구한다. `HYU_T3_072`의 고정된 원래 청크 `20240313001451:1246:4`에 연결된 상세 출자표에서 다음이 전달됐다.

| 필수 항목 | 64KiB | 160KiB에서 확인한 원문 연결 |
|---|---|---|
| 기말 지분율 | 미전달 | Motional 행 → 기말잔액 → 지분율 `25.81` |
| 투자장부금액 | 미전달 | 같은 행 → 기말잔액 → 장부가액 `1,294,367` |
| 기간·단위 | 목표 값과 함께 전달되지 않음 | 같은 표의 `2023년 12월 31일` 기준일, `백만원, 주, %` 표기 |
| 요약손익 | 미복구 | 여전히 미완료. 투자표의 순손익 하나는 요청된 요약손익 표 전체를 대신하지 못함 |

이는 **타법인출자 현황(상세)의 2023.12.31 기말잔액 기준 대안**이다. 고정 평가 기준이 허용한 투자표 대안으로 복구를 기록했다. 전달 frame에 `별도`라는 문자 자체가 없으므로 별도 재무제표 범위가 literal로 인증됐다고 주장하지 않는다. 연결 주석의 지분율 `26%`·장부금액 `700,691백만원`이 복구된 것도 아니다. 두 범위를 섞지 않는다.

물리 표는 `/DOCUMENT/BODY/SECTION-1[13]/SECTION-2[3]/TABLE-GROUP/TABLE[2]`이며, 목표는 펼친 행 143의 열 12·13이다. 160KiB packet의 해당 wire 단위 인덱스는 1,688·1,689다. 값과 같은 행에 있는 `2020.03.01`에는 `최초취득일자` 열 표제가 붙어 있다. 이를 2023년 기말 값의 보고기간으로 바꾸지 않았다. 같은 행의 기초 지분율 `25.92`도 기말 `25.81`과 다른 열로 보존된다.

Motional 문맥의 실제 크기는 65,443 → 163,836바이트, 해당 표의 전달 단위는 432 → 1,701개다. 목표 행은 앞부분 64KiB 범위를 벗어나 있었고 160KiB에서 포함됐다. 이번 160KiB packet은 앞서 저장한 단일 문항 예산 진단 결과와도 정확히 일치한다.

요약손익의 영업수익 `1,775`, 계속손익 `(803,742)`, 기타포괄손익 `12,115`, 총포괄손익 `(791,627)`백만원을 이름·기업·기간과 함께 제공하는 주석 근거는 고정된 전달 대상에 없다. 투자표의 `최근사업연도재무현황 → 당기순손익 -803,742`는 별도로 기록했으며, 이것만으로 요약손익 요구를 통과시키지 않았다. **필수 요구 세 범주 중 두 범주의 부분 복구이고, 완전한 질문 해결은 아니다.**

## 잘못된 연결 검사와 남은 의미 한계

독립 구현의 검사는 두 조건의 154개 case-arm과 예산 제안 37,568개를 매번 실제 전체 JSON 바이트로 대조했다. 전달된 합집합의 고유 물리 표 341개, 물리 단위 14,953개, 물리 셀 24,436개를 11개 원문 XML 및 저장 witness와 확인했다. 새 160KiB 전용 셀도 포함했으며, 포함 문맥의 hash·XPath·문자 구간·부모·인접 관계도 검사했다. **이 물리적 출처·좌표·의존성 검사에서 불일치는 0건이다.** Projector를 재실행하지 않았고 원문 구조 검사 알고리즘도 별도로 구현했으며 XML sanitizer만 공유했다.

물리적으로 같은 표의 셀이라는 사실이 질문에 맞는 기간·주체·연결/별도·단위의 의미까지 보증하지는 않는다. 19개 축 감시 문항과 전체 단위 보존을 별도로 검토했다. Motional의 취득일과 기준일, 기초·기말, SKI의 화폐 단위는 literal 역할을 구분해서 기록했다.

`MIX_T2_047`의 `1149:18` 저장 구조에는 첫 데이터 행을 추정 header prefix로 둔 기존 한계가 남아 있다. 실제 XML의 THEAD/TH는 없고 `declared_header_source_tr_indices`도 양쪽 모두 빈 배열이다. 첫 임원 데이터 행(김걸, raw TR 2)을 prefix로 참조하는 단위가 34 → 493개로 늘어, 같은 모호성이 추가 459개 단위에 노출됐다. 이는 새 값 연결을 재추론한 것이 아니라 고정된 기존 표현의 노출 증가다. 모델이 이를 열 표제나 주체로 오독하지 않는다는 보증은 아니다. 따라서 물리 검사 0건을 ‘잘못된 의미 연결이 절대로 없다’로 확대하지 않는다.

## 해석 및 보존

확인된 사실은 **이 고정 조건에서 예산 확대만으로 Motional 투자 근거가 전달됐고, 기존 전달 근거의 소실 없이 일부 추가 근거가 들어갔다**는 것이다. 더 복잡한 선택기나 검색 변경이 반드시 필요하다는 근거는 이번 결과에서 나오지 않는다. 반면 후보·문서 범위 밖의 근거나 없는 의미 축까지 예산이 만들어 주지는 않는다.

160KiB는 이전 Motional 진단을 본 뒤 선택한 상한이고, 77문항도 반복 사용한 개발 자료다. 두 상한만 실행하고 규칙을 결과에 맞춰 바꾸지 않았지만 새로운 검증 집합의 일반화 실험은 아니다. 축 검토는 기존 projector 작성자의 검토이며, 검토자들은 이전 작업 문맥을 공유한다. 물리 검사 코드의 독립 구현을 익명 평가나 다른 모델을 통한 의미 검증으로 표현하지 않는다. 실제 답변의 정확도·필수 항목 누락·출처 충실도·거절 성능·주의 분산은 측정하지 않았다. 표가 커져도 기존 근거가 유지되는지 확인한 결과와 모델이 이를 잘 읽는다는 주장은 다르다. ARS 통계적 오류 11개 항목을 검토했고 추론 통계·유의확률은 사용하지 않았다.

기존 구현·`.env`·활성 v12 store 11개 파일·이전 산출물을 포함한 **5,626개 보호 파일이 바이트 hash까지 동일**하다. Git HEAD·index·작업 상태도 같다. SQLite/Chroma 클라이언트를 열지 않았고 앱 재시작, 외부 모델·임베딩·검색 API 호출, 새 답변 생성, 커밋·push를 하지 않았다. 결과는 이 ignored 실험 폴더에만 보관하며 기본 앱의 문맥 예산은 변경하지 않았다.
