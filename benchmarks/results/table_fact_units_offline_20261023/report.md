# 원문에 연결된 값 단위 전달 실험 결과

**표 전체 거절을 값·행 단위로 좁히는 데는 성공했지만, 새 필수 숫자는 복구하지 못했다. 이번 FCT12 방식은 채택하지 않는다.**

2026-10-23, academic-research-suite의 experiment-agent 절차로 저장된 77문항을 1회 비교했다. A12는 원래 답변 문맥, T12는 이전 전체 표 첨부 결과, FCT12는 이번 값 단위 첨부 결과다. T12를 다시 실행하지 않았다. 외부 모델·임베딩·검색 API 호출 0회, 새 답변 0개, 외부 API 비용 $0이다. 동결한 실행은 58.53초였으며 별도 상한 30분 안에 종료했다.

Motional 표의 실제 전달 범위는 펼친 행 3~38이고, 목표 행은 143이었다. 원래 문맥 31,689바이트에 33,754바이트를 추가해 최종 65,443바이트가 됐다. 남은 예산은 93바이트인데, 목표 지분율 단위는 축을 포함해 추가 167바이트, 장부금액 단위는 171바이트가 필요해 각각 제외됐다. 최초 취득일 `2020.03.01`에는 `최초취득일자` 표제가 함께 검증됐으나 이 행 자체가 전달되지 않았다. 그 날짜를 보고기간으로 바꿔 해석하지 않았다. 투자 표의 순손익 하나를 전체 요약손익 요구의 충족으로 세지도 않았다.

이는 이번 조건에서 확인된 **선택·예산 배분의 실패**다. 질문 관련성을 사용하지 않고 앞 행부터 담으면 단위를 작게 만들어도 필요한 뒤쪽 행은 놓친다. 질문에 관련된 값과 그 축을 먼저 선택하는 단계가 다음 검토 우선순위라는 것은 이 결과에서 얻은 추론이며, 그 방법의 효과를 이번에 검증한 것은 아니다. 순서를 바꾸거나 예산을 늘린 추가 실행은 하지 않았다.

원래 A12와 비교한 보존과 T12에서 덧붙였던 정보의 감소는 구분해야 한다. **77/77문항의 원래 본문·문맥·출처 ID·순서는 모두 동일**하다. 반면 숫자 셀이 없는 연혁·개발 단계·관계 서술 표는 FCT12의 대상에서 빠진다. HYU 연혁, CEL 개발 단계, NAV Poshmark 서술, LGE `33.47/kg` 표 등이 해당한다. LGE의 USD 표시는 원래 다른 청크에도 남으므로, 통화 정보가 전부 삭제됐다고 해석하면 안 된다. 정확한 표와 단위를 묶어 주던 보강이 줄어든 것이다.

별도로 KBF_T2_043의 두 표와 SAM_T1_001의 한 표는 예산 때문에 T12 첨부가 사라졌다. 삼성 문항에서는 `제55기 → 2023년`의 명시적 기간 캡션 보강이 빠졌다. 기존 본문 근거가 남아 있어 26개 필수 단위의 손실로 세지는 않았지만, 추가 문맥의 회귀로 기록했다. 같은 표가 양쪽에 첨부됐다는 사실도 모든 추가 셀이 동일하게 보존됐다는 뜻은 아니다.

FCT12의 총 문맥은 A12보다 46.36% 크고 T12보다 0.28% 작다. 71문항에 추가가 있었으며 30문항에서 값 단위의 예산 제외가 발생했다. 문항별로 값 단위 9,465회가 전달되고 9,319회가 제외됐다. 이 단위에는 저장된 `-` 같은 결측 표시도 포함되며, 중복 발생 횟수나 전달 단위 수를 새로운 숫자 사실 수로 해석하면 안 된다.

후보·점수·Dense/BM25/RRF 순서, 최종 선정 12개, 원래 실제 전달 문서, 질문·보고서 범위, 65,536바이트 상한을 고정했다. 원래 예산 때문에 문서가 빠진 6문항은 그대로 두어 전체 실제 문서는 907회다. 기존 본문을 줄이지 않고, 이미 전달된 첫 표 소유자의 저장 `rows[].cells[]`에서 검증된 값과 행·열 축을 추가했다. 질문·정답·목표 숫자는 projector의 입력이 아니다.

원문 XML은 저장 셀의 위치를 확인하는 데만 사용했다. 없는 값을 원문에서 새로 채우지 않았다. 표 정체성·좌표계·헤더 prefix는 전역 검증을 유지하고, 행 축의 모호성은 해당 행에, 값의 불일치는 해당 셀에 한정했다. 여러 열에 걸친 셀과 행 축에는 점유한 열의 표제를 모두 보존했다. 공유 물리 셀을 중복 제거하고, 첫 frame과 값 및 필요한 축이 한꺼번에 예산에 들어갈 때만 추가했다. 실패하면 새 축도 모두 취소하고 고정된 다음 값으로 진행했다. 기존 출처 ID 아래의 추가 필드가 원문 표로 연결되는 확장 근거이며, 새 셀이 원래 청크 본문에도 들어 있었다고 주장하지 않는다.

합성 계약 테스트 43개가 통과했다(원문 검증 32, 전달·예산 11). 실행 전 교차 검토에서 0개 유효 값의 로그 분류와 colspan의 전체 열 표제 보존을 수정했고, 실제 결과를 본 뒤 projector·정책을 수정하거나 두 번째 변형을 실행하지 않았다.

별도 구현의 사후 감사는 77문항과 예산 결정 18,784개를 전수 대조했다. 실제 전달된 고유 표 270개, 단위 7,714개, 물리 셀 12,467개를 저장 witness와 원문 위치에 대조했으며, 포함 문맥 1,372개의 hash·문자 구간·부모·물리 관계도 확인했다. **검사 범위에서 물리 연결 불일치 0건**이었다. 이 검사는 projector를 재실행하거나 helper를 재사용하지 않았고, 기존 XML sanitizer만 공유했다.

축 연결 주의 문항 19개는 projector 작성자가 별도로 검토했다. 검토 대상에서 새로 단정한 축의 원문 충돌은 확인하지 못했지만 익명·독립 의미 평가가 아니다. 독립 물리 감사도 전달된 단위의 위치 대응을 확인한 것이며, 제외된 모든 단위나 기간·주체·연결/별도·단위의 의미를 보증하지 않는다. 기존 잘못된 `unit_hint`도 원래 본문 보존 조건 때문에 남아 있다. 올바른 캡션 추가가 모델의 오독을 막는지는 측정하지 않았다.

이번 비교는 숫자 셀 중심 표현으로 바꾸면서 서술형 표의 포함 범위와 직렬화 비용도 함께 달라졌다. 따라서 검증 실패 범위만 단독으로 바꾼 인과 실험이라고 해석하면 안 된다. 개발 중 반복해서 본 77문항이며, 답변 생성·정확도·출처 충실도·거절 성능·새 좌표 형식의 독해 효과는 모두 미측정이다.

기존 구현·`.env`·활성 v12 store 11개 파일을 포함한 보호 파일 5,393개의 hash가 그대로다. Git HEAD·index·작업 상태도 동일하다. SQLite/Chroma 클라이언트를 열거나 앱을 재시작하지 않았으며, store 파일은 보존 확인을 위한 바이트 hash만 읽었다. 새 파일은 이 ignored 실험 폴더에만 작성했고 커밋·push·기존 상태 문서 갱신은 하지 않았다.

최종 판단은 **실험 종료, 미채택**이다. 원문 검증 성공과 최종 전달 성공이 서로 다르다는 경계는 명확해졌지만, 현재 누락된 필수 숫자를 복구하는 이득은 없었다. 숫자 셀만 추가하는 규칙을 기본 앱에 반영하지 않는다.
